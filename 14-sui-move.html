SUI 篇 II：Move 合约开发

从 Sui CLI 到五个递进实战，完整掌握 Move 语法、Coin 标准与合约测试。主要参考：docs.sui.io、Sui Move Intro Course（sui-foundation）、The Move Book（move-book.com）。

本章目标：
  • 配好 Sui CLI 与 testnet 环境，跑通 build/test/publish 全流程。
  • 理解 module/use、基本类型、可见性、结构体四能力与对象三要素。
  • 掌握 transfer/share/freeze 与 TxContext，能正确表达对象所有权。
  • 读懂 Coin 标准：OTW、TreasuryCap、create_currency 与拆合支付。
  • 完成五个递进实战（Counter → 共享计数 → 自定义币 → 捐赠罐 → NFT 市场）。
  • 会用 #[test] 与 test_scenario 写测试，并识别常见安全陷阱。

1. 环境与开发流程

1.1 安装 Sui CLI

两种方式二选一：

# 方式 A：用官方安装脚本（推荐，自动装最新稳定版）
curl -sSf https://raw.githubusercontent.com/MystenLabs/sui/main/scripts/install.sh | sh

# 方式 B：从源码用 Rust 编译（需先装 Rust toolchain）
cargo install --locked --git https://github.com/MystenLabs/sui.git --branch main sui

装好后确认版本：

sui --version
# 输出类似：sui 1.30.0-...

1.2 配置 testnet 并领水

# 生成/选用一个地址身份（默认生成新密钥对）
sui client new-address ed25519

# 配置 testnet 全节点环境（名为 testnet）
sui client new-env --alias testnet --rpc https://fullnode.testnet.sui.io:443

# 切到该环境并设为活跃
sui client switch --env testnet

# 领测试水（依赖反机器人，偶尔需手动到 https://faucet.sui.io）
sui client faucet
提示：sui client addresses 查看本机地址；sui client active-address 查看当前活跃地址。发布合约用的是当前活跃地址。

1.3 项目结构与核心命令

# 创建一个 Move 项目
sui move new my_first_package
# 生成的目录结构：
# my_first_package/
# ├── Move.toml          # 包清单（包名、版本、依赖）
# ├── sources/           # 你的 .move 源文件放在这里
# ├── tests/             # 单元测试
# └── Move.lock          # 依赖锁文件

cd my_first_package

# 编译
sui move build

# 跑单元测试
sui move test

# 发布到 testnet（需先领水付 gas/存储费）
sui move publish --gas-budget 100000000

Move.toml 长这样：

[package]
name = "my_first_package"
edition = "2024.beta" # 或 "legacy"
version = "0.0.1"

[dependencies]
Sui = { git = "https://github.com/MystenLabs/sui.git", subdir = "crates/sui-framework", rev = "framework/testnet" }

[addresses]
my_first_package = "0x0"   # 本地开发用 0x0 占位，发布时由链分配真实 ID

[dev-addresses]
# 测试用地址别名
# my_first_package = "0xDEADBEEF"

1.4 包升级：UpgradeCap 与兼容性

  • 发布时会生成一个 UpgradeCap 对象（独占对象），它持有对该包的升级权限。
  • 升级需满足兼容性规则：可以新增函数/结构体、给结构体追加字段（带默认值语义），但不能删除/重排已有字段、不能改已发布结构体的能力（ability）。
  • 升级命令：sui move publish --upgrade-capability <UpgradeCap对象ID>（或 --skip-fetch-latest-git-deps 加速）。
升级风险：掌握 UpgradeCap 等于能改合约逻辑。金库类合约建议发布后把 UpgradeCap 转交多签或销毁（transfer::public_transfer 给多签 / 或调用 upgrade::burn）。

2. Move 语法系统

下面逐点铺开 Move（Sui 版）语法，每点配可运行代码。

2.1 module 声明与地址别名

// 一个 module 属于某个「包」，包发布后模块全名形如 0x包ID::模块名
module my_first_package::basic {
    // 模块体
}

地址别名用于引用别人包里的模块：

module my_first_package::basic {
    use sui::balance;        // 直接按「包名::模块」导入（sui 是框架包别名）
    use sui::coin::{Self, Coin}; // 导入 coin 模块及其下的 Coin 类型
}

2.2 use 导入与可见性

写法含义
use sui::coin;导入模块，使用时写 coin::xxx。
use sui::coin::Coin;只导入 Coin 类型，可直接写 Coin<T>。
use sui::coin::{Self, Coin};同时导入模块与其中类型。

2.3 基本类型与 vector

module my_first_package::basic {
    // 基本标量类型：u8 / u8..u256、bool、address、signer
    // vector<T> 是动态数组
    fun demo() {
        let a: u8 = 1;
        let b: u64 = 1_000_000;
        let c: u128 = 340282366920938463463374607431768211455;
        let ok: bool = true;
        let addr: address = @0xA;            // 字面量地址

        let v: vector<u8> = vector[1, 2, 3]; // 字节数组常用于字符串/哈希
        let len = v.length();                 // 取长度
        v.push_back(4);                       // 追加
    }
}

2.4 函数可见性：public / entry / public(friend)

修饰谁能调用能否作为交易入口
（默认）仅同模块内否
public任意模块否（只能被别的 Move 调用）
entry仅同模块内 + 可作为交易入口是
public entry任意模块 + 可作为交易入口是
public(friend)仅 friend 模块否
module my_first_package::basic {
    // 只能被 PTB 直接调用（交易入口），但别的模块不能内部调用它
    entry fun only_entry() {}

    // 既能当入口，又能被别的模块调用
    public entry fun public_entry(x: u64) {}

    // 内部工具函数
    fun helper() {}
}
关键区别：只有带 entry 的函数才能被外部交易（PTB 的 MoveCall）直接调用；普通 public 函数只能被其他 Move 代码调用，不能当交易入口。

2.5 结构体与四种能力（Ability）

能力决定一个值「能做什么」，对资产安全至关重要：

能力含义对资产的意义
key可作为全局对象（有 UID）资产对象必须有它，才能存链上、被索引
store可被存入其他结构 / 被转移允许资产在对象间流转、被包裹
copy值可被复制资产绝不能有，否则能无限复制
drop作用域结束可被丢弃资产绝不能有，否则能凭空销毁
module my_first_package::basic {
    // 真金白银的资产：只给 key + store
    struct GoldCoin has key, store {
        id: UID,
        value: u64,
    }

    // 纯配置/常量：给 copy + drop 方便使用
    struct Config has copy, drop {
        fee_bps: u64,
    }

    // 一次性见证（见 Coin 标准）：只给 drop
    struct MY_TOKEN has drop {}
}
铁律：任何「代表价值」的对象都只能有 key, store，绝不能加 copy 或 drop。一旦误加，攻击者可能复制或丢弃你的资产。

2.6 对象三要素：UID、id 字段、object::new

module my_first_package::basic {
    use sui::object::{Self, UID};
    use sui::tx_context::{Self, TxContext};

    struct Counter has key {
        id: UID,        // 每个对象必须有且仅有一个 id: UID 字段
        value: u64,
    }

    public entry fun create(ctx: &mut TxContext) {
        // object::new(ctx) 用交易上下文派生出唯一 UID
        let c = Counter { id: object::new(ctx), value: 0 };
        // 转移逻辑见 2.7
    }
}
为什么 UID：链上用 UID（内部是个 32 字节 ID）唯一标识对象。两个对象即便内容相同，UID 也不同，因此不会被混淆。

2.7 转移语义：transfer / public_transfer / share_object / freeze_object

函数效果对象后续归属
transfer::transfer(obj, addr)把对象转给 addr成为 addr 的独占对象
transfer::public_transfer(obj, addr)同上，但可被任意模块调用独占对象
transfer::share_object(obj)把对象设为共享共享对象（任何人可引用）
transfer::freeze_object(obj)冻结对象不可变对象（永久只读）
module my_first_package::basic {
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};

    struct Thing has key, store { id: UID, v: u64 }

    // 私有的：仅本模块能调用 transfer
    public entry fun make_private(ctx: &mut TxContext) {
        let t = Thing { id: object::new(ctx), v: 1 };
        transfer::transfer(t, tx_context::sender(ctx)); // 给调用者
    }

    // 共享：谁都能引用它（如全局计数器、订单簿）
    public entry fun make_shared(ctx: &mut TxContext) {
        let t = Thing { id: object::new(ctx), v: 1 };
        transfer::share_object(t);
    }

    // 冻结：发布后永久不可改
    public entry fun make_immutable(ctx: &mut TxContext) {
        let t = Thing { id: object::new(ctx), v: 1 };
        transfer::freeze_object(t);
    }
}

2.8 TxContext 与 ctx.sender()

TxContext 是每笔交易自动注入的上下文，提供：sender()（付款方地址）、object::new(ctx) 造 UID、fresh_object_address() 等。注意它几乎总是 &mut TxContext 参数。

use sui::tx_context::{Self, TxContext};

public entry fun whoami(ctx: &mut TxContext) {
    let caller = tx_context::sender(ctx); // 当前交易的发送者地址
    // 用 caller 做权限判断、记录 owner 等
}

2.9 泛型与 phantom

phantom 用于「类型参数只出现在类型标记里、不出现在字段值里」的泛型，避免 unused 报错；典型就是 Coin 的 Coin<T> 中 T 是 phantom。

module my_first_package::basic {
    use sui::object::{Self, UID};

    // T 是 phantom：结构体里没有直接存 T 类型的值，只用于类型区分
    struct Wrapper<phantom T> has key, store {
        id: UID,
        amount: u64,
    }
}

2.10 Option 与 String

module my_first_package::basic {
    use std::option::{Self, Option};
    use sui::string::String;

    fun demo() {
        let some: Option<u64> = option::some(10);
        let none: Option<u64> = option::none();
        if (option::is_some(&some)) {

提示：Sui 里展示名/描述常用 String（UTF8），而合约内部标识（symbol）常用 vector<u8> 或 ascii::String。

2.11 动态集合：Table / Bag / ObjectTable 与动态字段

当「键的集合在编译期未知」时，用动态集合而非固定字段：

类型键/值特点
Table<K, V>任意 K、任意 V单独对象，含全部键值对
Bag任意 K、任意 V与父对象「同生命周期」打包存
ObjectTable<K, V>K、V 为对象值是对象，便于分别转移
动态字段 DOF挂在对象上用 dynamic_field 在对象上挂任意键值
module my_first_package::basic {
    use sui::table::{Self, Table};

    struct Registry has key {
        id: UID,
        items: Table<address, u64>, // 地址 -> 数值 的动态映射
    }

    public entry fun add(reg: &mut Registry, who: address, v: u64) {
        table::add(&mut reg.items, who, v);
    }
    public entry fun get(reg: &Registry, who: address): u64 {
        table::borrow(®.items, who)
    }
}

2.12 事件、Clock 与 Random

module my_first_package::basic {
    use sui::event;
    use sui::clock::{Self, Clock};
    use sui::random::{Self, Random};

    // 事件结构体：发出后链下可索引（注意事件结构通常只写一次）
    struct CounterIncremented has copy, drop, store {
        new_value: u64,
    }

    public entry fun tick(ctx: &mut TxContext) {
        let new_v = 1;
        event::emit(CounterIncremented { new_value: new_v });
    }

    // 取当前时间（需引用共享的 Clock 对象）
    public entry fun now(clock: &Clock) {
        let ts = clock::timestamp_ms(clock); // 毫秒
    }

    // 取随机数（需引用 Random 对象；链上随机用于游戏/抽奖）
    public entry fun roll(random: &Random) {
        let rand = random::generate(random, /*种子*/ b"seed", ctx);
    }
}
Clock 与 Random 是共享对象：调用时由 PTB 把系统的 0x6（Clock）或 Random 对象作为实参传入。它们走共识，但读取开销低。

3. Coin 标准精讲

Sui 的原生代币（包括 SUI 与你发的任意币）都遵循 sui::coin 标准。

类型作用
Coin<T>用户持有的「币对象」；内部持有一个 Balance<T>。
Balance<T>纯数值余额（无对象壳），用于合约内部记账。
TreasuryCap<T>铸造/销毁权限对象（谁持有谁就能 mint/burn）。
CoinMetadata<T>币种元信息（名/符号/精度/图标）。

3.1 一次性见证 OTW 与 init

发币的关键机制是 OTW（One-Time Witness，一次性见证）：一个模块发布时，链会自动创建一个「名字等于模块名」的、带 drop 能力的空结构体实例，作为「我确实发布了这个币」的证明。init 函数（模块初始化函数）会收到它。

module my_coin::my_coin {
    use sui::coin::{Self, TreasuryCap, Coin};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};

    // OTW：名字==模块名 MY_COIN，仅 drop 能力。链发布时自动产生一个实例
    struct MY_COIN has drop {}

    // 模块初始化：仅在 publish 时执行一次
    fun init(witness: MY_COIN, ctx: &mut TxContext) {
        let (treasury_cap, metadata) = coin::create_currency<MY_COIN>(
            witness,
            9,                       // 小数位（与 SUI 一致 9）
            b"MYC",                  // symbol 符号
            b"My Coin",              // name 名称
            b"demo coin on Sui",     // description 描述
            option::none(),          // icon URL（可选）
            ctx,
        );
        // 把权限与元信息转给发布者（重要：否则没人能 mint）
        transfer::public_transfer(treasury_cap, tx_context::sender(ctx));
        transfer::public_transfer(metadata, tx_context::sender(ctx));
    }
}

3.2 mint / burn / freeze metadata

    // 铸造：只有持有 TreasuryCap 的人能调
    public entry fun mint(
        cap: &mut TreasuryCap<MY_COIN>,
        amount: u64,
        recipient: address,
        ctx: &mut TxContext,
    ) {
        let coin = coin::mint(cap, amount, ctx);

        coin::burn(cap, coin);
    }

    public entry fun freeze_metadata(metadata: &mut CoinMetadata<MY_COIN>) {
        coin::freeze_metadata(metadata);
    }

3.3 TreasuryCap 的权限管理

TreasuryCap 本身是一个独占对象。你可以：

  • 转交：transfer::public_transfer(cap, new_owner) 把发币权交给别人/多签。
  • 销毁：coin::burn_supply(cap) 后该币将再无法 mint（常用于「固定总量」）。
  • 托管：把 cap 交给一个「治理合约」的共享对象，由治理逻辑控制 mint。
泄露即失控：TreasuryCap 一旦落到他人独占对象且你无法取回，对方就能无限增发你的币。发布后请立即转交多签或销毁。

3.4 Coin 拆合与 PTB 支付

Coin<T> 的拆合由 SDK 的 splitCoins/mergeCoins（见上篇）完成；合约侧用 coin::from_balance / coin::into_balance 在 Coin 与 Balance 间转换。支付时在 PTB 里把拆好的 Coin 作为 Coin<T> 参数传给 moveCall 即可。

4. 实战一：独占对象 Counter

最经典的入门：每个用户拥有一个「归自己的计数器」对象，只有自己能 +1。这是独占对象，走 FastPath，最快。

// sources/counter.move
module counter::counter {
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};

    // 计数器对象：key + store（无 copy/drop）
    struct Counter has key {
        id: UID,
        value: u64,
    }

    // 创建并归调用者所有
    public entry fun create(ctx: &mut TxContext) {
        let counter = Counter { id: object::new(ctx), value: 0 };
        transfer::transfer(counter, tx_context::sender(ctx));
    }

    // 自增（参数是 &mut，因为对象归调用者，可直接借用）
    public entry fun increment(counter: &mut Counter) {
        counter.value = counter.value + 1;
    }

    // 读值（view 函数，不需要 entry，可被 devInspect 调用）
    public fun value(counter: &Counter): u64 {
        counter.value
    }
}

TS 调用：

// 创建
const tx = new Transaction();
tx.moveCall({ target: `${pkg}::counter::create` });
await client.signAndExecuteTransaction({ transaction: tx, signer });

// 先查自己的 Counter 对象 ID
const objs = await client.getOwnedObjects({
  owner: me,
  filter: { StructType: `${pkg}::counter::Counter` },
  options: { showContent: true },
});
const id = objs.data[0].data?.objectId;

// 自增（对象 ID 作为引用传入）
const tx2 = new Transaction();
tx2.moveCall({ target: `${pkg}::counter::increment`, arguments: [tx2.object(id)] });
await client.signAndExecuteTransaction({ transaction: tx2, signer });

5. 实战二：共享计数器

把计数器改成共享对象，任何人都能 +1。注意：共享对象走共识、有并发开销，适合同步状态。

// sources/shared_counter.move
module counter::shared_counter {
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};

    struct SharedCounter has key {
        id: UID,
        value: u64,
    }

    // 创建后 share（变为共享对象）
    public entry fun create(ctx: &mut TxContext) {
        let c = SharedCounter { id: object::new(ctx), value: 0 };
        transfer::share_object(c);
    }

    // 任何人都能 +1
    public entry fun increment(counter: &mut SharedCounter) {
        counter.value = counter.value + 1;
    }
}
对照：共享计数器与实战一的唯一差别是 share_object 替代 transfer。代价是每笔交易都要共识排序；高频计数请优先考虑「每用户独占 + 汇总」模式。

6. 实战三：自定义 Coin 发币

把 3.1/3.2 的片段组合成完整可发布模块，并演示 mint 给朋友。

// sources/my_coin.move
module my_coin::my_coin {
    use sui::coin::{Self, TreasuryCap, Coin, CoinMetadata};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};
    use std::option::{Self, Option};

    struct MY_COIN has drop {}

    fun init(witness: MY_COIN, ctx: &mut TxContext) {
        let (treasury_cap, metadata) = coin::create_currency<MY_COIN>(
            witness, 9, b"MYC", b"My Coin", b"demo", option::none(), ctx,
        );
        transfer::public_transfer(treasury_cap, tx_context::sender(ctx));
        transfer::public_transfer(metadata, tx_context::sender(ctx));
    }

    public entry fun mint(
        cap: &mut TreasuryCap<MY_COIN>,
        amount: u64,
        recipient: address,
        ctx: &mut TxContext,
    ) {
        let coin = coin::mint(cap, amount, ctx);
        transfer::public_transfer(coin, recipient);
    }

    public entry fun burn(cap: &mut TreasuryCap<MY_COIN>, coin: Coin<MY_COIN>) {
        coin::burn(cap, coin);
    }
}

TS 调用 mint（注意 TreasuryCap 对象 ID 也要传入）：

const tx = new Transaction();
tx.moveCall({
  target: `${pkg}::my_coin::mint`,
  arguments: [
    tx.object(treasuryCapId),         // TreasuryCap 对象
    tx.pure.u64(1_000_000_000),       // 1 个 MYC（9 位精度）
    tx.pure.address(friendAddress),   // 接收者
  ],
  typeArguments: [],                  // 本例币种由模块固定，无需泛型
});
await client.signAndExecuteTransaction({ transaction: tx, signer });

7. 实战四：捐赠罐 TipJar

一个共享对象收 SUI，owner 可提取。演示「共享对象 + 权限判断 + 转 Coin」。

// sources/tip_jar.move
module tip_jar::tip_jar {
    use sui::coin::{Self, Coin};
    use sui::sui::SUI;
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::tx_context::{Self, TxContext};

    struct TipJar has key {
        id: UID,
        owner: address,
        total: u64,
    }

    // 创建共享捐赠罐
    public entry fun create(ctx: &mut TxContext) {
        let jar = TipJar {
            id: object::new(ctx),
            owner: tx_context::sender(ctx),
            total: 0,
        };
        transfer::share_object(jar);
    }

    // 任何人捐赠：把 Coin<SUI> 转给 jar.owner，并记录总额
    public entry fun donate(jar: &mut TipJar, payment: Coin<SUI>) {
        let amount = coin::value(&payment);
        jar.total = jar.total + amount;
        transfer::public_transfer(payment, jar.owner);
    }

    // 仅 owner 提取（清空罐并销毁共享对象）
    public entry fun withdraw(jar: &mut TipJar, ctx: &mut TxContext) {
        assert!(tx_context::sender(ctx) == jar.owner, 0); // 0 = 非 owner
        // 若想返还，可把 jar 内累计余额用 coin::from_balance 转出；
        // 这里演示「提取后删除对象」：
        let TipJar { id, owner: _, total: _ } = jar;
        object::delete(id);
    }
}
注意：上面 withdraw 直接删除罐但没把累计余额退还——因为余额早已在 donate 时转给 owner。若你设计成「余额留在 jar 内」则需在 withdraw 里用 coin::from_balance 把 Balance<SUI> 转出。请按你的设计保持一致。

8. 实战五：NFT 市场（核心）

这是本章核心：一个完整、可组合、原子交换的 NFT 市场。包含三个函数——

  • list：卖家把 NFT 挂单（放进共享 Listing 对象，记录价格与卖家）。
  • buy：买家用 PTB 付 Coin<SUI>，原子拿到 NFT、卖家收到币。
  • cancel：卖家取消挂单，取回 NFT。
// sources/market.move
module nft_market::market {
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::coin::{Self, Coin};
    use sui::sui::SUI;
    use sui::tx_context::{Self, TxContext};
    use sui::string::String;

    // 一个最简 NFT：有 id 与名字（key + store 才能流转）
    struct NFT has key, store {
        id: UID,
        name: String,
    }

    // 挂单对象（共享），持有被卖的 NFT
    struct Listing has key {
        id: UID,
        nft: NFT,
        price: u64,       // 单位 MIST
        seller: address,
    }

    // 铸造一个测试 NFT（演示用，真实场景应有独立 NFT 合约）
    public entry fun mint_nft(name: vector<u8>, ctx: &mut TxContext): NFT {
        let nft = NFT { id: object::new(ctx), name: sui::string::utf8(name) };
        transfer::transfer(nft, tx_context::sender(ctx)); // 先归铸造者
        nft                                            // 返回以便链式使用
    }

    // 挂单：把 NFT 包进共享 Listing
    public entry fun list(nft: NFT, price: u64, ctx: &mut TxContext) {
        let listing = Listing {
            id: object::new(ctx),
            nft,
            price,
            seller: tx_context::sender(ctx),
        };
        transfer::share_object(listing);
    }

    // 购买：原子交换（NFT 归买家，SUI 归卖家）
    public entry fun buy(listing: Listing, payment: Coin<SUI>, ctx: &mut TxContext) {
        let Listing { id, nft, price, seller } = listing;
        object::delete(id);                              // 摘单
        assert!(coin::value(&payment) == price, 1);      // 1 = 付款金额不符
        transfer::public_transfer(payment, seller);      // 币给卖家
        transfer::public_transfer(nft, tx_context::sender(ctx)); // NFT 给买家
    }

    // 取消：仅卖家可取回 NFT
    public entry fun cancel(listing: Listing, ctx: &mut TxContext) {
        assert!(tx_context::sender(ctx) == listing.seller, 2); // 2 = 非卖家
        let Listing { id, nft, price: _, seller: _ } = listing;
        object::delete(id);
        transfer::public_transfer(nft, tx_context::sender(ctx));
    }
}

8.1 TS 端：挂单

// 卖家挂单：把自己的 NFT 对象转入 Listing
const listTx = new Transaction();
listTx.moveCall({
  target: `${pkg}::market::list`,
  arguments: [
    listTx.object(nftId),               // 卖家名下的 NFT 对象
    listTx.pure.u64(50_000_000),        // 售价 0.05 SUI（MIST）
  ],
});
await client.signAndExecuteTransaction({ transaction: listTx, signer: seller });

8.2 TS 端：购买（PTB 原子付币）

// 买家：拆出精确面额 SUI 作为 payment，调用 buy
const buyTx = new Transaction();
const [payment] = buyTx.splitCoins(buyTx.gas, [buyTx.pure.u64(50_000_000)]);
buyTx.moveCall({
  target: `${pkg}::market::buy`,
  arguments: [
    buyTx.object(listingId),   // 共享 Listing 对象
    payment,                   // 恰好 price 的 Coin<SUI>
  ],
});
const res = await client.signAndExecuteTransaction({ transaction: buyTx, signer: buyer });
await client.waitForTransaction({ digest: res.digest });
// 成功：buyer 名下出现 NFT 对象，seller 余额 +0.05 SUI

8.3 TS 端：取消

const cancelTx = new Transaction();
cancelTx.moveCall({
  target: `${pkg}::market::cancel`,
  arguments: [cancelTx.object(listingId)],
});
await client.signAndExecuteTransaction({ transaction: cancelTx, signer: seller });
为什么这是「原子」的：整个 buy 是一个 PTB，要么付款与转 NFT 同时成功，要么全回滚。买家不可能「付了钱没拿到 NFT」，卖家也不可能「丢了 NFT 没收钱」——这正是 PTB 编排的威力。

9.2 test_scenario：多交易多用户模拟

test_scenario 让你在单测里模拟「用户 A 发交易 → 用户 B 发交易」的真实流程，包括对象在用户间转移。

// tests/market_tests.move
#[test]
fun test_list_and_buy() {
    use sui::test_scenario;
    use sui::tx_context;

    let seller = @0xA;
    let buyer  = @0xB;

    // ① 卖家铸造一个 NFT（mint_nft 返回并直接转移给 sender）
    test_scenario::begin(seller);
    {
        let ctx = &mut tx_context::dummy();
        // 用场景框架取回卖家刚得到的 NFT 并挂单
        let nft = test_scenario::take_from_sender<nft_market::market::NFT>(seller);
        nft_market::market::list(nft, 50_000_000, ctx);
    };

    // ② 买家购买：付 SUI（测试中用 test_scenario 提供的 coin 设施）
    test_scenario::next_tx(buyer);
    {
        // 取回刚创建的 Listing 共享对象
        let listing = test_scenario::take_shared<nft_market::market::Listing>();
        // 用买家余额造一个 Coin<SUI> 作为 payment
        let payment = test_scenario::sui_coins_for_testing(50_000_000);
        nft_market::market::buy(listing, payment, &mut tx_context::dummy());
    };

    // ③ 校验买家拿到 NFT、卖家余额增加
    test_scenario::next_tx(buyer);
    {
        let _nft = test_scenario::take_from_sender<nft_market::market::NFT>(buyer);
        // 若取到说明购买成功转移到买家
    };

    test_scenario::end();
}
说明：test_scenario 的具体辅助函数名随 Sui 版本略有差异；核心套路是 begin → take_from_sender/take_shared → 调函数 → next_tx → end。以你安装的 CLI 文档为准。

10. 安全与陷阱

陷阱后果防御
资产对象误加 copy/drop可被复制或丢弃，价值归零值对象只给 key, store
TreasuryCap 泄露他人无限增发你的币发布后立即转多签/销毁
共享对象前端竞争 + gas 竞价抢单被夹、交易被插队设滑点/超时参数、用专属撮合合约
