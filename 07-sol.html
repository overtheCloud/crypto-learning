SOL 篇 I：概念与钱包开发

从零理解 Solana 的高性能设计，并用 Node.js 在 devnet 上完整写出一个能转账、能发代币的钱包。主要参考：Solana 官方文档 solana.com/docs、Solana Cookbook solana.com/cookbook。

本章目标：
  1. 说清 Solana 为什么快：PoH + Tower BFT、400ms 出块与乐观确认；
  2. 彻底理解账户模型（一切皆账户）与 rent-exempt 押金；
  3. 掌握交易 / 指令 / PDA / CPI / SPL Token 的核心概念；
  4. 用 @solana/web3.js 在 devnet 实现助记词派生、查询、转账、代币操作；
  5. 用 wallet-adapter 把钱包接入 React 前端，并了解 web3.js v2 与 RPC 限速坑。

1. Solana 是什么：为高频交易而生

Solana 是一条权益证明（PoS）公链，核心卖点是高吞吐、低延迟、低费用。它在设计上把"可扩展性"当作第一优先级，目标是在普通硬件上也能达到数千 TPS，出块间隔约 400 毫秒。理解 Solana 的关键，是理解它如何用一系列工程手段把"全局时钟""并行执行""最小化冗余"做到极致。

与以太坊（账户 + 合约存储世界状态、EVM 串行执行）不同，Solana 的核心设计哲学有几点：

  • 历史证明 PoH（Proof of History）：在链上嵌入一个可验证的全局时间戳序列，让所有验证者无需相互通信就能就"事件发生的先后顺序"达成共识的时钟。
  • 并行执行：通过账户的"读写锁（read/write lock）"声明，验证者可以并行处理互不冲突的交易，而不是像 EVM 那样全局串行。
  • 无全局状态存储于合约：Solana 程序（合约）本身无状态，状态全部存在独立的"数据账户"里，从而天然支持程序升级与并行。
  • 租费模型 rent：账户占用链上空间需质押少量 SOL 作为押金（rent-exempt），不活跃但缴足押金的账户不会被删除；这是与 EVM storage 收费完全不同的模型。
注意：Solana 快，但代价是硬件门槛更高、状态模型更复杂、编程范式与 EVM 差异巨大。作为钱包开发者，你首先要适应"一切皆账户""私钥地址是 ed25519 公钥的 Base58""没有原生 mapping 存储概念"这些新习惯。

2. 共识与性能：PoH + Tower BFT + 乐观确认

2.1 历史证明 PoH：可验证延迟函数做全局时钟

PoH 本质是一个可验证延迟函数（VDF）的连续哈希链：每个输出都作为下一个输入的一部分，形成一条"时间流逝"的密码学记录。验证者可以"快进"验证而不必逐步重算，因此 PoH 不是共识本身，而是为共识提供可信的全局时钟。

有了这个时钟，验证者在投票时就不需要先对"时间戳"再达成一轮共识——时间顺序已经由 PoH 序列证明。这极大减少了通信开销。

一句话：PoH 让"先后顺序"本身可被密码学证明，Tower BFT 在这个时钟之上做 PBFT 风格的投票确认。

2.2 Tower BFT：基于 PoH 的 PBFT 变体

Tower BFT 是 Solana 对实用拜占庭容错（PBFT）的改造版本。验证者用"投票"来确认一个 PoH 哈希（即一个 slot / 区块）。为了安全，投票会锁定（lockout）质押的 SOL：越深入历史、重复确认的次数越多，回滚所需的质押成本呈指数上升。恶意验证者若试图分叉，会损失大量质押。

2.3 400ms 出块与乐观确认

  • Slot：约 400ms 一个 slot，每个 slot 由一位领导者（leader）负责出块。
  • 乐观确认（Optimistic Confirmation）：当某个区块被足够多质押权重的验证者"确认（confirmed）"后，网络就乐观地认为它不会回滚，客户端即可视为成功——无需等待完全 finalized。
  • confirmed vs finalized：confirmed 是"绝大多数投票通过"，finalized 是"已被超级多数（supermajority）根定、极难回滚"。钱包应用通常先等 confirmed 提升体验，关键操作再等 finalized。
经验值：转账类操作等 confirmed 通常 1~2 秒；涉及资金安全（如托管结算）建议等 finalized（约 12~32 个 slot，即十几秒）。

3. 账户模型精讲：一切皆账户

Solana 里所有东西都是账户（Account）。一个账户由 Solana 运行时统一管理，但"它是什么"取决于它的 owner 程序。账户有 5 个核心字段：

字段含义钱包开发关注点
lamports账户里有多少 lamport（1 SOL = 1e9 lamport）余额查询、转账金额单位
owner拥有该账户的程序（Program ID）。只有 owner 程序能修改账户数据判断代币账户归属、防止伪造
data账户存储的任意字节（程序状态）。程序账户此处为空解析代币余额、自定义状态
executable是否为可执行程序账户区分"程序"与"数据"
pubkey账户的 32 字节地址（ed25519 公钥 / PDA）转账目标、ATA 推导

3.1 程序账户 vs 数据账户

  • 程序账户（executable=true）：存放已编译的 BPF 字节码。程序本身无状态，它不保存用户数据。
  • 数据账户：由某个程序拥有，用来保存状态。例如一个 DeFi 池子的配置、一笔借贷头寸，都是独立的数据账户。数据账户的 owner 是管理它的程序。
可升级性：Solana 程序默认可以"升级"（用 loader 替换字节码），也可以设为不可变。这与以太坊不可变合约不同——但也意味着你要信任程序作者不会恶意升级。

3.2 rent 与 rent-exempt 押金

链上存储需要资源，因此每个账户要按占用空间支付"租金（rent）"。但 Solana 提供 rent-exempt（免租） 机制：只要账户里质押的 lamports 不低于"两年租金"的等价额，账户就永远不被回收。新创建账户（init）时，必须一次性转入足够的免租押金。

空间大约免租押金（历史值，随网络参数变动）
165 字节（一个 ATA 代币账户）约 0.00203928 SOL
82 字节（一个 Mint 账户）约 0.00141536 SOL
重要：关闭账户（close）会把免租押金退给指定账户，这是 Solana 上"清理垃圾账户、退回 SOL"的常用手段。钱包显示"可用余额"时，要把这些被锁定的押金算清楚。

4. 交易结构与指令 Instruction

4.1 一笔交易（Transaction）的结构

交易本质上是一段被签名的、可序列化的字节。它包含：

  • message：核心部分，包含
    • instructions：要执行的一条或多条指令；
    • recent_blockhash：最近一个区块哈希，作为"新鲜度"凭证，过期（约 150 个 slot）则交易作废；
    • fee_payer：支付手续费的账户（必须签名）；
    • account_metas：本交易涉及的所有账户及其 meta（是否签名者、是否可写）。
  • signatures：对应签名者账户对 message 的 ed25519 签名列表。

4.2 指令 Instruction 的三要素

每条指令告诉运行时："调用哪个程序（program_id），用哪些账户（accounts），带什么参数（data）"：

要素说明
program_id目标程序的地址
accounts该指令要读写的账户列表，每个带 meta：is_signer（需签名）、is_writable（可写）
data指令的入参，通常是 Borsh/自定义序列化后的字节（如"调用 transfer 并转 100 个 token"）
账户 meta 很关键：运行时靠 is_writable 决定哪些交易可并行、靠 is_signer 决定谁有权限。钱包在构造交易时，必须正确声明每个账户的 meta，否则要么并行冲突、要么权限不足被拒。

4.3 compute budget 与优先费

每笔交易有一个 compute budget（计算预算），限制其最多消耗的"计算单元（CU）"。当网络拥堵时，你可以附加一条 ComputeBudgetProgram 指令来：

  • setComputeUnitLimit：提高上限（复杂合约需要）；
  • setComputeUnitPrice：设置每 CU 的微 lamport 价格（= 优先费 / 小费），出价高者被 leader 优先打包。

5. PDA 与 CPI：程序的"身份证"与"打电话"

5.1 PDA（Program Derived Address，程序派生地址）

普通账户地址是 ed25519 公钥（在曲线上，有私钥）。PDA 是"不在 ed25519 曲线上"的地址，因此没有对应的私钥，外部无法用私钥签名它。

PDA 由 seeds（种子，如 b"vault"、用户 pubkey）+ program_id 通过带 bump（偏移量 255→0 寻找）的哈希推导出来。因为无私钥，只有拥有它的程序在 CPI 中通过提供相同 seeds + bump 来"代签"。

PDA 的意义：它让程序拥有"确定性、可预测"的"签名身份"，用来持有资金、做托管、做跨用户共享状态。类比：以太坊合约地址是创建者+nonce 决定的；Solana PDA 是 program+seeds 决定的，任何人都能算出同一个地址。

5.2 CPI（跨程序调用，Cross-Program Invocation）

程序 A 在执行中可以"调用"程序 B 的指令，这就是 CPI。被调用的程序 B 会把 A 传入的账户原样传递，并可选地"代签"由 A 的 PDA 拥有的账户。CPI 是 Solana 组合性的核心：钱包/前端只需触发顶层指令，底层 SPL Token、系统程序等由合约自动串联调用。

6. SPL Token 体系与 ERC-20 对照

SPL Token 是 Solana 的代币标准（类似 ERC-20，但更"账户化"）。

概念SPL Token以太坊 ERC-20
代币定义Mint 账户（保存总供应量、精度、mint 权限）合约内 mapping 状态
用户余额每个用户一个 TokenAccount（ATA），独立账户合约内 balances[user]
转账调用 Token Program，读写两个 TokenAccount调用合约 transfer 函数
授权/许可Approve + Delegate（另设 delegate 账户）approve/allowance
关联的"钱包地址"owner 的 system 账户 ≠ 其 ATA；ATA 由 owner+mint 推导用户地址即余额持有人

6.1 Mint 与 TokenAccount / ATA

  • Mint：一个代币的"定义账户"，其地址就是该代币的标识。字段含 supply、decimals、mint_authority。
  • TokenAccount（代币账户）：某 owner 对某 mint 的余额容器，保存 mint、owner、amount。
  • ATA（Associated Token Account，关联代币账户）：用 owner 公钥 + mint 地址 通过 PDA 推导出来的"标准" TokenAccount，保证每个用户对同一代币有唯一、可预测地址。钱包显示某代币余额，本质就是读该用户的 ATA。

7. 地址、密钥与集群

7.1 ed25519 与 Base58 地址

Solana 使用 ed25519 椭圆曲线。一个 Keypair 由私钥（32 字节）和公钥（32 字节）组成。钱包地址 = 公钥的 Base58 编码字符串（不含校验和前缀那种，普通地址就是裸 Base58）。

  • 私钥可以导出为 Uint8Array(64)（含公私钥），或编码为 Base58 字符串；
  • 常见助记词标准：BIP39 助记词 → 通过 ed25519-hd-key 按路径 m/44'/501'/0'/0' 派生出 ed25519 种子。

7.2 集群（Cluster）

集群用途RPC 示例
mainnet-beta主网，真实资产https://api.mainnet-beta.solana.com（公共，限速）
devnet开发网，可免费领水https://api.devnet.solana.com
testnet测试网，主要给验证者测试https://api.testnet.solana.com
localnet本地 solana-test-validatorhttp://127.0.0.1:8899
本篇实战用 devnet：可以反复用 requestAirdrop 领测试 SOL，随便造币测试，不影响主网资产。

8. 钱包开发实战：web3.js v1 基础

我们用 @solana/web3.js（v1） 在 Node.js 中完成钱包核心功能。先初始化项目：

// 初始化 npm 工程并安装依赖
// npm init -y
// npm install @solana/web3.js@1 @solana/spl-token bip39 ed25519-hd-key

import { Connection, Keypair, LAMPORTS_PER_SOL, SystemProgram, Transaction, PublicKey } from "@solana/web3.js";
import { generateMnemonic, mnemonicToSeedSync } from "bip39";
import { derivePath } from "ed25519-hd-key";
import nacl from "tweetnacl"; // 一些环境下需要显式引入 ed25519 库

// 1) 连接 devnet
const connection = new Connection("https://api.devnet.solana.com", "confirmed");

console.log("已连接 devnet，区块高度:", await connection.getBlockHeight());

8.1 生成密钥对 & 从助记词派生

Solana 地址派生路径为 m/44'/501'/0'/0'（BIP44，coin type 501 即 SOL）。

// 方式 A：直接生成一个全新随机钱包
const keypairA = Keypair.generate();
console.log("新地址:", keypairA.publicKey.toBase58());
console.log("私钥(64字节数组):", Array.from(keypairA.secretKey));

// 方式 B：从助记词派生标准 SOL 钱包（钱包开发的标准做法）
const mnemonic = generateMnemonic(); // 12 个英文单词，必须安全保管
console.log("助记词:", mnemonic);

// 先把助记词转成 BIP39 seed（64 字节），再用路径派生 ed25519 种子
const seed = mnemonicToSeedSync(mnemonic); // Buffer 64 字节
const path = "m/44'/501'/0'/0'";          // SOL 标准派生路径
const derived = derivePath(path, seed.toString("hex"));
const keypairB = Keypair.fromSeed(derived.key); // 用 32 字节种子生成
console.log("派生地址:", keypairB.publicKey.toBase58());

// 方式 C：从已有私钥数组恢复
const recovered = Keypair.fromSecretKey(keypairB.secretKey);
console.log("恢复地址一致?", recovered.publicKey.equals(keypairB.publicKey));
私钥安全：secretKey 是 64 字节（含私钥+公钥）。在真实钱包里，永远不要在控制台打印、不要明文存磁盘。浏览器端应走 wallet-adapter，由用户钱包扩展托管私钥。

8.2 领水、查余额、转账完整代码

// 领测试 SOL（devnet 可用；主网无此接口）
async function airdrop(address: string, amountSol: number) {
  const sig = await connection.requestAirdrop(
    new PublicKey(address),
    amountSol * LAMPORTS_PER_SOL
  );
  // 等待交易确认，避免后续查询读到旧余额
  await connection.confirmTransaction(sig, "confirmed");
  return sig;
}

// 查询余额（返回 lamport 整数）
async function getBalance(address: string) {
  const lamports = await connection.getBalance(new PublicKey(address));
  return lamports / LAMPORTS_PER_SOL; // 转成 SOL
}

// 完整转账（SOL）：构造交易 -> 加指令 -> 签名 -> 发送 -> 确认
async function transferSol(from: Keypair, toAddress: string, amountSol: number) {
  const tx = new Transaction();
  tx.add(
    SystemProgram.transfer({
      fromPubkey: from.publicKey,    // 付款方（必须签名）
      toPubkey: new PublicKey(toAddress),
      lamports: amountSol * LAMPORTS_PER_SOL,
    })
  );

  // 让运行时填入最新 blockhash 与 fee payer
  const signature = await connection.sendTransaction(tx, [from]);
  console.log("交易签名:", signature);

  // 等待确认；confirmed 提升体验，finalized 更安全
  const result = await connection.confirmTransaction(signature, "confirmed");
  if (result.value.err) throw new Error("转账失败: " + JSON.stringify(result.value.err));
  return signature;
}

// 跑一遍
const me = Keypair.generate();
await airdrop(me.publicKey.toBase58(), 1);          // 领 1 SOL
console.log("余额:", await getBalance(me.publicKey.toBase58()));

const friend = Keypair.generate();
await transferSol(me, friend.publicKey.toBase58(), 0.1);
console.log("friend 余额:", await getBalance(friend.publicKey.toBase58()));
recent_blockhash 与重放：sendTransaction 内部会自动帮你设好 recentBlockhash 和 feePayer。如果你手动构造 Transaction，记得 tx.recentBlockhash = (await connection.getLatestBlockhash()).blockhash 并且设置 tx.feePayer，否则会报 blockhash 找不到。

8.3 交易模拟 simulateTransaction

发送前可用 simulateTransaction 先"试跑"，它不消耗真实资产，却会返回错误与日志，非常适合调试。

const tx = new Transaction().add(
  SystemProgram.transfer({
    fromPubkey: me.publicKey,
    toPubkey: friend.publicKey,
    lamports: 1000,
  })
);
const simulation = await connection.simulateTransaction(tx, [me]);
console.log("模拟日志:", simulation.value.logs);
if (simulation.value.err) console.error("模拟失败:", simulation.value.err);

9. SPL Token 实战：发币与转账

引入 @solana/spl-token。下面完整演示：创建 Mint → 为用户创建 ATA → 铸造 → 转账。

import {
  createMint,           // 创建 Mint 账户
  getOrCreateAssociatedTokenAccount, // 获取/创建 ATA
  mintTo,               // 铸造代币
  transfer,             // 转账代币
  getAccount,           // 读取 TokenAccount 原始数据
  getAssociatedTokenAddress, // 仅计算 ATA 地址（不创建）
} from "@solana/spl-token";

// 1) 创建 Mint：6 位精度，mint 权限与冻结权限都归 me
const mint = await createMint(
  connection,
  me,                  // payer：支付免租押金（me 出 SOL）
  me.publicKey,        // mintAuthority：谁可以增发
  me.publicKey,        // freezeAuthority：谁可以冻结（可传 null）
  6                    // decimals：6 位小数
);
console.log("Mint 地址:", mint.toBase58());

// 2) 为 me 创建 ATA（关联代币账户），并把铸造的币打给它
const myAta = await getOrCreateAssociatedTokenAccount(
  connection, me, mint, me.publicKey
);

// 3) 铸造 1000 个代币（注意单位：amount = 数量 * 10^decimals）
await mintTo(
  connection, me,
  mint, myAta.address,
  me,                 // mintAuthority（必须签名）
  1000 * 10 ** 6      // 1000 个，精度 6
);
console.log("我的 ATA 余额:", (await getAccount(connection, myAta.address)).amount);

// 4) 为 friend 创建 ATA 并转 200 个过去
const friendAta = await getOrCreateAssociatedTokenAccount(
  connection, me, mint, friend.publicKey
);
await transfer(
  connection, me,
  myAta.address,      // 源
  friendAta.address,  // 目标
  me,                 // owner/授权者（必须签名）
  200 * 10 ** 6
);
console.log("friend ATA 余额:", (await getAccount(connection, friendAta.address)).amount);

9.2 设置优先费（ComputeBudgetProgram）

网络拥堵时，附加优先费指令可提升打包优先级。

import { ComputeBudgetProgram } from "@solana/web3.js";
import { TransactionMessage, VersionedTransaction } from "@solana/web3.js";

// 构造带优先费的转账交易

const tx = new Transaction()

9.3 签名消息 signMessage（钱包适配器场景）

钱包常用于"签名一段消息"来证明身份（登录、领空投），不发送链上交易。注意 web3.js 本身不直接 signMessage，前端由钱包扩展提供：

// 浏览器端（钱包已连接时），用 window.solana 或 adapter 提供的 signMessage
// 这里演示纯 Node 用 keypair 完成等效签名，便于理解
import nacl from "tweetnacl";
import bs58 from "bs58";

const message = "登录 example.com 时间为 2026-09-03";
const signature = nacl.sign.detached(
  new TextEncoder().encode(message),
  me.secretKey // 实际前端由用户钱包签名，私钥不出设备
);
const ok = nacl.sign.detached.verify(
  new TextEncoder().encode(message),
  signature,
  me.publicKey.toBytes()
);
console.log("验签通过?", ok);
console.log("签名(base58):", bs58.encode(signature));

10. 前端集成 wallet-adapter

真实 DApp 不应自己管私钥，而是让用户用 Phantom / Solflare 等浏览器扩展钱包。@solana/wallet-adapter 提供统一接口。下面是一个最小完整 React 示例。

// 安装：npm i @solana/wallet-adapter-react @solana/wallet-adapter-react-ui @solana/wallet-adapter-wallets
//        @solana/web3.js @solana/wallet-adapter-base

// App.tsx
import { useMemo } from "react";
import { ConnectionProvider, WalletProvider, useWallet, useConnection } from "@solana/wallet-adapter-react";
import { WalletModalProvider, WalletMultiButton } from "@solana/wallet-adapter-react-ui";
import { PhantomWalletAdapter, SolflareWalletAdapter } from "@solana/wallet-adapter-wallets";
import { PublicKey, LAMPORTS_PER_SOL, SystemProgram, Transaction } from "@solana/web3.js";

// 1) 顶层：提供 Connection 与 Wallet 上下文
function App() {
  const endpoint = "https://api.devnet.solana.com";
  const wallets = useMemo(() => [new PhantomWalletAdapter(), new SolflareWalletAdapter()], []);
  return (
    <ConnectionProvider endpoint={endpoint}>
      <WalletProvider wallets={wallets} autoConnect>
        <WalletModalProvider>
          <Dashboard />
        </WalletModalProvider>
      </WalletProvider>
    </ConnectionProvider>
  );
}

// 2) 业务组件：连接按钮 + 余额 + 转账
function Dashboard() {
  const { connection } = useConnection();
  const { publicKey, sendTransaction, connected } = useWallet();

  async function showBalance() {
    if (!publicKey) return;
    const bal = await connection.getBalance(publicKey);
    alert("余额: " + bal / LAMPORTS_PER_SOL + " SOL");
  }

  async function sendTo(toBase58: string, amountSol: number) {
    if (!publicKey) throw new Error("请先连接钱包");
    const tx = new Transaction().add(
      SystemProgram.transfer({
        fromPubkey: publicKey,
        toPubkey: new PublicKey(toBase58),
        lamports: amountSol * LAMPORTS_PER_SOL,
      })
    );
    // 钱包扩展会弹出签名确认，私钥不出设备
    const sig = await sendTransaction(tx, connection);
    await connection.confirmTransaction(sig, "confirmed");
    alert("已发送，签名: " + sig);
  }

  return (
    <div>
      <WalletMultiButton /> {/* 自带"连接钱包"按钮 */}
      {connected && (
        <div>
          <button onClick={showBalance}>查余额</button>
          <button onClick={() => sendTo("目标地址Base58", 0.01)}>转 0.01 SOL</button>
        </div>
      )}
    </div>
  );
}
要点：useWallet() 给你 publicKey 与 sendTransaction（由钱包代签），useConnection() 给 RPC 连接。所有"敏感操作"都由钱包扩展弹窗完成，你的前端永远拿不到私钥。

11. web3.js v2、Playground 与脚手架

11.1 VersionedTransaction 与 Address Lookup Table

当一笔交易涉及的账户很多（如聚合器路由要调 10+ 个账户），交易体积会超限。Address Lookup Table（ALT，地址查找表） 把常用地址"登记"进一个表，交易里只用 1 字节索引引用，从而大幅压缩体积。VersionedTransaction 就是支持 ALT 的新交易格式（v0）。

// web3.js v1 中也可构造 v0 交易
import { VersionedTransaction, TransactionMessage, AddressLookupTableProgram } from "@solana/web3.js";

// 拿到最近的 blockhash（v0 必须用 blockhash 对象）
const { blockhash, lastValidBlockHeight } = await connection.getLatestBlockhash();

const message = new TransactionMessage({
  payerKey: me.publicKey,
  recentBlockhash: blockhash,
  instructions: [/* 你的指令数组 */],
}).compileToV0Message(/* 可选：lookupTableAccounts */);

const vtx = new VersionedTransaction(message);
vtx.sign([me]);
const sig = await connection.sendTransaction(vtx);
await connection.confirmTransaction({ blockhash, lastValidBlockHeight, signature: sig });

11.2 Solana Playground 与 create-solana-dapp

  • Solana Playground（solpg.io）：浏览器内写 Rust/Anchor 合约、编译、部署到 devnet，零本地环境。新手先做合约强烈推荐。
  • create-solana-dapp：官方脚手架，一键生成"前端 Next.js + Anchor 合约"的全栈模板，自带 wallet-adapter 与测试。
# 本地脚手架（需要 Node 18+）
npx create-solana-dapp my-dapp
# 之后可在 web/ 写前端，anchor/ 写合约，programs/ 放 Rust

11.3 web3.js v2（@solana/kit）新架构简述

web3.js v2（包名 @solana/kit，曾用 @solana/web3.js@2）做了重构：

  • 全面 Tree-shaking 友好，按需引入，包体更小；
  • 采用 函数式 API（如 createSolanaRpc 替代 new Connection），地址用 Address 类型而非 PublicKey；
  • 原生支持 TransactionMessage / VersionedTransaction 与异步签名器（TransactionSendingSigner）；
  • 默认使用 Uint8Array 与 ABIs，性能更好。
迁移建议：新项目若追求体积/性能可直接用 v2；但生态大量示例与 spl-token 仍基于 v1。建议先精通 v1 的 Connection / Keypair / Transaction 心智模型，再平滑过渡到 v2，二者概念一致，只是 API 形态不同。

12. RPC 服务商与限速坑

公共 RPC api.devnet.solana.com / api.mainnet-beta.solana.com 有严格限速（约 1~2 请求/秒、每日配额低），只适合练手，做产品必须换专业服务商：

服务商特点
Helius增强 API（getAssets、webhook）、文档友好，新手友好
QuickNode稳定老牌、全球节点、有 Solana 专用插件
TritonSolana 基金会背景团队，专业 RPC
限速坑清单：
  • 429 错误：并发过高，需加指数退避重试；
  • getProgramAccounts 在大程序上极慢且可能被熔断，优先用索引器/增强 API；
  • blockhash 过期：长任务要定期刷新 recentBlockhash；
  • preflight 失败：sendTransaction 默认先 simulate，若节点状态不同步会误报，可关 skipPreflight（谨慎）；
  • WebSocket 订阅（onAccountChange）在公共 RPC 常掉线，生产要用长连接管理。

13.1 从文件加载 CLI 钱包到 web3.js

import fs from "fs";
import { Keypair } from "@solana/web3.js";

// CLI 默认钱包路径（Linux/macOS）；Windows 通常是 C:\\Users\\<你>\\.config\\solana\\id.json
const home = process.env.HOME || process.env.USERPROFILE;
const path = home + "/.config/solana/id.json";
const secret = Uint8Array.from(JSON.parse(fs.readFileSync(path, "utf8")));
const cliKeypair = Keypair.fromSecretKey(secret);
console.log("CLI 钱包地址:", cliKeypair.publicKey.toBase58());

14. 关闭账户与回收免租押金

不再需要的代币账户会一直锁着押金。closeAccount 可将其关闭，押金退回指定地址——这是链上"清理垃圾、回笼 SOL"的标准姿势。

import { closeAccount } from "@solana/spl-token";

// 把 friend 的 ATA 关闭，押金退回 friend 自己
await closeAccount(
  connection,
  me,                       // payer（付手续费）
  friendAta.address,        // 要关闭的代币账户
  friend.publicKey,         // 押金接收者
  friend                   // 该账户的 owner（必须授权签名）
);
console.log("已关闭 ATA，押金已退回 friend");

// 关闭后该地址的账户信息变为不存在
const after = await connection.getAccountInfo(friendAta.address);
console.log("关闭后账户:", after); // null
注意：只有账户的 owner（或经授权的 delegate）能关闭它；关闭后余额必须先清零或随账户一并处理，具体取决于实现。生产钱包应提供"一键回收小额代币账户押金"功能，提升用户体验。

15. approve / delegate：授权第三方代付

类比 ERC-20 的 approve，SPL Token 用 approve + transfer（由 delegate 发起）实现授权。下面的例子演示"授权另一个密钥花我的代币"：

import { approve, createApproveInstruction, revoke } from "@solana/spl-token";

// 授权 delegateKey 可以最多动我 ATA 里的 500 个代币
await approve(
  connection, me,
  myAta.address,    // 被授权的代币账户
  delegateKey,      // 受托人（delegate）公钥
  me,               // owner（授权者，签名）
  500 * 10 ** 6     // 授权额度
);

// 之后 delegate 可以"代我"把代币转走（delegate 自己签名）
// 在 DApp 里这一步往往由合约 CPI 完成，前端只负责 approve
import { createTransferInstruction } from "@solana/spl-token";
const ix = createTransferInstruction(
  myAta.address,      // 源（我的）
  friendAta.address,   // 目标
  delegateKey,        // 授权者（delegate 作为签名者）
  [delegateKey],      // 签名者
  100 * 10 ** 6
);
const tx = new Transaction().add(ix);
const sig = await connection.sendTransaction(tx, [delegateKeypair]);

// 收回授权
await revoke(connection, me, myAta.address, me);
授权风险：approve 给无限额度（MAX）是常见漏洞来源。钱包 UI 应清晰展示"你授权了哪个合约、多少额度"，并鼓励用户用小额或及时 revoke。

16. 离线签名与冷钱包思路

高安全场景（金库、多签）要求私钥所在环境不联网。做法是：在联网机器构造并序列化交易，传到离线机器签名，再把签名结果回传广播。

// 联网机器：构造交易并序列化为 base64（不含签名）
const tx = new Transaction().add(
  SystemProgram.transfer({
    fromPubkey: vault.publicKey,
    toPubkey: friend.publicKey,
    lamports: 1_000_000,
  })
);
tx.feePayer = vault.publicKey;
tx.recentBlockhash = (await connection.getLatestBlockhash()).blockhash;
const serialized = tx.serialize({ requireAllSignatures: false }).toString("base64");
// 把 serialized 通过安全通道交给冷机

// 离线机器：反序列化 -> 用冷私钥签名 -> 导出签名
import { Transaction } from "@solana/web3.js";
const coldTx = Transaction.from(Buffer.from(serialized, "base64"));
coldTx.partialSign(coldKeypair); // 只签，不广播
const signedBase64 = coldTx.serialize({ requireAllSignatures: false }).toString("base64");
// 回传 signedBase64

// 联网机器：恢复并广播
const finalTx = Transaction.from(Buffer.from(signedBase64, "base64"));
const sig = await connection.sendRawTransaction(finalTx.serialize());
await connection.confirmTransaction(sig, "finalized");
partialSign：Solana 交易支持"多方逐步签名"。多方、多签、冷签都靠 partialSign + requireAllSignatures:false 实现，最后再以 sendRawTransaction 广播。

17. 钱包余额面板最小实现

把上面能力拼起来，就是一个最简"钱包首页"：左边 SOL 余额，右边 SPL 代币列表。

async function getWalletPortfolio(owner: PublicKey) {
  // 1) SOL 余额
  const solBalance = await connection.getBalance(owner) / LAMPORTS_PER_SOL;

  // 2) 所有 SPL 代币账户
  const tokenAccounts = await connection.getParsedTokenAccountsByOwner(owner, {
    programId: new PublicKey("TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA"),
  });

  const tokens = tokenAccounts.value.map(({ account }) => {
    const info = account.data.parsed.info;
    return {
      mint: info.mint,
      amount: info.tokenAmount.uiAmount,    // 已按 decimals 折算后的可读数
      decimals: info.tokenAmount.decimals,
    };
  }).filter((t) => t.amount > 0); // 过滤零余额

  return { solBalance, tokens };
}

// 使用
const portfolio = await getWalletPortfolio(me.publicKey);
console.log("SOL:", portfolio.solBalance);
portfolio.tokens.forEach((t) => console.log(t.mint, t.amount));
