SUI 篇 I：概念与钱包开发

读懂对象模型与 Move，并用 TypeScript 从零写出一个可用的 Sui 钱包交互层。主要参考：Sui 官方文档 docs.sui.io、Mysten Labs 技术博客。

本章目标：
  • 理解 Sui 的「一切皆对象」模型与三类对象差异，以及它如何带来高并发与亚秒终局。
  • 掌握 Move 的资源线性类型哲学，能对照 Solidity 说出 Sui 资产安全的核心差异。
  • 理解 PTB（可编程交易块）的编排方式，以及它为何是 Sui 组合性的基础。
  • 用 @mysten/sui SDK 完成连接、生成密钥、查余额、查对象、SUI 转账的完整链路。
  • 了解 dapp-kit 前端集成、zkLogin、多签与赞助交易等钱包层能力。

1. Sui 是什么：定位与 Mysten Labs

Sui 是一条 Layer1 公链，由 Mysten Labs 团队开发。这个团队的背景非常关键：它的核心成员（包括首席执行官 Evan Cheng、首席科学家 Sam Blackshear）来自 Meta（原 Facebook）的 Novi/Diem 稳定币项目，正是他们在 Diem 项目中发明了 Move 语言。当 Diem 被关停后，团队带着 Move 与对「资产如何在链上安全表达」的深刻理解，创建了 Sui。

因此 Sui 与 Aptos（另一支 Diem 出身团队）共享 Move 的基因，但设计取向完全不同：Aptos 更偏向「改进版 Diem 共识」，而 Sui 把赌注押在了 对象模型（Object Model） 上——把链上状态彻底拆成独立的对象，从而在多数交易上绕开全局共识、实现并行执行。

一句话定位：Sui 是一条「以对象为最小状态单元、用并行执行换取高吞吐与低延迟」的 Move 公链，适合高频、可组合的资产交互场景（游戏、DeFi、社交）。

1.1 关键事实速览

项目说明
原生代币SUI（用于 gas、质押、治理），最小单位 MIST，1 SUI = 10⁹ MIST。
智能合约语言Move（Sui 版，带对象能力扩展），不是 EVM。
共识算法Mysticeti（基于 DAG 的拜占庭容错 BFT）。
终局时间独占对象走 FastPath，约 100~200 毫秒亚秒级终局。
测试网水龙头https://faucet.sui.io 或 CLI 命令 sui client faucet。
主网 RPChttps://fullnode.mainnet.sui.io:443，测试网 https://fullnode.testnet.sui.io:443。
提示：本篇所有代码默认连接 testnet，避免烧掉真实资产。请先到水龙头领取测试 SUI 再运行示例。

2. 对象模型精讲

Sui 的世界观可以浓缩为一句话：「一切皆对象」（Everything is an Object）。账户（地址）只是一个「可以拥有对象的身份」，链上真正被读写的不是账户余额映射，而是无数个独立对象。这与以太坊「一个大状态树 + 合约存储槽」的模型形成鲜明对比。

2.1 每个对象都有三段元数据

字段含义说明
ID唯一标识32 字节（256 位）的全局唯一 ID，由创建时的哈希派生，永不重复。
version版本号每次该对象被写入，版本号 +1。可用于判断对象是否被更新。
digest内容摘要对象内容与元数据的哈希，用于校验对象完整性、缓存与引用。
对照理解：以太坊里「地址 A 有 5 个 USDC」是 ERC-20 合约里一个 mapping 项；Sui 里「A 有 5 个 SUI」是 A 名下挂着的若干个 Coin<SUI> 对象（每个对象自身记录余额）。资产是「对象」而不是「数字」。

2.2 三类对象：Owned / Shared / Immutable

对象按「谁能动它、能不能并发」分三类，这是理解 Sui 性能的关键：

类型定义谁可以修改交易路径典型例子
Owned（独占）对象由某个地址独占拥有（对象里记录了 owner 地址）。仅 owner 通过签名交易FastPath：跳过全节点共识，并行执行用户的 Coin、NFT、私有计数器
Shared（共享）对象没有单一 owner，任何人可读可写。任何地址（需交易引用它）Consensus：走 Mysticeti DAG 全共识订单簿、共享计数器、DEX 池
Immutable（不可变）被冻结（freeze_object）后永远不可修改。无人可改只在引用时读取，不参与写冲突发布后的合约代码、配置常量
性能含义：独占对象之间「互不依赖」即可完全并行，互不排队；只有共享对象需要排序与共识，因此会成为吞吐瓶颈。设计合约时，应让高频路径尽量使用独占对象，把共享对象留作「全局协调点」（如撮合池）。

2.3 一个真实对象的 JSON 长什么样

用 getObject 读到的对象在 SDK 里大致是这样（已简化）：

{
  "objectId": "0x9f1c...a3",
  "version": "42",                       // 被写入 42 次
  "digest": "AoQ2...",                   // 内容摘要
  "type": "0x2::coin::Coin<0x2::sui::SUI>",  // 泛型类型，注意 <> 是 Sui 的 Coin<T>
  "owner": { "AddressOwner": "0xabc...123" }, // 独占对象：归某地址
  "content": {
    "dataType": "moveObject",
    "fields": {
      "id": { "id": "0x9f1c...a3" },      // 对象必须有 id: UID 字段
      "balance": "1500000000"             // 1.5 SUI（MIST）
    }
  }
}
// 共享对象 owner 则是 { "Shared": { "initial_shared_version": "7" } }
// 不可变对象 owner 为 "Immutable"
读对象诀窍：判断对象类别直接看 owner 字段——AddressOwner = 独占，Shared = 共享，Immutable = 不可变。钱包 UI 常用它来分组展示。

2.4 FastPath 与 Consensus 路径示意

// 独占对象交易：FastPath（无需全共识）
// 交易只引用 owner 名下的 Coin 对象 → 节点本地校验签名后即可并行执行
[Owner A 签名] --> 引用 Coin_A1, Coin_A2 --> 并行执行 --> 亚秒终局

// 共享对象交易：Consensus（走 DAG 共识）
// 交易引用全局共享池 Pool_X → 必须先由共识排序，再执行
[任意签名] --> 引用共享 Pool_X --> Mysticeti 排序 --> 执行 --> 终局

3. Move 语言哲学：资源即资产

Move 的名字来自「移动（move）」，核心哲学是 资源（Resource）线性类型：资产在语言层面就是「值」，它不能被复制、不能被悄悄丢弃，只能被「移动」到别处。

概念Solidity 中的麻烦Move / Sui 的做法
资产复制ERC-20 只是一串数字，逻辑写错就能多发。资产对象若 has key 且未授予 copy，编译器禁止复制。
资产丢失selfdestruct 或写到错误地址可能导致永久丢失。未授予 drop 能力的对象若「凭空消失」，编译报错。
重入合约调用外部合约时状态未更新易重入。Move 无动态分派到任意合约、无重入；对象所有权明确。
Move 的承诺：「如果一个值存在，它一定在某个地方；你无法在编译期之外让它凭空产生或消失。」 这让资产安全从「靠开发者小心」变成「靠编译器保证」。

下一篇会展开 Move 语法；这里先记住四个能力（Ability）：key（可作为对象被全局索引）、store（可被存入其他结构/转移）、copy（可复制）、drop（可在作用域结束时被丢弃）。一个「真金白银」的资产对象通常只拥有 key + store，绝不该有 copy 和 drop。

4. Mysticeti 共识与亚秒终局

Sui 的共识层叫 Mysticeti（名字源自一种深海鱼，寓意 DAG 结构）。它是一个基于 有向无环图（DAG） 的 BFT 共识：

  • 验证者把待排序的交易广播为 DAG 中的「顶点（vertex）」，彼此引用形成图结构。
  • 借助 DAG 内的因果引用，验证者可以在一轮通信内就确认一批交易的顺序，而非传统链式逐块确认。
  • 结果：亚秒级（sub-second）终局，即交易从提交到「不可逆」通常只需几百毫秒。
为什么重要：UX 上，Sui 的转账/兑换确认比多数链更接近「即时」。做钱包时你可以把等待时间设得很短，不必像 BTC 那样等 6 个确认。

5. Gas 机制与存储费

Sui 的 gas 由两部分组成，这是它区别于以太坊的特色：

组成含义Sui 特色
计算费（Computation）执行交易逻辑消耗的 gas，类似 ETH。按指令计费，可用存储返利抵扣一部分。
存储费（Storage）把对象写入链上存储的预付款。存入「存储基金（Storage Fund）」。
  • 存储基金与 rebate：用户支付存储费时，大部分进入存储基金并按 epoch 分配给验证者/质押者；当对象被删除或回收时，系统返还一部分存储费（rebate）给发起者。
  • 删除对象退存储费：这意味着「清理链上状态」在 Sui 上可能是「省钱」的，鼓励开发者及时回收不再需要的对象（如提取后可销毁的临时对象）。
钱包层含义：Sui 上转账/交易 gas 不高，但首次创建对象（如发币、铸 NFT）会预付存储费。注意 gasBudget 要留出存储余量，否则会因预算不足失败。

6. 地址体系与签名方案

  • 地址为 0x 前缀的 32 字节（256 位）十六进制串，例如 0x2a9f...e71c。
  • 地址通常由公钥经 blake2b 哈希派生（取低 256 位）。
  • Sui 原生支持多签名方案（flag）：ed25519、secp256k1（与 BTC/ETH 同）、secp256r1（WebAuthn/Passkey 用的曲线，利于手机原生登录）。
// 签名方案 flag（一个字节，用于标识地址来自哪种曲线）
// 0x00 = Ed25519
// 0x01 = Secp256k1
// 0x02 = Secp256r1 (WebAuthn / Passkey)

// 助记词派生的标准路径（BIP-44 风格，SLIP-44 中 Sui 的 coin_type = 784）
// m/44'/784'/0'/0'/0'

// 由公钥推导地址（伪代码，SDK 内部已封装）
address = "0x" + blake2b(pubkey_bytes, 256 位)[低 32 字节]
提示：ed25519 是 Sui CLI 与 @mysten/sui 默认方案；secp256r1 是 zkLogin/Passkey 的基础。多方案并存让钱包能同时兼容传统加密钱包与 Web2 登录。

7. 赞助交易 Sponsored Transaction

赞助交易（Sponsored Transaction）：让用户发起交易，但由第三方（赞助者）支付 gas。典型场景：

  • 新用户没有 SUI 也能用 dApp（免 gas 上手）。
  • 游戏/社交 dApp 替用户承担交互成本，提升留存。
  • 商户补贴用户操作。

流程上分两段签名：

// 赞助交易的两段式流程（概念）
// 第 1 步：用户用其私钥对「交易意图」签名（不含 gas 代付）
// 第 2 步：赞助者用其私钥签名，声明「我愿意为这笔交易付 gas」
// 然后把两个签名一起提交给全节点执行

用户(sender) --签名--> 交易块(PTB) --> 赞助者(sponsor) --垫付 gas 签名--> 全节点执行
// 结果：对象变更归属于用户，gas 从赞助者账户扣除
安全注意：赞助者应当只在「自己构造并校验过的交易」上代付，避免被构造恶意高额 gas 的交易消耗资金。第 15 篇会给出赞助交易代码框架。

8. Epoch 与验证者质押

  • Sui 把时间切成 epoch（纪元，约 24 小时）。每个 epoch 重新计算验证者集合与权重。
  • SUI 持有者可把币质押（stake）给验证者，获得质押奖励（来自 gas 与存储基金分配）。
  • 质押时你会得到一个 StakedSui 对象（独占对象！），解押后需经过「解除期（epoch 边界）」才能取回本金+奖励。
钱包集成提示：质押产出的 StakedSui 也是对象，会出现在 getOwnedObjects 结果里，UI 上要单独识别并展示。

9. PTB 可编程交易块

PTB（Programmable Transaction Block，可编程交易块）是 Sui 交易的「编排容器」。一个 PTB 可以包含多条命令，它们原子执行：要么全成功，要么全回滚。

9.1 常用命令

命令作用
SplitCoins把一个 Coin 拆成若干指定面额的新 Coin（类似「找零」）。
MergeCoins把多个 Coin 合并成一个。
TransferObjects把若干对象转移给某地址。
MoveCall调用某个 Move 包里的某个函数（entry）。
MakeMoveVec把若干同类型对象/值打包成一个 vector，传给后续命令。

9.2 为什么 PTB 是组合性的核心

以太坊上「用 USDC 买代币」往往需要：先 approve 给路由合约，再发一笔 swap 交易——至少两笔、且 approve 有授权风险。Sui 上同样的事是一个 PTB 内完成：

// 一个 PTB 原子完成「拆 SUI → 调用 DEX swap → 把得到的币转给自己」
const tx = new Transaction();
const [coinOut] = tx.splitCoins(tx.gas, [amount]); // 拆出要花的 SUI
tx.moveCall({
  target: `${dexPackage}::router::swap`,
  arguments: [coinOut, /* 其他参数 */],
  typeArguments: ["0x2::sui::SUI", someTokenType],
});
// swap 内部直接把产出币转给 sender，无需先 approve
await client.signAndExecuteTransaction({ transaction: tx, signer });
PTB 让「多步操作」变成「一笔原子交易」，没有中间态、没有授权残留、天然可组合。这是 Sui 上 DeFi/聚合器体验优于 EVM 的根本原因之一。

9.3 用 MakeMoveVec 打包数组参数

某些 Move 函数参数是 vector<object> 或 vector<u64>。这时用 makeMoveVec 把多个结果聚成数组，再传给 moveCall。

// 例：一次把 3 个 Coin 合并，并把「合并结果」传给某函数（vector<Coin> 参数）
const tx = new Transaction();

// 拆出 3 个不同面额的 Coin
const [c1] = tx.splitCoins(tx.gas, [tx.pure.u64(1e9)]);
const [c2] = tx.splitCoins(tx.gas, [tx.pure.u64(2e9)]);
const [c3] = tx.splitCoins(tx.gas, [tx.pure.u64(3e9)]);

// 把 3 个 Coin 对象打包成 vector<Coin>（注意是对象引用，用 tx.object 思路）
const vec = tx.makeMoveVec({ elements: [c1, c2, c3] });

// 把 vector 传给某 Move 函数（假设它接收 vector<Coin<SUI>>）
tx.moveCall({
  target: `${pkg}::vault::deposit_many`,
  arguments: [vec],
  typeArguments: ["0x2::sui::SUI"],
});
// 整个动作仍是一笔 PTB，原子执行
记忆点：SplitCoins/MergeCoins 管「币的拆合」，MakeMoveVec 管「数组打包」，TransferObjects 管「所有权转移」，MoveCall 管「逻辑调用」——四个命令组合几乎能覆盖 90% 的 Sui 交互。

10. 钱包开发实战（TypeScript）

下面进入实战。我们用官方 @mysten/sui SDK（V1+）从头搭一个钱包交互层。先在项目里安装：

npm install @mysten/sui @mysten/bcs
版本提示：本篇代码基于 @mysten/sui 的 V1 API（SuiClient、Transaction）。若你装到 V0.x，方法名略有差异，请对照官方迁移指南。

10.1 连接 SuiClient（testnet）

import { getFullnodeUrl, SuiClient } from "@mysten/sui/client";

// 连接测试网全节点；也可传 "mainnet" / "devnet" / "localnet"
const client = new SuiClient({ url: getFullnodeUrl("testnet") });

// 探活：读取当前 epoch 与参考 gas 价格
const checkpoint = await client.getLatestCheckpointSequenceNumber();
console.log("最新 checkpoint 序号:", checkpoint);
const price = await client.getReferenceGasPrice();
console.log("参考 gas 价格:", price);

10.2 生成密钥对与助记词导入导出

import { Ed25519Keypair } from "@mysten/sui/keypairs/ed25519";
import { generateMnemonic, mnemonicToSeedSync } from "@scure/bip39";
import { wordlist } from "@scure/bip39/wordlists/english";

// 1) 全新生成一个 ed25519 密钥对
const keypair = new Ed25519Keypair();
console.log("地址:", keypair.getPublicKey().toSuiAddress());
console.log("私钥(仅演示，切勿泄露):", keypair.getSecretKey());

// 2) 导出助记词（12 个英文单词），用于钱包「备份」
const mnemonic = generateMnemonic(wordlist);
console.log("助记词:", mnemonic);

// 3) 从助记词按标准路径 m/44'/784'/0'/0'/0' 派生密钥
//    derivePath 在 SDK 内部使用 @mysten/sui 的 fromSeed
import { Ed25519Keypair as KP } from "@mysten/sui/keypairs/ed25519";
const seed = mnemonicToSeedSync(mnemonic, ""); // 第二个参数为可选 passphrase
const derived = KP.fromSeed(seed.slice(0, 32)); // 取前 32 字节作为 ed25519 种子
console.log("派生地址:", derived.getPublicKey().toSuiAddress());
安全警告：生产环境绝不要把助记词/私钥明文打印或存前端。真实钱包应使用受保护环境（浏览器 Extension 的 isolated world、或系统密钥库）。本文仅为教学演示。

10.3 查询余额 getBalance

// 查询某地址的 SUI 余额（coinType 缺省即 SUI）
const balance = await client.getBalance({

// Sui 对象可能很多，必须分页读取；cursor 为上一页末的游标
async function listAllObjects(owner: string) {
  let cursor: string | null | undefined = null;
  const all = [];
  do {
    const page = await client.getOwnedObjects({
      owner,
      filter: { MatchAll: [] },   // 不过滤；也可按 StructType 过滤
      options: { showType: true, showContent: true, showDisplay: true },
      limit: 50,                  // 每页最多 50
      cursor,
    });
    all.push(...page.data);
    cursor = page.hasNextPage ? page.nextCursor : null;
  } while (cursor);
  return all;
}

10.5 SUI 转账（完整 PTB：splitCoins + transferObjects）

import { Transaction } from "@mysten/sui/transactions";

// 给目标地址转 0.5 SUI
async function transferSui(sender: Ed25519Keypair, to: string, amountSui: number) {
  const tx = new Transaction();

  // 拆币：从 gas 对象里拆出 amountSui 个 SUI（单位 MIST）
  const [coin] = tx.splitCoins(
    tx.gas,                       // 来源：本交易的 gas 对象
    [tx.pure.u64(amountSui * 1_000_000_000)]
  );

  // 转对象：把拆出的 coin 转给 to
  tx.transferObjects([coin], tx.pure.address(to));

  // 签名并执行
  const result = await client.signAndExecuteTransaction({
    transaction: tx,
    signer: sender,
    options: { showEffects: true, showObjectChanges: true },
  });

  // 等待终局（Sui 终局极快，这里用 waitForTransaction 更稳妥）
  const digested = await client.waitForTransaction({
    digest: result.digest,
    options: { showEffects: true },
  });
  console.log("转账 digest:", digested.digest);
  console.log("状态:", digested.effects?.status.status); // "success"
  return digested;
}
细节：tx.gas 表示「用本交易自身的 gas 对象作为拆币来源」，等价于把 gas 余钱当成一个大 Coin 来切。转账后剩余会作为找零自动并回 sender 的 gas 对象。

10.7 调用链上 Move 函数（MoveCall）

// 以「调用一个发币包的 mint 函数」为例
function buildMintTx(packageId: string, treasuryCapId: string, to: string, amount: number) {
  const tx = new Transaction();
  tx.moveCall({
    target: `${packageId}::my_coin::mint`, // 格式：包::模块::函数
    arguments: [
      tx.object(treasuryCapId),            // TreasuryCap 对象（权限）
      tx.pure.u64(amount),                 // 数量
      tx.pure.address(to),                 // 接收者
    ],
    // 若该模块是泛型，需要 typeArguments；本例无泛型
  });
  return tx;
}

11. 读取并解析 Move 对象

链上对象通常以 BCS 编码存储，SDK 会自动解析成 JSON 友好的结构。我们通过 getObject 读取并访问其字段。

// 读一个对象的完整内容
const obj = await client.getObject({
  id: "0x对象ID",
  options: { showContent: true, showType: true, showDisplay: true },
});

const content = obj.data?.content;
if (content && content.dataType === "moveObject") {
  // fields 里就是 Move 结构体的字段
  const fields = content.fields as Record<string, any>;
  console.log("对象类型:", content.type);
  console.log("字段:", fields);
  // 例如 Counter 对象：fields = { id: {...}, value: "42" }
  const value = Number(fields.value);
  console.log("当前计数:", value);
}

// 读 Display（合约作者可在链上配置的展示元数据，如 NFT 名字/图片）
const display = obj.data?.display?.data;
console.log("展示名:", display?.name, "图片:", display?.image_url);
提示：showDisplay 依赖合约是否实现了 sui::display 标准；没有时返回空，UI 需有兜底展示逻辑。

12. BCS 序列化概念

BCS（Binary Canonical Serialization）是 Sui/Move 使用的二进制序列化格式，特点是「确定性」——同样的数据永远序列化成完全相同的字节，便于哈希与共识。常见用途：

  • 链上对象存储的底层编码。
  • 把交易参数（u64、address、vector 等）编码成字节传给 MoveCall。
  • 跨语言（Rust / TS / Python）一致地读写链上数据。
import { bcs } from "@mysten/bcs";

// 用 bcs 手动编码一个 u64 数量（SDK 的 tx.pure.u64 内部即封装了它）
const encoded = bcs.u64().serialize(1_000_000_000).toBytes();
console.log("编码后字节:", encoded);

// 解码回数字
const decoded = bcs.u64().parse(Uint8Array.from(encoded));
console.log("解码:", decoded.toString());
记住：日常开发几乎不需要手写 BCS，SDK 的 tx.pure.* 与 tx.object(...) 已自动处理。但理解 BCS 有助于排查「参数类型不匹配」类错误。

13. 前端集成 @mysten/dapp-kit

要在 React 前端让用户用浏览器钱包（如 Slush）连链并签名，官方提供 @mysten/dapp-kit。下面是最精简完整示例。

import { createNetworkConfig } from "@mysten/dapp-kit";
import { getFullnodeUrl, SuiClient } from "@mysten/sui/client";
import { SuiClientProvider, WalletProvider, ConnectButton, useCurrentAccount, useSignAndExecuteTransaction } from "@mysten/dapp-kit";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import "@mysten/dapp-kit/dist/index.css"; // 注意：dapp-kit 自带少量样式

// 1) 配置网络（这里只暴露 testnet，也可加 mainnet）
const { networkConfig } = createNetworkConfig({
  testnet: { url: getFullnodeUrl("testnet") },
});
const queryClient = new QueryClient();

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <SuiClientProvider networks={networkConfig} defaultNetwork="testnet">
        <WalletProvider>
          <Page />
        </WalletProvider>
      </SuiClientProvider>
    </QueryClientProvider>
  );
}

// 2) 业务页面：连接按钮 + 当前账户 + 调用链上函数
function Page() {
  const account = useCurrentAccount();          // 当前连接的账户（未连为 null）

  // 3) 调用链上函数：useSignAndExecuteTransaction 负责弹钱包签名
  const { mutate: signAndExecute } = useSignAndExecuteTransaction();

  function callSomeFunction() {
    const tx = new (require("@mysten/sui/transactions").Transaction)();
    tx.moveCall({
      target: "0x包::模块::函数",
      arguments: [ /* ... */ ],
    });
    // 把交易交给钱包签名并执行
    signAndExecute({ transaction: tx }, {
      onSuccess: (res) => console.log("成功 digest:", res.digest),
      onError: (e) => console.error("失败:", e),
    });
  }

  return (
    <div>
      <ConnectButton />                       {/* 渲染「连接钱包」按钮 */}
      {account ? (
        <div>
          <p>已连接: {account.address}</p>
          <button onClick={callSomeFunction}>调用合约</button>
        </div>
      ) : (
        <p>请先连接钱包</p>
      )}
    </div>
  );
}
调用链说明：SuiClientProvider 提供 RPC 客户端 → WalletProvider 接入 Wallet Standard 标准钱包 → ConnectButton 触发连接 → useCurrentAccount 读当前账户 → useSignAndExecuteTransaction 把交易交给钱包签名上链。整条链无需你自己管理私钥。

14. Slush 与 Wallet Standard

  • Slush 是 Mysten Labs 官方推出的 Sui 钱包（浏览器扩展 + 移动端），原生支持对象模型、zkLogin、赞助交易等特性。
  • Wallet Standard 是一套跨链钱包接口标准（类似 EVM 的 EIP-1193），dApp 通过它自动发现并连接已安装的兼容钱包，无需为每个钱包写适配代码。
  • 因为 dapp-kit 基于 Wallet Standard，只要用户装了 Slush（或其他兼容钱包），上面的 ConnectButton 就能直接列出并连接。
开发建议：优先用 Wallet Standard + dapp-kit，而不是自己实现「Slush 专属」连接逻辑，这样你的 dApp 未来也能连上新钱包。

15. zkLogin：无助记词登录

zkLogin 让用户可以「用 Google/Twitch 等 OAuth 账号登录即拥有 Sui 地址」，无需助记词。原理：

  1. 用户用 OAuth 登录，拿到身份提供商（如 Google）签发的 JWT（里面含用户唯一标识，如 email/sub）。
  2. 把 JWT 与一个用户自己保存的 salt 一起，通过零知识证明（zk）生成一个「证明」，证明「我知道某 JWT + 某 salt」，但不暴露 JWT 内容。
  3. 链上用「JWT 的 issuer + audience + salt 的哈希」派生出地址。之后用户用 zkProof 授权交易即可。
// zkLogin 集成流程（高层，非逐行代码）
// 1) 前端引导用户 OAuth 登录，拿到原始 JWT（仅在本地使用，不上链）
// 2) 调用 zk  prover 服务/本地生成 proof（输入：JWT、salt、zkLogin 电路）
// 3) 构造 ZkLoginSignature，随交易一起提交
const tx = new Transaction();
tx.setSender(zkLoginAddress);          // zkLogin 派生出的地址
// 交易本身与普通交易一样，只是签名材料换成 zkProof
await client.signAndExecuteTransaction({ transaction: tx, signature: zkLoginSignature });
维度传统助记词钱包zkLogin
上手成本需备份 12 词直接用 OAuth 账号
私钥保管用户自管由 salt + JWT 派生（用户需保管 salt）
适用场景原生的加密用户Web2 用户、游戏、社交登录
注意：salt 的保管至关重要——salt 丢失等同于「丢了私钥」。生产方案通常把 salt 存在用户云盘或托管服务，并配合密钥轮换策略。

16. 多签 Multisig

Sui 原生支持多签地址：由 N 个公钥按阈值 M 组成（如 2-of-3）。发起交易时需要 M 个成员分别签名，再聚合成一个多签交易提交。

import { MultiSigPublicKey } from "@mysten/sui/multisig";
import { Ed25519Keypair } from "@mysten/sui/keypairs/ed25519";

// 三个成员公钥
const k1 = new Ed25519Keypair();
const k2 = new Ed25519Keypair();
const k3 = new Ed25519Keypair();

// 构造 2-of-3 多签地址（权重各 1，阈值 2）
const multisig = MultiSigPublicKey.fromPublicKeys({
  threshold: 2,
  publicKeys: [
    { publicKey: k1.getPublicKey(), weight: 1 },
    { publicKey: k2.getPublicKey(), weight: 1 },
    { publicKey: k3.getPublicKey(), weight: 1 },
  ],
});
console.log("多签地址:", multisig.toSuiAddress());

// 构造交易并让其中两个成员分别签名，再聚合
const tx = new Transaction();
/* ... 填充交易内容 ... */
const sig1 = (await tx.sign({ client, signer: k1 })).signature;
const sig2 = (await tx.sign({ client, signer: k2 })).signature;
const multisigSig = multisig.serializeSignature([sig1, sig2]); // 聚合

await client.executeTransactionBlock({
  transactionBlock: tx,
  signature: multisigSig,
});
用途：金库（Treasury）、DAO 治理、团队共管资产。注意多签地址本身也是普通 Sui 地址，可以拥有任意对象。

17.2 监听合约事件（queryEvents）

合约通过 sui::event::emit 发出的事件，链下可用 queryEvents 轮询检索，非常适合「订单成交、转账到账」等通知。

// 按「包::模块::事件名」过滤事件；event 名是 Move 结构体的类型全名
const events = await client.queryEvents({
  query: {
    MoveEventType: "0x包ID::counter::CounterIncremented", // 事件结构体全限定名
  },
  limit: 50,
  order: "descending",
});
for (const e of events.data) {
  console.log("交易:", e.transactionDigest, "解析后字段:", e.parsedJson);
}

// 轮询示例：每 3 秒查一次新事件（简易版；生产用 checkpoint 订阅更稳）
async function pollEvents(lastCursor: string | null) {
  const page = await client.queryEvents({
    query: { MoveEventType: "0x包ID::counter::CounterIncremented" },
    cursor: lastCursor,
    limit: 50,
  });
  for (const e of page.data) console.log("新事件:", e.parsedJson);
  return page.hasNextPage ? page.nextCursor : lastCursor;
}
setInterval(async () => { /* cursor = await pollEvents(cursor) */ }, 3000);
生产建议：高频监听请用基于 WebSocket 的「checkpoint 订阅」或自建索引器（如 Sui 的 indexed GraphQL），比定时轮询更省资源也更实时。

18. 调试技巧与常见错误

现象可能原因排查
交易失败：gas budget 不足未留出存储费，或拆分面额过大先 dryRun 看 gasUsed，把 gasBudget 调高 2~3 倍。
moveCall 报错「function not found」包未发布 / 模块名拼错 / 函数非 entry核对 target 格式 包::模块::函数，确认函数有 entry 或 public 可见性。
类型报错「type mismatch」参数 BCS 类型与 Move 签名不符用 tx.pure.u64 / .address / .bool 显式声明类型。
共享对象交易明显更慢走 Mysticeti 共识排序属正常；高频路径改用独占对象或批处理。
读对象 fields 为空未加 showContent: true在 getObject/getOwnedObjects 的 options 里打开 content。
私钥永远别进前端：本文为演示把 Ed25519Keypair 写在 Node 脚本里。真实钱包（Slush、dapp-kit）由扩展在隔离环境保管私钥，dApp 只拿到「签名请求」与「地址」。务必遵循这个边界。

19. 综合：一个最小 CLI 钱包脚本

把前面知识点串起来，下面是一个可直接运行的 Node 脚本骨架：生成账户、领水（需你手动在浏览器完成领取，或用 faucet API）、查余额、转账。把代码存为 wallet.ts 用 tsx wallet.ts 运行。

import { getFullnodeUrl, SuiClient } from "@mysten/sui/client";
import { Ed25519Keypair } from "@mysten/sui/keypairs/ed25519";
import { Transaction } from "@mysten/sui/transactions";

const client = new SuiClient({ url: getFullnodeUrl("testnet") });

async function main() {
  // 1) 账户：这里复用已存在的私钥（演示）。生产请改为助记词派生或环境变量读取
  const keypair = Ed25519Keypair.fromSecretKey("你的base64私钥");
  const me = keypair.getPublicKey().toSuiAddress();
  console.log("本钱包地址:", me);

  // 2) 余额
  const bal = await client.getBalance({ owner: me });
  console.log("SUI 余额(MIST):", bal.totalBalance);

  // 3) 转账 0.05 SUI 给目标（请替换为真实测试地址）
  const to = "0x目标地址";
  const tx = new Transaction();
  const [coin] = tx.splitCoins(tx.gas, [tx.pure.u64(0.05 * 1e9)]);
  tx.transferObjects([coin], tx.pure.address(to));

  // 先 dryRun 估 gas
  const dry = await client.dryRunTransaction({ transaction: tx });
  console.log("预估 gasUsed:", dry.effects?.gasUsed);

  // 再真正执行
  const res = await client.signAndExecuteTransaction({
    transaction: tx, signer: keypair, options: { showEffects: true },
  });
  await client.waitForTransaction({ digest: res.digest });
  console.log("转账完成 digest:", res.digest);

  // 4) 校验对方到账
  const newBal = await client.getBalance({ owner: to });
  console.log("对方 SUI 余额(MIST):", newBal.totalBalance);
}

main().catch((e) => { console.error(e); process.exit(1); });
