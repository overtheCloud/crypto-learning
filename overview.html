数字货币钱包开发：从入门到精通（速查总览）

覆盖 BTC、ETH、SOL、TRON、SUI 五大公链的基础概念 → 钱包开发 → 智能合约 → DeFi 完整学习路径。每一步均附行业最经典的教程与官方文档，配套代码示例与实战项目。

🔑 密钥与 HD 钱包 ⚡ 交易构建与签名 📜 智能合约 💸 DeFi 协议 🛡️ 安全审计

① 从入门到精通：总路线图 ROADMAP

整个路径分为 8 个阶段，建议按顺序推进。前三阶段（通用基础 + BTC + ETH）是所有链的根基，学完后 SOL / TRON / SUI 可以按兴趣与业务需要并行学习——TRON 和 ETH 同为 EVM/Solidity 体系（学完 ETH 几乎免费送 TRON），SOL 和 SUI 则需要新的语言与思维模型。

P0

前置能力（1–2 周）

JavaScript/TypeScript（Node.js）、Python 基础；了解 Rust（SOL/SUI 需要）；Git 与命令行。不需要密码学背景，P1 会补。

完全零基础（小白）？先用 2–4 周学会 JavaScript 基础语法（推荐 MDN / freeCodeCamp / 廖雪峰教程，三选一），再从 P1 开始。全程不需要买币，所有操作在免费测试网完成。详见课程目录页「零基础从这里开始」。

产出：能独立写 Node.js 脚本、读懂 Rust 基本语法

P1

区块链与钱包通用原理（2–3 周）★ 必学

哈希 / 椭圆曲线 secp256k1 / ed25519 / 数字签名；助记词 BIP39、分层确定性钱包 BIP32、多币种路径 BIP44/84；UTXO 模型 vs 账户模型 vs 对象模型；地址编码（Base58 / Bech32 / hex / Sui Bech32）。

经典教程：《Mastering Bitcoin》前 5 章 + learnmeabitcoin.com；产出：手写一个「助记词 → 多链地址」生成器

P2

Bitcoin 深入（3–4 周）

UTXO、脚本语言、隔离见证、PSBT；bitcoinjs-lib / python-bitcoinlib 实战；测试网转账。

经典教程：《Mastering Bitcoin》全书 + 《Programming Bitcoin》；产出：命令行钱包（生成/查余额/构建交易/广播）

P3

Ethereum 与 EVM 体系（6–8 周）★ DeFi 主战场

账户、Gas、EVM、Solidity、ERC 标准；ethers.js/viem + Foundry/Hardhat 工具链；EIP-155 / EIP-712 签名；DeFi：DEX/AMM、借贷、预言机。TRON 复用本阶段 90% 知识。

经典教程：《Mastering Ethereum》+ CryptoZombies + Cyfrin Updraft + Ethernaut；产出：发行 ERC-20、写一个 Mini-DEX

P4

Solana（4–6 周）

账户模型（Program/Account/PDA/Rent）、Rust、Anchor 框架、SPL Token、@solana/web3.js（v1 与 v2）、钱包适配器；Jupiter / Orca 等 DeFi。

经典教程：Solana 官方课程 + Anchor Book + Paulx Escrow 教程；产出：Anchor 全栈 dApp（含 PDA + 前端）

P5

TRON（2–3 周，EVM 体系快速迁移）

与以太坊的差异：TVM、Energy/Bandwidth 资源模型、TRC-20（最大 USDT 发行链）、TronBox / TronWeb / TronLink；JustLend 等 DeFi。

经典教程：developers.tron.network 官方文档（有中文版）；产出：Shasta 测试网部署 DApp + TRC-20 转账脚本

P6

Sui（4–5 周）

Move 语言、对象模型（Owned/Shared/Immutable）、PTB 可编程交易块、zkLogin；@mysten/dapp-kit；Cetus / DeepBook 等 DeFi。

经典教程：Sui 官方文档 + Sui Move Intro Course + Move Book；产出：发布 Move 包 + React 前端 dApp

P7

精通：安全、架构与跨链（持续）

智能合约安全与审计（重入、整数溢出、私钥管理漏洞）、MPC / AA（ERC-4337）钱包、跨链桥原理、Trust Wallet Core 多链钱包源码研读。

经典教程：Damn Vulnerable DeFi + Secureum + RareSkills；产出：一个支持 3+ 链的多币种钱包 Demo

时间预估：全职学习约 4–5 个月完成 P0–P6；业余时间（每天 1–2 小时）约 10–12 个月。建议主线 ETH 优先——EVM 生态的资料量、工具链成熟度、DeFi 深度远超其他链，且 TRON 直接复用。

② 通用基础：所有链共用 FOUNDATIONS

2.1 必须掌握的密码学

哈希函数

SHA-256、Keccak-256、RIPEMD-160。用途：区块链接、地址生成、签名摘要。特性：单向、抗碰撞、雪崩效应。

椭圆曲线签名

secp256k1（BTC/ETH/TRON：256 位私钥 → 公钥）、ed25519（SOL/SUI：更快、签名即公钥可推导）。私钥本质是 256 位随机数。

数字签名

ECDSA（r, s, v）与 Schnorr / EdDSA。签名证明「私钥持有者授权了这笔交易」，且不泄露私钥。EIP-712 结构化签名是钱包开发高频考点。

2.2 HD 钱包：BIP32 / BIP39 / BIP44 —— 钱包开发的核心

现代钱包（MetaMask、TronLink、Phantom、Slush）全部基于同一套标准：一个助记词派生所有链的所有地址。

  • BIP39：128/256 位熵 → 校验 → 2048 词表映射为 12/24 个助记词；助记词 + 密码短语经 PBKDF2-HMAC-SHA512（2048 轮）拉伸为 512 位种子。
  • BIP32：种子经 HMAC-SHA512 生成主密钥 + 链码；父密钥可派生子密钥（ hardened ' 与 normal），形成树状结构；xpub/xprv 扩展密钥可只凭公钥派生地址（观察钱包原理）。
  • BIP44/84/86：标准化派生路径 m / purpose' / coin_type' / account' / change / index，coin_type 由 SLIP-44 定义。
链曲线派生路径（coin_type）地址格式示例
BTC（原生隔离见证）secp256k1m/84'/0'/0'/0/0bc1q…（Bech32）
BTC（传统）secp256k1m/44'/0'/0'/0/01A1zP…（Base58, P2PKH）
ETHsecp256k1m/44'/60'/0'/0/00x…40 位 hex（公钥 Keccak-256 后 20 字节）
TRONsecp256k1m/44'/195'/0'/0/0T…（Base58Check，= ETH 地址加 0x41 前缀）

SUIed25519 / secp256k1 / secp256r1m/44'/784'/0'/0'/0'0x…（Bech32, blake2b 派生）

2.3 三种状态模型：理解各链差异的钥匙

UTXO 模型（BTC）

余额 = 未花费交易输出集合。转账 = 消费若干 UTXO 作为输入 + 生成新 UTXO（含找零）。并行安全、隐私好，但无原生智能合约。

账户模型（ETH / TRON / SOL）

全局状态存储每个账户的余额与数据，转账直接改余额。智能合约也是账户。直观易编程，但状态膨胀、并发需 nonce/序号防重放。

对象模型（SUI）

资产是一等公民「对象」，每个对象有唯一 ID 与属主。独占对象交易可并行执行（Mysticeti 共识 <400ms 终局），共享对象才走全序共识。

③ Bitcoin (BTC) UTXO · 脚本 · 数字黄金

3.1 基础概念

  • 共识：PoW（工作量证明），10 分钟出块，2100 万枚上限，减半每 4 年。
  • UTXO：见 2.3。钱包「余额」= 扫描链上属于你地址的所有未花费输出之和。
  • 脚本（Script）：类 Forth 的逆波兰栈语言。P2PKH（传统）、P2SH、P2WPKH（隔离见证 Bech32，主流）、Taproot (P2TR, Schnorr 签名)。
  • 手续费：按交易体积（vByte）计费，非按金额；矿工按 sat/vB 竞价。
  • PSBT (BIP174)：部分签名比特币交易——多签钱包、冷热分离签名的事实标准，钱包开发必学。

3.2 钱包开发

主力库：bitcoinjs-lib（JS，配合 bip39 / bip32 / tiny-secp256k1）、python-bitcoinlib / bit（Python）、rust-bitcoin（Rust）。测试网用 testnet3/4，区块浏览器 mempool.space（支持测试网），水龙头 coinfaucet.eu。

// npm i bitcoinjs-lib bip39 @scure/bip32 @scure/btc-signer
import * as bip39 from 'bip39';
import { HDKey } from '@scure/bip32';
import { bitcoin } from '@scure/btc-signer';

// 1. 助记词 → 种子 → 主密钥
const mnemonic = bip39.generateMnemonic(128);          // 12 词
const seed = await bip39.mnemonicToSeed(mnemonic);
const hd = HDKey.fromMasterSeed(seed);

// 2. 原生隔离见证路径派生首个地址
const path = "m/84'/0'/0'/0/0";
const child = hd.derive(path);
const address = bitcoin.getAddress(child.publicKey);   // bc1q...

④ Ethereum (ETH) EVM · Solidity · DeFi 主战场

4.1 基础概念

  • 账户：EOA（外部账户，私钥控制）vs 合约账户（代码控制）。地址 = 公钥 Keccak-256 取后 20 字节。
  • Gas：每步 EVM 操作码消耗 Gas；EIP-1559 后费用 = base fee（销毁）+ priority fee（小费）。钱包需实现费率估算与 Gas 上限。
  • 交易防重放：nonce（每账户递增）+ 链 ID（EIP-155）。
  • ERC 标准：ERC-20（同质化代币）、ERC-721/1155（NFT）、ERC-4337（账户抽象）、EIP-712（结构化签名）。
  • 签名：ECDSA (r,s,v)，v 用于恢复公钥（ecrecover）。

4.2 钱包开发

工具链：ethers.js v6 / viem（前端 + Node）、wagmi + RainbowKit/ConnectKit（钱包连接）、Foundry/Hardhat（合约）、Remix（浏览器 IDE，零配置入门）。L2 生态（Arbitrum/Base/Optimism）EVM 等价，同一套代码多链复用。

// npm i ethers
// —— 一套助记词派生 ETH + 签名转账 ——
import { Wallet, HDNodeWallet, Mnemonic } from 'ethers';

const mnemonic = Mnemonic.fromPhrase('your twelve words ...');
const wallet = HDNodeWallet.fromMnemonic(mnemonic, "m/44'/60'/0'/0/0");

console.log(wallet.address);            // 0x...
console.log(await wallet.signMessage('hello'));  // EIP-191 个人签名

// 连接网络并发送转账（测试网 Sepolia，水龙头 faucets.chain.link）
const provider = new ethers.JsonRpcProvider('https://rpc.sepolia.org');
const signer = wallet.connect(provider);
const tx = await signer.sendTransaction({
  to: '0xRecipient...',
  value: ethers.parseEther('0.01'),
});
console.log(tx.hash);                   // etherscan.io/sepolia/tx/...

⑤ Solana (SOL) 高性能 · Rust · Anchor

5.1 基础概念

  • 共识：PoH（历史证明，为交易全局排序提供时钟）+ PoS（Tower BFT），400ms 级出块，高吞吐低费用。
  • 一切皆账户（Account）：程序（无状态、可升级）与数据账户分离；数据账户要付 Rent（押金，关闭可取回）。
  • PDA（Program Derived Address）：程序签名派生地址——程序控制的「账户」，Solana 版「合约存储 + 权限」核心概念，必须吃透。
  • 交易：由多条指令（Instruction）组成，原子执行；签名用 ed25519；地址 = Base58 公钥。
  • SPL Token：SOL 的代币标准（对应 ERC-20），代币账户体系（Mint / Token Account / ATA）。

5.2 钱包开发

SDK：@solana/web3.js（v1 稳定版生态最全；v2 重构为模块化 @solana/kit）；前端连接用 @solana/wallet-adapter（Phantom/Solflare/Backpack）；浏览器零安装开发用 Solana Playground (solpg.io)。

// npm i @solana/web3.js @solana/spl-token
// —— 助记词派生 + 查余额 + 转账 ——
import { Connection, Keypair, LAMPORTS_PER_SOL, sendAndConfirmTransaction,
         SystemProgram, Transaction, PublicKey } from '@solana/web3.js';

const connection = new Connection('https://api.devnet.solana.com');
const from = Keypair.generate();              // ed25519，浏览器钱包中通常不落盘私钥
await connection.requestAirdrop(from.publicKey, 2 * LAMPORTS_PER_SOL);

const tx = new Transaction().add(
  SystemProgram.transfer({
    fromPubkey: from.publicKey,
    toPubkey: new PublicKey('收款方Base58地址'),
    lamports: 0.1 * LAMPORTS_PER_SOL,
  })
);
await sendAndConfirmTransaction(connection, tx, [from]);  // devnet 确认秒级

⑥ TRON EVM 系 · USDT 最大流通链

6.1 基础概念

  • 架构：DPoS（27 个超级代表轮流出块），3 秒出块，TVM 兼容 EVM（Solidity 直接用，多数合约仅需重编译）。
  • 地址：= 以太坊地址前加 0x41 再 Base58Check。同一 secp256k1 密钥在 ETH 与 TRON 是「同私钥不同地址表示」——支持 EVM 的多链钱包靠这一点统一派生。
  • 资源模型（TRON 特色，必须掌握）：带宽（Bandwidth，普通转账消耗）与能量（Energy，合约调用/部署消耗）。可以质押 TRX 获得资源，或燃烧 TRX 抵扣——做 USDT 交易钱包、量化工具的核心成本知识。
  • TRC-20：TRON 版 ERC-20。TRON 上流通着最多的 USDT（万亿级市值），是该链钱包/支付开发的第一需求场景。

⑦ Sui Move · 对象模型 · 并行执行

7.1 基础概念

  • 对象模型：一切资产都是对象（唯一 ID、属主、版本）。独占对象（Owned）交易可并行执行无需全局共识，共享对象（Shared）才走拜占庭共识——这是 Sui 高吞吐的根源。
  • Move 语言：源自 Diem 的资源导向语言。线性类型系统让「资产只能被拥有一次、不能凭空复制或意外销毁」，静态防止重入与双花级别 bug。
  • PTB（可编程交易块）：一个交易块内编排最多 1024 个操作（Move 调用、转账、拆合币），原子执行——链上可组合性的独特形态。
  • Move 对象能力：has key / store / copy / drop 能力标注决定对象行为；TreasuryCap 模式管理代币铸造权限。
  • zkLogin：用 Web2 账号（Google/Apple）零助记词登录链上账户——Sui 钱包体验的差异化卖点，钱包开发必看。
  • 共识：Mysticeti DAG 共识，亚秒级终局。

7.2 钱包开发

SDK：@mysten/sui（TS SDK，含钱包 Client）、@mysten/dapp-kit（React 连接钱包组件：ConnectButton / useCurrentAccount / useSignAndExecuteTransaction）；官方钱包 Slush；测试网水龙头 docs.sui.io/guides/developer/getting-started/get-coins。

// pnpm add @mysten/dapp-kit @mysten/sui
// —— dApp Kit：连接钱包并调用 Move 函数（React）——
import { ConnectButton, useCurrentAccount,
         useSignAndExecuteTransaction } from '@mysten/dapp-kit';
import { Transaction } from '@mysten/sui/transactions';

function CreateGreeting() {
  const account = useCurrentAccount();
  const { mutate: signAndExecute } = useSignAndExecuteTransaction();

  const tx = new Transaction();
  tx.moveCall({
    target: `${PACKAGE_ID}::greeting::new`,   // 调用链上 Move 函数
  });

  return (<>
    <ConnectButton />                       // 内置 Slush/Phantom 等钱包选择
    <button onClick={() => signAndExecute({ transaction: tx })}>创建</button>
  </>);
}

// sources/counter.move —— 最小 Move 包示例
module counter::counter {
    use sui::object::{Self, UID};
    use sui::transfer;
    use sui::tx_context::TxContext;

    public struct Counter has key { id: UID, value: u64 }

    public entry fun create(ctx: &mut TxContext) {
        let c = Counter { id: object::new(ctx), value: 0 };
        transfer::public_transfer(c, ctx.sender());  // 转给调用者（独占对象）
    }
    public entry fun increment(c: &mut Counter) { c.value = c.value + 1; }
}
