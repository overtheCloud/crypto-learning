ETH 篇 II：Solidity 合约语法与开发

从 Remix 5 分钟上手到 Foundry 全家桶，系统精讲 Solidity 语法、OpenZeppelin 标准与 5 个可编译合约，并覆盖测试、部署、升级与安全。主要参考：Solidity 官方文档 docs.soliditylang.org（含中文版）、Cyfrin Updraft、CryptoZombies。

本章目标：
  • 搭好本地合约开发环境（Remix / Foundry / Hardhat）并跑通编译与测试
  • 掌握 Solidity 全部核心语法：类型、数据位置、可见性、可变性、错误处理、继承、库
  • 会用 OpenZeppelin 标准实现 ERC20/721/1155 与权限/安全修饰器
  • 独立写出 5 个完整合约（含重点的 x*y=k AMM）
  • 理解升级模式、gas 优化与常见安全漏洞并能在测试中复现攻防

1. 开发环境：Remix 与 Foundry 全家桶

1.1 Remix 浏览器 IDE（5 分钟上手）

Remix（remix.ethereum.org）是零安装的网页 IDE，内置编译器与 JS VM 本地链，最适合快速验证想法：

  1. 左侧 File Explorer 新建 contracts/MyToken.sol。
  2. 切到 Solidity Compiler，选择编译器版本（如 0.8.24），点 Compile。
  3. 切到 Deploy & Run，环境选 JavaScript VM (Cancun)，点 Deploy。
  4. 在下方合约面板调用函数，直接在内存链看到状态变化与事件。
建议：Remix 适合学习与演示，但无法做复杂测试与 CI。严肃项目请用 Foundry。

2. 语法系统精讲（一）：编译头、值类型与数据位置

2.1 pragma 与 SPDX

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Hello {
    // ^0.8.24 表示兼容 0.8.24 及以上但低于 0.9.0
}

SPDX 注释声明许可证（部分工具会警告缺失）；pragma 锁定编译器版本，避免用错版本导致意外行为。

2.2 值类型

类型说明最小示例
uint / int无符号/有符号整数，宽度 8~256（默认 uint256）uint256 a = 1;
address20 字节地址，address payable 可收转账address owner = msg.sender;
bytes32定长字节，适合哈希bytes32 h = keccak256("x");
bool布尔bool ok = true;
枚举 enum自定义离散值enum State { Created, Active }
pragma solidity ^0.8.24;

contract Types {
    uint256 public count;
    address public owner;
    bytes32 public hash;
    bool public flag;

    enum Status { Pending, Shipped, Done }
    Status public status;

    function demo() external {
        count = type(uint256).max;     // 最大值
        owner = msg.sender;
        hash = keccak256(abi.encodePacked("hi"));
        flag = true;
        status = Status.Shipped;
    }
}

2.3 storage / memory / calldata 三者的坑

位置生命周期可改？成本用途
storage持久（上链）可最贵状态变量
memory函数调用期可中函数内临时结构
calldata调用期只读不可最省external 参数（尤字节数组）
pragma solidity ^0.8.24;

contract Locations {
    struct User { uint256 id; string name; }
    User[] public users;             // users 在 storage

    // calldata：外部传入的字节数组，不能修改，最省 gas
    function add(string calldata name) external {
        User memory u = User(users.length, name); // memory 临时
        users.push(u);                              // 写入 storage
    }

    // 返回 memory 副本（只读场景推荐 calldata 参数）
    function get(uint256 i) external view returns (User memory) {
        return users[i];
    }
}
坑：① 数组/结构体作为参数，external 函数优先用 calldata（省 gas 且不拷贝）；② 函数内想改 storage 数组元素，要声明 User storage u = users[i]; 而非 memory，否则只改了副本；③ memory 与 storage 不能混用引用。

3. 语法系统精讲（二）：可见性、可变性、修饰器与特殊函数

3.1 函数可见性

可见性谁能调用
external仅外部（合约外）；内部调用需 this.f()
public内外部均可
internal本合约及子类
private仅本合约（不代表链上不可见！）
pragma solidity ^0.8.24;

contract Vis {
    uint256 private secret;            // 仅本合约可读写
    function externalFn() external {}  // 外部调用
    function publicFn() public {}      // 内外部
    function internalFn() internal {}  // 子类可用
    function callThem() public {
        publicFn();
        internalFn();
        // this.externalFn(); // 也可通过 this 调 external
    }
}

3.2 状态可变性

修饰含义
view读状态但不改（不耗 Gas 当被外部调用读）
pure既不读也不改状态
payable可接收 ETH
pragma solidity ^0.8.24;

contract Mut {
    uint256 x;
    function readX() external view returns (uint256) { return x; }
    function pureFn(uint256 a, uint256 b) external pure returns (uint256) { return a + b; }
    function deposit() external payable { x += msg.value; } // 收 ETH
}

3.3 modifier 与 constructor

pragma solidity ^0.8.24;

contract Owned {
    address public owner;
    constructor() { owner = msg.sender; }       // 部署时执行一次

    modifier onlyOwner() {                       // 自定义修饰器
        require(msg.sender == owner, "not owner");
        _;                                       // 插入被修饰函数体
    }

    function setOwner(address o) external onlyOwner {
        owner = o;
    }
}

3.4 receive 与 fallback

合约收 ETH 有两个特殊函数：receive() external payable 处理「无 calldata 的纯转账」；fallback() external payable 处理「函数不存在或带数据」的调用。没有这两者，合约收到纯 ETH 会 revert。

pragma solidity ^0.8.24;

contract Sink {
    event Received(address from, uint256 amount);
    receive() external payable { emit Received(msg.sender, msg.value); }
    fallback() external payable {}
    function balance() external view returns (uint256) { return address(this).balance; }
}

4. 语法系统精讲（三）：错误处理、事件与数据结构

4.1 require / revert / assert 与 custom error

方式用途Gas 对比
require(cond, "msg")输入/状态校验，条件假则回滚字符串较长时贵
revert CustomError(...)自定义错误，省 Gas、信息结构化最省
assert(cond)不应发生的内部不变式，失败表示有 bug失败时消耗所有 Gas
pragma solidity ^0.8.24;

// 自定义错误：编码后比字符串短得多，省 gas
error InsufficientBalance(uint256 have, uint256 need);

contract Err {
    mapping(address => uint256) public bal;
    function withdraw(uint256 amt) external {
        if (bal[msg.sender] < amt) revert InsufficientBalance(bal[msg.sender], amt); // 推荐
        require(amt > 0, "amount must > 0");  // 传统写法
        bal[msg.sender] -= amt;
        (bool ok, ) = msg.sender.call{value: amt}("");
        assert(ok);                            // 内部不变式
    }
}

4.2 事件 event 与 indexed

pragma solidity ^0.8.24;

contract Ev {
    event Transfer(address indexed from, address indexed to, uint256 value); // 前两个可过滤
    function emitIt() external {
        emit Transfer(msg.sender, address(0), 100);
    }
}
用法：indexed 参数（最多 3 个）进入 topics，可被前端/合约精确订阅；非 indexed 进入 data，需用 ABI 解码。事件不是给链上逻辑用的，是给「外部世界」听的（见上篇事件监听）。

4.3 mapping 与数组（遍历陷阱）

pragma solidity ^0.8.24;

contract Maps {
    mapping(address => uint256) public balances;   // 无长度概念，不能 for 遍历
    address[] public holders;                       // 数组可遍历

    function credit() external {
        balances[msg.sender] += 1;
        holders.push(msg.sender);
    }
    function totalHolders() external view returns (uint256) { return holders.length; }
}
陷阱：mapping 没有「全部 key 列表」，无法用 for 遍历所有余额；要么额外维护一个数组（如上），要么在链下用事件/Graph 重建。直接 for (k in mapping) 不可行。

4.4 结构体 struct

pragma solidity ^0.8.24;

contract Structs {
    struct Order { address maker; uint256 amount; bool filled; }
    Order[] public orders;
    function create(uint256 amt) external {
        orders.push(Order(msg.sender, amt, false));
    }
}

5. 语法系统精讲（四）：继承、接口、库与低级调用

5.1 继承（is、virtual/override、C3 线性化）

pragma solidity ^0.8.24;

contract Base {
    function foo() public virtual returns (string memory) { return "base"; }
}
contract A is Base {
    function foo() public virtual override returns (string memory) { return "A"; }
}
contract B is Base {
    function foo() public virtual override returns (string memory) { return "B"; }
}
// 多重继承按 C3 线性化：最派生在最右，base 在左
contract C is A, B {
    function foo() public override(A, B) returns (string memory) { return "C"; }
}
C3 线性化：多重继承时调用顺序由「子类优先于父类、声明顺序从左到右」决定，确保菱形继承不会重复初始化。写 override(A, B) 列出所有被覆盖的父。

5.2 接口 interface

pragma solidity ^0.8.24;

interface IERC20 {
    function transfer(address to, uint256 amt) external returns (bool);
    function balanceOf(address who) external view returns (uint256);
}

contract Spender {
    function use(IERC20 token, address to, uint256 amt) external {
        require(token.transfer(to, amt), "transfer failed"); // 调用任意 ERC20
    }
}

5.3 库 library 与 using for

pragma solidity ^0.8.24;

library Math {
    function double(uint256 a) internal pure returns (uint256) { return a * 2; }
}

contract UseLib {
    using Math for uint256;       // 把库函数挂到类型上
    function go() external pure returns (uint256) {
        return 21.double();       // 等价于 Math.double(21)
    }
}

5.4 ABI encode/decode 与低级调用

pragma solidity ^0.8.24;

contract Low {
    // 编码：把参数按 ABI 拼成字节
    function enc(uint256 a, address b) external pure returns (bytes memory) {
        return abi.encode(a, b);
    }
    function encPacked(uint256 a, string memory s) external pure returns (bytes memory) {
        return abi.encodePacked(a, s); // 紧密打包，省空间
    }
    function dec(bytes memory data) external pure returns (uint256 a, address b) {
        (a, b) = abi.decode(data, (uint256, address));
    }

    // 低级调用：手动构造 calldata 并 call 另一合约
    function rawCall(address target, bytes memory data) external payable returns (bool ok, bytes memory ret) {
        (ok, ret) = target.call{value: msg.value}(data);
    }
}
call / delegatecall 风险：call 在目标合约上下文执行（msg.sender 变本合约，storage 是目标的）；delegatecall 则在本合约上下文执行目标代码（storage 是自己的）——代理升级正是利用 delegatecall 把逻辑委托给实现合约，但因此极易造成「存储布局冲突」（见 13 节）。staticcall 则禁止改状态，用于只读调用。

7. 合约①：ERC20 代币

完整可编译，含权限 mint/burn：

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import {Ownable} from "@openzeppelin/contracts/access/Ownable.sol";

/// @title 教学用 ERC20：带权限的增发与销毁
contract MyToken is ERC20, Ownable {
    constructor(uint256 initialSupply) ERC20("My Tutorial Token", "MTT") Ownable(msg.sender) {
        // 部署者初始增发 initialSupply（带 18 位精度）
        _mint(msg.sender, initialSupply * 10 ** decimals());
    }

    /// @notice 仅所有者可增发
    function mint(address to, uint256 amount) external onlyOwner {
        _mint(to, amount);
    }

    /// @notice 任意持有者销毁自己的代币
    function burn(uint256 amount) external {
        _burn(msg.sender, amount);
    }
}
逐段讲解：① is ERC20, Ownable 多重继承标准实现；② 构造函数把名称/符号传给 ERC20，并把 owner 设为部署者（0.8.20+ 的 Ownable 需显式传 msg.sender，不再默认）；③ _mint 是 OZ 内部函数，绕过 allowance 直接铸；④ onlyOwner 把关 mint；⑤ burn 不限 owner，因为烧的是调用者自己的币。

8. 合约②：ERC721 NFT

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {ERC721} from "@openzeppelin/contracts/token/ERC721/ERC721.sol";
import {Ownable} from "@openzeppelin/contracts/access/Ownable.sol";

/// @title 教学用 NFT：每个 id 对应一个链下 metadata URI
contract MyNFT is ERC721, Ownable {
    uint256 public nextId;
    string public baseURI;          // 如 "https://api.x.com/meta/"

    constructor(string memory uri) ERC721("Tutorial NFT", "TNFT") Ownable(msg.sender) {
        baseURI = uri;
    }

    /// @notice 增发一个 NFT 给 to
    function mint(address to) external onlyOwner returns (uint256) {
        uint256 id = nextId;
        _safeMint(to, id);          // OZ 安全铸造（会检查 recipient 可收）
        nextId++;
        return id;
    }

    /// @notice 返回某 id 的 metadata 链接（OpenSea 等会来读）
    function tokenURI(uint256 id) public view override returns (string memory) {
        require(id < nextId, "nonexistent");
        return string(abi.encodePacked(baseURI, _toString(id), ".json"));
    }

    function _toString(uint256 v) internal pure returns (string memory) {
        if (v == 0) return "0";
        uint256 digits;
        for (uint256 t = v; t > 0; t /= 10) digits++;
        bytes memory buf = new bytes(digits);
        for (uint256 i = digits; i > 0; i--) { buf[i-1] = bytes1(uint8(48 + v % 10)); v /= 10; }
        return string(buf);
    }
}
metadata 规范：tokenURI 指向的 JSON 应包含 name/image/description/attributes，image 通常是 ipfs:// 链接。铸造后 OpenSea 等市场会自动抓取展示。

9. 合约③：众筹合约

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title 目标制众筹：达标放款给受益人，未达标可退款
contract CrowdFund {
    address public immutable beneficiary;
    uint256 public immutable goal;
    uint256 public immutable deadline;
    mapping(address => uint256) public pledged;
    uint256 public total;
    bool public claimed;

    constructor(address _beneficiary, uint256 _goal, uint256 _duration) {
        beneficiary = _beneficiary;
        goal = _goal;
        deadline = block.timestamp + _duration;
    }

    function contribute() external payable {
        require(block.timestamp < deadline, "ended");
        pledged[msg.sender] += msg.value;
        total += msg.value;
    }

    function claim() external {
        require(msg.sender == beneficiary, "not beneficiary");
        require(block.timestamp >= deadline, "not ended");
        require(total >= goal, "goal not met");
        require(!claimed, "claimed");
        claimed = true;
        (bool ok, ) = beneficiary.call{value: total}("");
        require(ok, "transfer failed");
    }

    function refund() external {
        require(block.timestamp >= deadline, "not ended");
        require(total < goal, "goal met");
        uint256 amt = pledged[msg.sender];
        require(amt > 0, "nothing");
        pledged[msg.sender] = 0;       // CEI：先清零再转账，防重入
        (bool ok, ) = msg.sender.call{value: amt}("");
        require(ok, "transfer failed");
    }
}
关键设计：退款采用 Checks-Effects-Interactions——先把 pledged[msg.sender]=0（Effects）再 call（Interaction），即便被重入也因余额已清而无法二次取走。这也是下一篇安全模式强调的核心。

10. 合约④：2-of-3 多签钱包

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title 2-of-3 多签：任意 2 个 owner 确认后执行转账
contract MultiSig2of3 {
    address[3] public owners;
    uint256 public constant REQUIRED = 2;
    uint256 public nonce;

    struct Tx { address to; uint256 value; bytes data; bool executed; }
    mapping(uint256 => Tx) public txs;
    mapping(uint256 => mapping(address => bool)) public confirmed;

    event Submitted(uint256 id);
    event Confirmed(uint256 id, address by);
    event Executed(uint256 id);

    constructor(address[3] memory _owners) {
        owners = _owners;
    }

    modifier onlyOwner() {
        bool ok = false;
        for (uint256 i = 0; i < 3; i++) if (owners[i] == msg.sender) ok = true;
        require(ok, "not owner");
        _;
    }

    function submit(address to, uint256 value, bytes calldata data) external onlyOwner returns (uint256 id) {
        id = nonce++;
        txs[id] = Tx(to, value, data, false);
        emit Submitted(id);
    }

    function confirm(uint256 id) external onlyOwner {
        require(!txs[id].executed, "executed");
        require(!confirmed[id][msg.sender], "confirmed");
        confirmed[id][msg.sender] = true;
        emit Confirmed(id, msg.sender);

        uint256 c;
        for (uint256 i = 0; i < 3; i++) if (confirmed[id][owners[i]]) c++;
        if (c >= REQUIRED) _execute(id);
    }

    function _execute(uint256 id) internal {
        Tx storage t = txs[id];
        t.executed = true;
        (bool ok, ) = t.to.call{value: t.value}(t.data);
        require(ok, "exec failed");
        emit Executed(id);
    }
}
讲解：submit 提出一笔待执行交易（含任意 data，可调用合约）；每位 owner 调 confirm 投票；当确认数达 2 自动执行。nonce 保证每笔提案唯一，避免重放替换。

11. 合约⑤：最小 AMM（x*y=k，重点）

自动做市商（AMM）是 DeFi 的核心。这里实现一个最小但完整可编译的恒定乘积做市商：

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// @title 最小 AMM：恒定乘积 x*y=k，含 0.3% 手续费
contract MiniAMM {
    address public token;           // 配对资产（另一种为 ETH）
    uint256 public reserveToken;    // 合约内 token 储备
    uint256 public reserveEth;      // 合约内 ETH 储备
    uint256 public totalLp;         // LP 总份额
    mapping(address => uint256) public lpOf;

    uint256 constant FEE_BPS = 30;  // 0.3% = 30/10000
    uint256 constant BPS = 10000;

    constructor(address _token) { token = _token; }

    // ---- 流动性 ----
    function addLiquidity(uint256 tokenAmt) external payable returns (uint256 lp) {
        if (totalLp == 0) {
            lp = address(this).balance;            // 首笔以 ETH 量为份额基准
        } else {
            // 按当前比例注入，保持 k 不变
            uint256 ethAmt = msg.value;
            uint256 needToken = reserveToken * ethAmt / reserveEth;
            require(tokenAmt >= needToken, "token short");
            lp = totalLp * ethAmt / reserveEth;
        }
        _safeTransferFrom(token, msg.sender, address(this), tokenAmt);
        reserveToken += tokenAmt;
        reserveEth += msg.value;
        lpOf[msg.sender] += lp;
        totalLp += lp;
    }

    function removeLiquidity(uint256 lp) external returns (uint256 ethOut, uint256 tokenOut) {
        require(lpOf[msg.sender] >= lp, "no lp");
        ethOut = reserveEth * lp / totalLp;
        tokenOut = reserveToken * lp / totalLp;
        lpOf[msg.sender] -= lp;
        totalLp -= lp;
        reserveEth -= ethOut;
        reserveToken -= tokenOut;
        _safeTransfer(token, msg.sender, tokenOut);
        (bool ok, ) = msg.sender.call{value: ethOut}("");
        require(ok, "eth out failed");
    }

    // ---- 交易 ----
    function swapExactEthForToken() external payable returns (uint256 tokenOut) {
        uint256 ethIn = msg.value;
        // 扣除手续费后的有效输入
        uint256 ethInAfter = ethIn * (BPS - FEE_BPS) / BPS;
        uint256 newEth = reserveEth + ethInAfter;
        // x*y=k => 新 token 储备 = k / newEth；输出 = 原储备 - 新储备
        uint256 newToken = reserveEth * reserveToken / newEth; // 注：用 k/reserveEth
        tokenOut = reserveToken - newToken;
        require(tokenOut > 0, "no out");
        reserveEth = newEth;
        reserveToken = newToken;
        _safeTransfer(token, msg.sender, tokenOut);
        emit Swap(msg.sender, ethIn, 0, 0, tokenOut);
    }

    function swapExactTokenForEth(uint256 tokenIn) external returns (uint256 ethOut) {
        uint256 tokenInAfter = tokenIn * (BPS - FEE_BPS) / BPS;
        uint256 newToken = reserveToken + tokenInAfter;
        uint256 newEth = reserveToken * reserveEth / newToken;
        ethOut = reserveEth - newEth;
        require(ethOut > 0, "no out");
        _safeTransferFrom(token, msg.sender, address(this), tokenIn);
        reserveToken = newToken;
        reserveEth = newEth;
        (bool ok, ) = msg.sender.call{value: ethOut}("");
        require(ok, "eth out failed");
        emit Swap(msg.sender, 0, tokenIn, ethOut, 0);
    }

    function getAmountOut(uint256 amountIn, uint256 reserveIn, uint256 reserveOut)
        public pure returns (uint256)
    {
        uint256 inAfter = amountIn * (BPS - FEE_BPS) / BPS;
        return reserveOut - reserveIn * reserveOut / (reserveIn + inAfter);
    }

    event Swap(address indexed who, uint256 ethIn, uint256 tokenIn, uint256 ethOut, uint256 tokenOut);

    // ---- ERC20 内部安全封装 ----
    function _safeTransfer(address t, address to, uint256 amt) internal {
        (bool ok, bytes memory d) = t.call(abi.encodeWithSignature("transfer(address,uint256)", to, amt));
        require(ok && (d.length == 0 || abi.decode(d, (bool))), "transfer failed");
    }
    function _safeTransferFrom(address t, address from, address to, uint256 amt) internal {
        (bool ok, bytes memory d) = t.call(abi.encodeWithSignature("transferFrom(address,address,uint256)", from, to, amt));
        require(ok && (d.length == 0 || abi.decode(d, (bool))), "transferFrom failed");
    }
}
逐段讲解：① 核心不变量是 reserveEth * reserveToken 在扣费后保持恒定（此处用 ethInAfter 计入手续费，等价于 Uniswap V2 的 (x+dx')(y-dy)=k）；② addLiquidity 首笔以 ETH 量为份额基准，后续按现有比例注入防套利；③ getAmountOut 是通用兑换公式，与 swapExactTokenForEth 逻辑一致，可单独测试；④ 用底层 call 封装 ERC20 转账并对返回值做兜底（兼容不返回 bool 的老代币），等价于 OZ 的 SafeERC20；⑤ swap 函数先更新储备再发币（Effects 在 Interaction 前），但本合约不持有外部状态，重点是 math 正确。

13. 升级模式、gas 优化与安全模式

13.1 升级模式：透明代理 vs UUPS

合约默认不可变。要「升级逻辑」，采用代理模式：用户始终与代理合约交互，代理用 delegatecall 把调用转发给实现合约；升级=换掉实现地址，存储仍在代理里。

模式升级函数位置特点
透明代理 Transparent在代理合约管理员与用户调用路由不同，安全但代理较大
UUPS在实现合约代理极小、gas 低；升级逻辑需写进实现，老实现无升级函数则永久锁死
// 最小 UUPS 实现（示意，生产用 OZ 的 UUPSUpgradeable）
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {UUPSUpgradeable} from "@openzeppelin/contracts-upgradeable/proxy/utils/UUPSUpgradeable.sol";
import {OwnableUpgradeable} from "@openzeppelin/contracts-upgradeable/access/OwnableUpgradeable.sol";

contract Box is Initializable, OwnableUpgradeable, UUPSUpgradeable {
    uint256 public value;
    function initialize() public initializer {
        __Ownable_init(msg.sender);
        __UUPSUpgradeable_init();
    }
    function setValue(uint256 v) external onlyOwner { value = v; }
    // 升级权限：仅 owner
    function _authorizeUpgrade(address) internal override onlyOwner {}
}
存储冲突陷阱：delegatecall 用代理的存储布局。若实现合约新增状态变量插在中间，会与代理原有布局错位，覆盖数据。规则：① 升级时只在末尾追加新变量；② 绝不要改已有变量类型/顺序；③ 用 OZ upgradeable 系列（变量声明顺序固定）。这是代理升级头号事故源。

13.3 安全模式：CEI、重入、tx.origin、approve、闪电贷

① Checks-Effects-Interactions：先校验、再改本合约状态、最后才做外部调用（如转账），从根本上杜绝重入。

// 重入攻击演示：下面写法危险（先转账后改状态）
function unsafeWithdraw(uint256 amt) external {
    (bool ok, ) = msg.sender.call{value: amt}(""); // 外部调用先发生
    require(ok);
    balance[msg.sender] -= amt;                       // 攻击者可在此被回调再次 withdraw
}

// 修复：先改状态再转账 + ReentrancyGuard
function safeWithdraw(uint256 amt) external nonReentrant {
    require(balance[msg.sender] >= amt, "low");
    balance[msg.sender] -= amt;   // Effects 先完成
    (bool ok, ) = msg.sender.call{value: amt}("");
    require(ok);
}

② tx.origin 钓鱼：不要用 tx.origin 做权限判断——它是最初发起者，攻击合约可中转调用你的合约从而绕过。改用 msg.sender。

function bad() external { require(tx.origin == owner); ... }   // 危险：可被中间合约绕过
function good() external { require(msg.sender == owner); ... } // 正确

③ approve 无限授权风险：ERC20 的 approve(spender, type(uint256).max) 虽方便，但一旦 spender 合约有漏洞，攻击者能转走你全部余额。建议：按需授权、用 permit（EIP-2612）一次性授权、定期用 revoke.cash 收回。

④ 闪电贷攻击面：闪电贷让攻击者在「一笔交易内」借到巨额资金，用于操纵预言机、拉高价格后砸盘等。防御：用 TWAP/Chainlink 等抗操纵喂价、设交易额/滑点限制。
