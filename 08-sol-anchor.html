SOL 篇 II：Rust 原生程序与 Anchor 合约开发

用 Rust 写 Solana 程序，再用 Anchor 框架把"账户校验 / PDA / CPI / 序列化"全部自动化。主要参考：Anchor Book anchor-lang.com/docs、Paulx Escrow 教程 paulx.dev、Solana 官方课程。

本章目标：
  1. 掌握 Solana 开发者必需的 Rust 最小知识（所有权、生命周期、Result/？）；
  2. 搭建 rustup + Solana CLI + AVM + anchor 的本地开发环境；
  3. 理解原生程序的写法，知道 Anchor 帮你省掉了哪些脏活；
  4. 熟用 Anchor 的 #[program] / Context / #[derive(Accounts)] 与各类约束；
  5. 完整实现 Counter、Token 金库、Escrow 三个递进程序，并了解部署与安全。
本章目录
1. Rust 速通（面向 Solana 开发者） 2. 环境安装与 anchor init 结构 3. 原生程序开发（理解原理） 4. Anchor 精讲：账户、约束与 CPI 5. 实战①：Counter（PDA 存储） 6. 实战②：Token 金库 Vault 7. 实战③：Escrow 托管交易（核心） 8. 部署：build / deploy / upgrade / verify 9. 常见安全漏洞与正确写法

1. Rust 速通（面向 Solana 开发者）

Solana 程序用 Rust（也支持 C/C++、Move 等，但生态主流是 Rust）编写并编译成 BPF 字节码。你不需要成为 Rust 专家，但必须理解下面这些"卡住 90% 新手"的概念。

1.1 所有权、借用与生命周期

Rust 的核心规则：

  • 每个值有唯一所有者（owner）；所有者离开作用域，值被释放；
  • 你可以借出不可变引用 &T（多份并存）或可变引用 &mut T（同一时刻仅一份）；
  • 生命周期保证引用不会比它指向的数据活得更久。
// 不可变借用：多个 & 可以共存
fn read(data: &Vec<u8>) -> u8 {
    data[0]
}

// 可变借用：&mut 独占
fn write(data: &mut Vec<u8>, v: u8) {
    data.push(v);
}

fn main() {
    let mut buf = Vec::new();
    write(&mut buf, 1);
    let first = read(&buf); // 不可变借用，OK
    println!("{}", first);
}
Solana 关联：Anchor 里 Context<'info, T> 的 'info 就是一个生命周期参数，它约束"所有账户引用的存活期不超过本次调用"。你写 Anchor 时基本不用手写生命周期，但看到 <'info, ...> 要知道它是什么。

1.2 struct / enum / impl

// 结构体
struct Counter { count: u64 }

// 枚举（常用于错误码、状态机）
enum State { Open, Closed }

// 为类型实现方法（类似 class 的方法）
impl Counter {
    fn new() -> Self { Self { count: 0 } }
    fn inc(&mut self) { self.count += 1; } // &mut self 借用自身可变
}

1.3 Result / Option 与 ? 操作符

Solana 程序绝不能 panic（会让整笔交易失败且仍扣费）。Rust 用 Result<T, E> 表示"可能出错"，用 ? 提前返回错误——Anchor 会将其转成程序错误码。

// Result<T, E>：Ok(T) 或 Err(E)
fn divide(a: u64, b: u64) -> Result<u64, String> {
    if b == 0 { return Err("除零".to_string()); }
    Ok(a / b)
}

// ? 把 Err 直接向上抛出；这里是链式传播
fn calc() -> Result<u64, String> {
    let x = divide(10, 2)?; // 若出错，直接 return Err
    let y = divide(x, 0)?; // 这行会触发错误
    Ok(y)
}

// Option<T>：Some(T) 或 None（表示"可能为空"）
let maybe: Option<u64> = Some(5);
if let Some(v) = maybe { println!("{}", v); }

1.4 trait 与 derive

trait 类似接口；derive 让编译器自动生成常见实现（如序列化、Debug、Clone）。Anchor 大量使用 derive 宏。

// derive 自动生成 Debug / Clone 能力
#[derive(Debug, Clone)]
struct Point { x: i32, y: i32 }

// trait：定义共享行为
trait Greet { fn hello(&self) -> String; }
impl Greet for Point {
    fn hello(&self) -> String { format!("({}, {})", self.x, self.y) }
}

3. 原生程序开发（理解原理）

在看 Anchor 之前，先理解"没有框架时你要做什么"。下面是一个手写原生程序的最小例子：把指令数据第一个字节存进账户。

use solana_program::{
    account_info::{next_account_info, AccountInfo},
    entrypoint,
    entrypoint::ProgramResult,
    msg,
    pubkey::Pubkey,
    program_error::ProgramError,
};

// entrypoint! 宏声明程序入口
entrypoint!(process_instruction);

fn process_instruction(
    program_id: &Pubkey,
    accounts: &[AccountInfo],
    instruction_data: &[u8],
) -> ProgramResult {
    // 1) 手动迭代账户列表
    let accounts_iter = &mut accounts.iter();
    let account = next_account_info(accounts_iter)?;

    // 2) 手动校验账户 owner 是否是本程序
    if account.owner != program_id {
        return Err(ProgramError::IncorrectProgramId);
    }

    // 3) 手动借出可变数据并写入
    let mut data = account.try_borrow_mut_data()?;
    data[0] = instruction_data[0];
    msg!("存好了: {}", data[0]);
    Ok(())
}

你看到的每一个手写步骤，Anchor 都自动帮你做了：

手写动作Anchor 如何代劳
迭代并取账户Context<'info, T> 按名字结构化取出
校验 owner账户类型 Account<'info, T> 自带 owner 检查
反序列化数据#[account] 自动 Borsh 序列化/反序列化
校验签名者/可写约束 mut / Signer
校验 PDA seeds约束 seeds = [...], bump
为什么要懂原生：当 Anchor 报出"账户约束不满足"等错时，你必须知道背后它检查了什么，才能快速定位。理解原生，等于理解了 Anchor 的"底层契约"。

4. Anchor 精讲：账户、约束与 CPI

4.1 程序入口声明

use anchor_lang::prelude::*;

// declare_id! 声明本程序的地址（部署后由 Anchor 写入，需与链上一致）
declare_id!("Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS");

#[program]
pub mod my_program {
    use super::*;

    // 每个 pub fn 就是一条"指令"，参数 ctx 是账户上下文，其余是入参
    pub fn hello(ctx: Context<Hello>, value: u64) -> Result<()> {
        msg!("hello {}", value);
        Ok(())
    }
}

4.2 Context 与 #[derive(Accounts)]

Context<'info, T> 装着你这条指令要用到的所有账户，定义在同名结构体里：

#[derive(Accounts)]
pub struct Hello<'info> {
    #[account(mut)]
    pub user: Signer<'info>,       // 签名者，必须签名
    pub system_program: Program<'info, System>, // 引用的程序
}

4.3 约束属性逐个讲

约束作用
init新建账户，自动从 payer 扣免租押金；需配合 payer 与 space
payer = x指定谁出 SOL 押金
space = N账户数据区大小（字节）
mut该账户在指令中会被修改（运行时据此标记 writable）
seeds = [...], bump声明这是 PDA，Anchor 校验地址 = seeds+bump 推导
has_one = field校验账户内某字段等于另一账户公钥（如 owner 匹配）
constraint = expr任意布尔表达式，不满足则报错
close = dest指令结束时关闭账户，押金退给 dest

4.4 Signer / Account / AccountInfo / UncheckedAccount

  • Signer<'info>：必须是交易签名者，Anchor 验证其签名。
  • Account<'info, T>：owner 必须是当前程序，且数据是类型 T 的 Borsh 反序列化结果——最安全。
  • AccountInfo<'info>：裸账户信息，需要你自己校验 owner/数据。
  • UncheckedAccount<'info>：完全不校验，仅当你确信安全时用（务必加 /// CHECK: 注释说明原因）。
安全差异：优先用 Account<'info, T>。把本应校验的账户写成 UncheckedAccount 而忘记手动校验，是严重漏洞来源（见 s9）。

4.5 anchor-spl 的 Token 类型与 CPI

与 SPL Token 交互时用 anchor_spl 提供的包装类型（Mint、TokenAccount、Token、AssociatedToken）。CPI 跨程序调用两种方式：

use anchor_spl::token::{self, Token, TokenAccount, Mint, Transfer};

// 方式 A：调用 anchor_spl 封装好的 CPI（内部帮你拼账户 + invoke）
let cpi_accounts = Transfer {
    from: ctx.accounts.src.to_account_info(),
    to: ctx.accounts.dst.to_account_info(),
    authority: ctx.accounts.user.to_account_info(),
};
let cpi_ctx = CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi_accounts);
token::transfer(cpi_ctx, amount)?;

// 方式 B：PDA 作为 authority 时，用带签名的 CPI
let seeds = &[b"vault".as_ref(), &[bump]];
let signer = &[&seeds[..]];
let cpi_ctx_signed = CpiContext::new_with_signer(
    ctx.accounts.token_program.to_account_info(),
    cpi_accounts,
    signer, // 告诉运行时：用这个 PDA seeds 代签
);
token::transfer(cpi_ctx_signed, amount)?;

4.6 错误码、事件与 space 计算

// 自定义错误码（? 抛出的 Err 会被映射成它）
#[error_code]
pub enum MyError {
    #[msg("数量必须为正")]
    InvalidAmount,
    #[msg("调用者不是 owner")]
    Unauthorized,
}

// 事件：链上可索引的日志
#[event]
pub struct Trade { pub maker: Pubkey, pub amount: u64 }
emit!(Trade { maker: ctx.accounts.user.key(), amount });

// space 计算规则：8 字节 discriminator（Anchor 自动加）+ 各字段
// u64=8, Pubkey=32, bool=1, u8=1
// 推荐用 InitSpace 宏自动算：
#[account]
#[derive(InitSpace)]
pub struct Vault { pub owner: Pubkey, pub amount: u64, pub active: bool }
// 总 space = 8 + 32 + 8 + 1 = 49

5. 实战①：Counter（PDA 存储）

最经典的入门：一个全局计数器，存在 PDA 里，任何人可自增。

use anchor_lang::prelude::*;

declare_id!("Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS");

#[program]
pub mod counter {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        ctx.accounts.counter.count = 0;
        Ok(())
    }

    pub fn increment(ctx: Context<Update>) -> Result<()> {
        let counter = &mut ctx.accounts.counter;
        // checked_add 防止 u64 溢出（安全写法）
        counter.count = counter.count.checked_add(1).unwrap();
        Ok(())
    }
}

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(init, payer = user, space = 8 + 8)]
    pub counter: Account<'info, Counter>,
    #[account(mut)]
    pub user: Signer<'info>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct Update<'info> {
    #[account(mut)]
    pub counter: Account<'info, Counter>,
}

#[account]
pub struct Counter {
    pub count: u64, // 8 字节
}

讲解：counter 账户由 init 创建，user 付押金；space = 8 + 8 中第一个 8 是 discriminator，第二个 8 是 u64 count。客户端调用时无需知道 PDA 细节，Anchor 客户端会自动用 program_id + 空 seeds 推导地址。

5.1 配套 TS 测试（片段）

import * as anchor from "@coral-xyz/anchor";
import { Program } from "@coral-xyz/anchor";

describe("counter", () => {
  const provider = anchor.AnchorProvider.env();
  anchor.setProvider(provider);
  const program = anchor.workspace.Counter as Program;

  it("init + increment", async () => {
    const counter = anchor.web3.Keypair.generate();
    await program.methods.initialize().accounts({ counter: counter.publicKey, user: provider.wallet.publicKey, systemProgram: anchor.web3.SystemProgram.programId }).signers([counter]).rpc();

    await program.methods.increment().accounts({ counter: counter.publicKey }).rpc();

});

6. 实战②：Token 金库 Vault

用户把 SPL Token 存入由 PDA 控制的金库 ATA，再可取回。重点：PDA 作为 ATA 的 authority，用 new_with_signer 代签放行。

use anchor_lang::prelude::*;
use anchor_spl::token::{self, Token, TokenAccount, Mint, Transfer};
use anchor_spl::associated_token::AssociatedToken;

declare_id!("Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS");

#[program]
pub mod vault {
    use super::*;

    pub fn deposit(ctx: Context<Deposit>, amount: u64) -> Result<()> {
        let cpi = Transfer {
            from: ctx.accounts.user_ata.to_account_info(),
            to: ctx.accounts.vault_ata.to_account_info(),
            authority: ctx.accounts.user.to_account_info(),
        };
        token::transfer(CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi), amount)?;
        Ok(())
    }

    pub fn withdraw(ctx: Context<Withdraw>, amount: u64) -> Result<()> {
        // PDA 签名：seeds=[b"vault", user] + bump
        let bump = ctx.bumps.vault;
        let seeds = &[b"vault".as_ref(), ctx.accounts.user.key().as_ref(), &[bump]];
        let signer = &[&seeds[..]];
        let cpi = Transfer {
            from: ctx.accounts.vault_ata.to_account_info(),
            to: ctx.accounts.user_ata.to_account_info(),
            authority: ctx.accounts.vault.to_account_info(),
        };
        token::transfer(CpiContext::new_with_signer(ctx.accounts.token_program.to_account_info(), cpi, signer), amount)?;
        Ok(())
    }
}

#[derive(Accounts)]
pub struct Deposit<'info> {
    #[account(mut)]
    pub user: Signer<'info>,
    pub mint: Account<'info, Mint>,
    #[account(mut)]
    pub user_ata: Account<'info, TokenAccount>,
    #[account(
        init_if_needed, payer = user,
        associated_token::mint = mint,
        associated_token::authority = vault
    )]
    pub vault_ata: Account<'info, TokenAccount>,
    #[account(seeds = [b"vault".as_ref(), user.key().as_ref()], bump)]
    /// CHECK: PDA 作为 vault ATA 的 authority，地址由 seeds 保证
    pub vault: UncheckedAccount<'info>,
    pub token_program: Program<'info, Token>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct Withdraw<'info> {
    #[account(mut)]
    pub user: Signer<'info>,
    pub mint: Account<'info, Mint>,
    #[account(mut)]
    pub user_ata: Account<'info, TokenAccount>,
    #[account(mut, associated_token::mint = mint, associated_token::authority = vault)]
    pub vault_ata: Account<'info, TokenAccount>,
    #[account(seeds = [b"vault".as_ref(), user.key().as_ref()], bump)]
    /// CHECK: PDA authority
    pub vault: UncheckedAccount<'info>,
    pub token_program: Program<'info, Token>
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}
init_if_needed：首次存款时顺手创建 ATA，后续存款直接复用。注意 associated_token::authority = vault 让金库 PDA 成为该 ATA 的主人，普通用户无法直接动它——这正是"托管"的安全前提。

7. 实战③：Escrow 托管交易（核心）

这是本篇核心：maker 想把 A 代币换成 taker 的 B 代币。流程：

  • make：maker 创建 escrow 状态账户 + 一个由 PDA 拥有的 vault ATA，并把 A 代币锁进去；
  • take：taker 把 B 代币付给 maker，vault 把 A 代币放给 taker，最后关闭 vault 与 escrow，押金退回。

完整 lib.rs：

use anchor_lang::prelude::*;
use anchor_spl::token::{self, Mint, Token, TokenAccount, Transfer};
use anchor_spl::associated_token::AssociatedToken;

declare_id!("EscarowX1111111111111111111111111111111111");

#[program]
pub mod escrow {
    use super::*;

    pub fn make(
        ctx: Context<Make>,
        seed: u64,
        deposit_amount: u64,
        receive_amount: u64,
    ) -> Result<()> {
        // 写入 escrow 状态
        ctx.accounts.escrow.set_inner(Escrow {
            maker: ctx.accounts.maker.key(),
            mint_a: ctx.accounts.mint_a.key(),
            mint_b: ctx.accounts.mint_b.key(),
            receive_amount,
            seed,
            bump: ctx.bumps.escrow,
        });

        // 把 maker 的 A 代币转入 vault（PDA 拥有的 ATA）
        let cpi = Transfer {
            from: ctx.accounts.maker_ata_a.to_account_info(),
            to: ctx.accounts.vault.to_account_info(),
            authority: ctx.accounts.maker.to_account_info(),
        };
        token::transfer(CpiContext::new(ctx.accounts.token_program.to_account_info(), cpi), deposit_amount)?;
        Ok(())
    }

    pub fn take(ctx: Context<Take>) -> Result<()> {
        // 1) taker 付 B 给 maker
        let pay_b = Transfer {
            from: ctx.accounts.taker_ata_b.to_account_info(),
            to: ctx.accounts.maker_ata_b.to_account_info(),
            authority: ctx.accounts.taker.to_account_info(),
        };
        token::transfer(CpiContext::new(ctx.accounts.token_program.to_account_info(), pay_b), ctx.accounts.escrow.receive_amount)?;

        // 2) vault 把 A 给 taker，PDA 代签
        let bump = ctx.accounts.escrow.bump;
        let seeds = &[b"escrow".as_ref(), ctx.accounts.maker.key().as_ref(), &ctx.accounts.escrow.seed.to_le_bytes(), &[bump]];
        let signer = &[&seeds[..]];
        let give_a = Transfer {
            from: ctx.accounts.vault.to_account_info(),
            to: ctx.accounts.taker_ata_a.to_account_info(),
            authority: ctx.accounts.vault.to_account_info(),
        };
        token::transfer(CpiContext::new_with_signer(ctx.accounts.token_program.to_account_info(), give_a, signer), ctx.accounts.vault.amount)?;

        // 3) 关闭 vault ATA，押金退 maker
        let close_acc = anchor_spl::token::CloseAccount {
            account: ctx.accounts.vault.to_account_info(),
            destination: ctx.accounts.maker.to_account_info(),
            authority: ctx.accounts.vault.to_account_info(),
        };
        anchor_spl::token::close_account(CpiContext::new_with_signer(ctx.accounts.token_program.to_account_info(), close_acc, signer))?;
        Ok(())
    }

    pub fn refund(ctx: Context<Refund>) -> Result<()> {
        // 把 vault 的 A 退回 maker，并关闭 escrow（押金退 maker）
        let bump = ctx.accounts.escrow.bump;
        let seeds = &[b"escrow".as_ref(), ctx.accounts.maker.key().as_ref(), &ctx.accounts.escrow.seed.to_le_bytes(), &[bump]];
        let signer = &[&seeds[..]];
        let give_back = Transfer {
            from: ctx.accounts.vault.to_account_info(),
            to: ctx.accounts.maker_ata_a.to_account_info(),
            authority: ctx.accounts.vault.to_account_info(),
        };
        token::transfer(CpiContext::new_with_signer(ctx.accounts.token_program.to_account_info(), give_back, signer), ctx.accounts.vault.amount)?;
        let close_acc = anchor_spl::token::CloseAccount {
            account: ctx.accounts.vault.to_account_info(),
            destination: ctx.accounts.maker.to_account_info(),
            authority: ctx.accounts.vault.to_account_info(),
        };
        anchor_spl::token::close_account(CpiContext::new_with_signer(ctx.accounts.token_program.to_account_info(), close_acc, signer))?;
        Ok(())
    }
}

import * as anchor from "@coral-xyz/anchor";
import { Program, BN } from "@coral-xyz/anchor";
import { PublicKey, Keypair } from "@solana/web3.js";
import {
  TOKEN_PROGRAM_ID, ASSOCIATED_TOKEN_PROGRAM_ID,
  createMint, mintTo, getAssociatedTokenAddressSync, getAccount,
} from "@solana/spl-token";

describe("escrow", () => {
  const provider = anchor.AnchorProvider.env();
  anchor.setProvider(provider);
  const program = anchor.workspace.Escrow as Program;
  const maker = Keypair.generate();
  const taker = Keypair.generate();

  let mintA: PublicKey, mintB: PublicKey;
  let makerAtaA: PublicKey, makerAtaB: PublicKey;
  let takerAtaA: PublicKey, takerAtaB: PublicKey;

  const seed = new BN(42);
  const depositAmount = new BN(1000);
  const receiveAmount = new BN(500);

  before(async () => {
    // 给 maker/taker 转 SOL 当手续费
    const sig1 = await provider.connection.requestAirdrop(maker.publicKey, 2_000_000_000);
    await provider.connection.confirmTransaction(sig1);
    const sig2 = await provider.connection.requestAirdrop(taker.publicKey, 2_000_000_000);
    await provider.connection.confirmTransaction(sig2);

    mintA = await createMint(provider.connection, provider.wallet.payer, maker.publicKey, null, 6);
    mintB = await createMint(provider.connection, provider.wallet.payer, taker.publicKey, null, 6);

    makerAtaA = await getAta(maker.publicKey, mintA, maker);
    makerAtaB = await getAta(maker.publicKey, mintB, maker);
    takerAtaA = await getAta(taker.publicKey, mintA, taker);
    takerAtaB = await getAta(taker.publicKey, mintB, taker);

    await mintTo(provider.connection, provider.wallet.payer, mintA, makerAtaA, maker, 1000);
    await mintTo(provider.connection, provider.wallet.payer, mintB, takerAtaB, taker, 500);
  });

  async function getAta(owner: PublicKey, mint: PublicKey, payer: Keypair) {
    const ata = getAssociatedTokenAddressSync(mint, owner);
    // 省略创建 ATA 的代码（用 createAssociatedTokenAccount）
    return ata;
  }

  it("make: 锁 A 进 vault", async () => {
    const [escrowPda] = PublicKey.findProgramAddressSync(
      [Buffer.from("escrow"), maker.publicKey.toBuffer(), seed.toArrayLike(Buffer, "le", 8)],
      program.programId
    );
    await program.methods
      .make(seed, depositAmount, receiveAmount)
      .accountsPartial({
        maker: maker.publicKey,
        mintA, mintB,
        escrow: escrowPda,
        makerAtaA,
        // vault / vaultAuth 由 Anchor 自动推导
      })
      .signers([maker])
      .rpc();
    console.log("escrow 已创建:", escrowPda.toBase58());
  });

  it("take: taker 付 B、取走 A、关账户", async () => {
    const [escrowPda] = PublicKey.findProgramAddressSync(
      [Buffer.from("escrow"), maker.publicKey.toBuffer(), seed.toArrayLike(Buffer, "le", 8)],
      program.programId
    );
    await program.methods
      .take()
      .accountsPartial({ taker: taker.publicKey, maker: maker.publicKey, mintA, mintB, escrow: escrowPda, takerAtaA, takerAtaB, makerAtaB })
      .signers([taker])
      .rpc();

    const takerBalA = (await getAccount(provider.connection, takerAtaA)).amount;
    console.log("taker 拿到 A:", takerBalA.toString()); // 1000
  });
});

# 编译（生成 so + IDL + TS 类型）
anchor build

# 把程序部署到当前 cluster（Anchor.toml 里配置的 devnet）
anchor deploy

# 部署后把生成的 program id 写回 declare_id! 与 Anchor.toml，再 build 一次确保一致
# 之后跑测试
anchor test

# 升级已部署程序（字节码替换，地址不变）
anchor upgrade target/deploy/my_escrow.so --program-id <PROGRAM_ID>

# 程序验证：证明链上字节码与开源源码一致（信任最小化）
anchor verify <PROGRAM_ID>
# 或 solana-verify：
solana-verify verify-from-repo <git 仓库> <PROGRAM_ID>
升级 vs 不可变：默认部署的程序是可升级的（由 upgrade authority 控制）。若要不可变，部署后执行 solana program set-upgrade-authority <PROGRAM_ID> --final 放弃升级权限。用户应优先与"已验证且不可变"的程序交互。

9. 常见安全漏洞与正确写法

9.1 缺 signer 检查

错误：把敏感操作账户写成 Account 而非 Signer，任何人都能调用。

// ❌ 错误：没有 Signer 约束，任意账户都能当 user 转走资金
pub struct Bad<'info> { pub user: AccountInfo<'info>, pub vault: Account<'info, Vault> }

// ✅ 正确：必须是签名者
pub struct Good<'info> { #[account(mut)] pub user: Signer<'info>, pub vault: Account<'info, Vault> }

9.2 账户 owner 未校验

错误：用 UncheckedAccount 接收本应是某个程序的账户，却没验 owner。

// ❌ 错误：拿到 token_account 但没验证它是 Token Program 拥有的 ATA
#[account(mut)] pub token_account: UncheckedAccount<'info>

// ✅ 正确：用 Account<'info, TokenAccount>，Anchor 自动校验 owner == Token Program
#[account(mut)] pub token_account: Account<'info, TokenAccount>

9.3 PDA seeds 可预测被抢

错误：用可被用户操控的 seeds 推导 PDA，攻击者抢先创建同名账户并植入恶意数据。

// ❌ 错误：seeds 含用户随意传入的 pubkey，攻击者可抢注
seeds = [user_supplied_key.as_ref()], bump

// ✅ 正确：seeds 至少含 program 自身或不可伪造的上下文
seeds = [b"vault".as_ref(), maker.key().as_ref()], bump

9.4 任意 CPI 账户替换

错误：CPI 时直接信任调用方传入的 token_program，攻击者换成假程序。

// ❌ 错误：token_program 由用户传，可能被替换成恶意程序
// ✅ 正确：硬编码校验
#[account(address = token::ID)]
pub token_program: Program<'info, Token>,

9.5 重初始化攻击

错误：init 的账户没加唯一性约束，攻击者重复调用把状态重置。

// ❌ 错误：没有把关键字段放进 seeds，导致可重复 init
#[account(init, payer = user, space = 8 + 32)] pub escrow: Account<'info, Escrow>

// ✅ 正确：用 maker + seed 作为唯一 seeds，重复创建会因"账户已存在"而失败
#[account(init, payer = user, space = 8 + Escrow::INIT_SPACE, seeds = [b"escrow".as_ref(), maker.key().as_ref(), &seed.to_le_bytes()], bump)]
pub escrow: Account<'info, Escrow>,
审计清单：每次写指令前自问——谁必须签名？哪个账户 owner 必须校验？PDA seeds 攻击者能否抢注？CPI 程序地址是否硬编码？重复调用是否会被重置？这五条能挡住绝大多数 Solana 合约漏洞。
