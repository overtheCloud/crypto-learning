1. DeFi 乐高与可组合性

DeFi（去中心化金融）不是单个应用，而是一组开放、可互操作的货币积木。核心特征是可组合性（Composability）：一个协议能直接调用另一个协议，像乐高一样拼接。

为什么能拼：所有协议都是公开的智能合约，输入输出是标准化的（ERC20 代币、统一接口）。一笔交易内可以「在 Aave 抵押 ETH 借出 DAI → 到 Uniswap 把 DAI 换成 ETH → 把 ETH 存进 Lido 拿 stETH」，全程无需信任任何中介，且原子化（任一步失败整体回滚）。

1.1 可组合性代码直觉

「乐高」在代码层面就是「拿到一个合约地址 + 它的接口，直接调用」。下面用 ethers 演示如何在一份脚本里串联多个协议（伪流程，真实需先 approve）：

// 01-legos.js
// 可组合性直觉：同一 wallet 连续调用不同协议，像拼积木
import { ethers } from "ethers";
import "dotenv/config";

const provider = new ethers.JsonRpcProvider("http://127.0.0.1:8545"); // fork
const wallet = new ethers.Wallet(process.env.MNEMONIC, provider);

const aave = new ethers.Contract(AAVE_POOL, [
  "function supply(address,uint256,address,uint16) external",
], wallet);
const uniswap = new ethers.Contract(ROUTER, [
  "function swapExactTokensForTokens(uint,uint,address[],address,uint) external returns (uint[])",
], wallet);
const lido = new ethers.Contract(STETH, ["function submit(address) external payable"], wallet);

// 积木 1：Aave 抵押 WETH
await aave.supply(WETH, parseEther("1"), wallet.address, 0);
// 积木 2：Uniswap 用借来的 DAI 换 WETH（需先 borrow + approve）
await uniswap.swapExactTokensForTokens(usdcAmt, minOut, [USDC, WETH], wallet.address, deadline);
// 积木 3：Lido 把 ETH 质押换 stETH
await lido.submit(wallet.address, { value: parseEther("0.5") });

// 以上三步若放在同一个合约函数里顺序执行，即「原子可组合」；
// 用 JS 顺序发送则是多笔独立交易（任一步失败不会自动回滚前面的）。
原子 vs 非原子：真正的「乐高」威力在于把多步放进同一笔交易（一个合约函数内顺序 call），任一步 revert 整体回滚，没有中间态风险。用 ethers 逐笔发是「分步组合」，适合演示，但生产套利/清算必须合约内原子化。

积木层代表提供能力
资产层ERC20/ERC721、USDC、stETH可组合的价值载体
交易层Uniswap、Curve、1inch兑换流动性
借贷层Aave、Compound抵押借贷、生息
预言机层Chainlink、Uniswap TWAP链下价格上链
收益/衍生品层Lido、Yearn、GMX质押/杠杆/策略

2. AMM 数学推导：x*y=k、滑点与无常损失

2.1 恒定乘积 x*y=k

传统交易所有订单簿，AMM 用公式定价。Uniswap V2 的核心不变量：

reserve_token_x * reserve_token_y = k   (恒定)

买入 dy 数量的 Y，需注入 dx 数量的 X：
(x + dx)(y - dy) = k = x*y
=> dy = y * dx / (x + dx)            // 不考虑手续费
含 0.3% 手续费（30/10000）：
dx' = dx * 9970 / 10000
dy = y * dx' / (x + dx')

价格由储备比定义：price = y / x（用 X 计价的 Y 价格）。每笔交易都会沿曲线移动价格点，天然产生「 slippage（滑点）」——你买得越多，实际成交价越差。

2.2 价格滑点公式

// 给定输入 dx（X 资产），输出 dy（Y 资产）
function getAmountOut(uint dx, uint x, uint y) pure returns (uint dy) {
    uint dxAfter = dx * 997;          // 0.3% 费
    dy = y * dxAfter / (1000 * x + dxAfter);
}

// 滑点 = (理想价 - 实际成交价) / 理想价
// 理想价 = y/x（无限小交易量）
// 实际成交价 = dy / dx（含费、含深度影响）

2.2.1 数值示例：大单滑点有多痛

设储备 x=1000 ETH、y=2,000,000 USDC（即市价 2000 USDC/ETH）。若一次卖出 100 ETH：

// 用上面的 getAmountOut 计算
x = 1000e18, y = 2000000e6, dx = 100e18
dxAfter = 100e18 * 997 / 1000 = 99.7e18
dy = 2000000e6 * 99.7e18 / (1000e18 * 1000 + 99.7e18)
   = 199400000e24 / (1000997e18)         ≈ 199,201e6  // 约 199,201 USDC

理想无费收入 = 100 * 2000 = 200,000 USDC
实得         = 199,201 USDC
滑点损耗     ≈ 799 USDC（约 0.4%）
实际成交价   = 199201 / 100 ≈ 1992 USDC/ETH（比市价低 0.4%）

可见：交易量占池子比例越大，滑点越显著。这也是为什么大额兑换要走聚合器拆单或V3 集中流动性深区间来摊薄冲击。

价格冲击 vs 手续费：上面 0.4% 里大部分来自「x*y=k 曲线移动」（价格冲击），仅 0.3% 是协议费。深度越浅，价格冲击占比越高。做 DEX 交互时，amountOutMin 应基于「含冲击的理论输出」再打折，而非基于市价。

2.3 无常损失（Impermanent Loss）数值示例

LP 提供双边流动性，当价格偏离初始比例时会比「单纯持有」亏一些。设初始 x=y=100，价格 1；若价格变为 4（Y 更贵）：

情形X 储备Y 储备组合价值
初始（价=1）100100200
只持有（价=4）100×4 + 100 = 500—500
做 LP（k=10000，价=4 ⇒ x=50,y=200）50×4=200200400

LP 价值 400 < 持有 500，差额 100 即无常损失（约 20%）。「无常」指若价格回到原点，损失消失——但只要撤出时偏离，损失就实锤。手续费收益是对冲 IL 的补偿。

直觉：AMM 自动「低卖高买」——价格涨时 Y 被换走（你少了上涨资产），跌时 X 变多。波动越大 IL 越大，故稳定币对（波动小）的 LP 更受欢迎。

3. Uniswap V2 架构与 V3/V4 简介

3.1 V2：Factory / Pair / Router / LP

组件职责
Factory按两种代币创建唯一 Pair 合约（地址确定性）
Pair持有双边储备，实现 x*y=k，发 LP token 记录份额
Router用户入口，计算路径（A→B→C）、收授权、执行 swap 并校验最小输出
LP tokenERC20，代表在 Pair 中的流动性份额，可转让/质押
// V2 核心不变量（Pair 合约内伪代码）
uint balance0 = IERC20(token0).balanceOf(address(this));
uint balance1 = IERC20(token1).balanceOf(address(this));
uint amount0In = balance0 - reserve0;   // 本次转入的 token0
uint amount1In = balance1 - reserve1;
// 扣除 0.3% 费后满足 k 不减
require((balance0 - amount0In/1000*3) * (balance1 - amount1In/1000*3) >= reserve0*reserve1);

3.2 V3 集中流动性与 V4 hooks

版本关键创新影响
V2全区间 x*y=k资金利用率低
V3集中流动性：LP 只在区间 [Pa,Pb] 内提供流动性，用 tick 划分价格刻度资本效率高，但需主动管理；头寸是 NFT（非同质）
V4hooks：在 swap 前后插入自定义合约逻辑（费率动态、限价单、TWAMM）极大可定制，单例 Factory 省 gas
tick 是什么：V3 把价格轴按 1.0001^t 的几何刻度切成离散 tick，LP 选定 [tickLower, tickUpper] 区间。只有当前价格落在区间内才参与做市，越窄区间单位资本深度越大、手续费越高，但越易被划出区间而暂时不赚费。

3.3 V3 tick 数值示例

价格与 tick 的关系为 price = 1.0001^tick。几个刻度对照：

tick价格（USDC/ETH）含义
01.0000基准
69,314≈ 2000对应市价 2000（ln(2000)/ln(1.0001) ≈ 69314）
69,314 ± 1000≈ 2000 × 1.0001^±1000约 ±10% 区间
// 计算某价格对应的 tick（与 V3 内部一致，向下取整）
function priceToTick(uint priceX96) pure returns (int24 tick) {
    // 简化：用对数   tick = floor(log(price) / log(1.0001))
    // 实际 V3 用 Q64.96 定点，这里仅示意数值关系
    // price = 1.0001 ** tick  =>  tick = ln(price) / ln(1.0001)
}
// 直觉：市价 2000 附近，tick 约 69314。
// 若 LP 只提供 [68314, 70314]（±约 2%），则价格在此 ±2% 内
// 这段极窄区间的资本效率远高于 V2 全区间；但价格一旦冲出，
// 该头寸全部变为单一资产（不再赚费），需手动再平衡。
选区间的权衡：窄区间 = 高手续费收益但需频繁再平衡（gas 成本+被划出风险）；宽区间 = 被动但收益低。被动型 LP 常选宽区间（如 ±50%~±100%），主动型做市商用窄区间追求高 APR。

4. 借贷协议：Aave V3 与 Compound

4.1 利率模型（利用率拐点曲线）

借贷利率随利用率 U = 借出总额 / 存款总额变化。为鼓励健康，采用「拐点（kink）」模型：U 低于拐点时平缓上升，超过拐点后陡升，迫使借款人还款以恢复 liquidity。

// 简化利率模型（Aave/Compound 思路一致）
function borrowRate(uint U) pure returns (uint) {
    uint kink = 80;                    // 80% 拐点
    if (U <= kink) {
        return baseRate + U * slope1;  // 平缓段
    } else {
        return baseRate + kink * slope1 + (U - kink) * slope2; // 陡升段(slope2>>slope1)
    }
}

4.2 aToken / cToken 计息

协议计息代币机制
Aave V3aToken（aUSDC）余额随时间按指数增长，1 aUSDC 始终可赎回 > 1 USDC
CompoundcToken（cUSDC）兑换率 exchangeRate 随时间上升，c 数量不变但价值增

4.3 健康因子与清算流程

健康因子 HF = (抵押品价值 * 清算阈值) / 债务价值
- HF > 1：安全
- HF < 1：可被清算

清算人操作：
1) 替借款人偿还一部分债务（获得折扣价的抵押品作为奖励，如 5% bonus）
2) 协议把对应抵押品转给清算人
清算人收益 = 清算奖励 -  gas/价差成本
风险：当抵押品价格暴跌（或债务币种暴涨），HF 跌破 1 即被清算，且清算往往发生在行情最差时，是借贷用户最大风险点。务必留足缓冲、关注预言机延迟。

4.3.1 数值示例：抵押率与安全垫

假设你存入价值 15,000 USDC 的 ETH（清算阈值 80%），借出 6,000 USDC：

抵押品价值   = 15000 USDC
清算阈值     = 80%  => 可借上限 = 15000 * 0.8 = 12000 USDC
当前债务     = 6000 USDC
HF = (15000 * 0.8) / 6000 = 12000 / 6000 = 2.0     // 安全

若 ETH 跌 30%：抵押品变 15000 * 0.7 = 10500
HF = (10500 * 0.8) / 6000 = 8400 / 6000 = 1.4      // 仍安全

若 ETH 跌 50%：抵押品变 7500
HF = (7500 * 0.8) / 6000 = 6000 / 6000 = 1.0      // 临界，随时被清算
// 所以即便 HF=2 起步，单抵押 50% 跌幅也会清零，必须留更大缓冲或分散抵押。
经验值：普通用户保持 HF ≥ 1.5（即抵押率远高于借款），并把单抵押品的潜在跌幅控制在「缓冲内」。用 Aave 的 getUserAccountData 实时监控 HF，写个告警 bot 比事后补救更稳。

5. 稳定币三范式对照

范式代表锚定机制风险
法币托管USDC、USDT链下法币 1:1 储备（审计托管）中心化冻结、储备透明度
超额抵押DAI链上加密资产超额抵押（如 150% 的 ETH）抵押品暴跌需清算
算法（无抵押）UST（已崩）算法供需调节 + 铸烧毁锚死亡螺旋，# 脱锚归零
UST 教训：2022 年 Terra/UST 靠「质押赚高息吸引需求、抛压时用销毁 UST 铸 LUNA 接盘」维持锚定。一旦信心崩塌，LUNA 无限增发致价格崩塌，UST 彻底脱锚归零——证明无储备的算法稳定币在极端行情下缺乏支撑。这是 DeFi 史上最重要的反面教材。

6. 预言机：Chainlink 与 TWAP

6.1 Chainlink 聚合喂价

Chainlink 由多个独立节点对价格「投票取中位数」，写入链上聚合器合约。读取只需一次调用：

// 取 ETH/USD 最新轮次（见实战④）
(roundId, answer, startedAt, updatedAt, answeredInRound) = aggregator.latestRoundData();
// answer 是带 8 位小数的整数，如 3000e8 表示 $3000

6.2 Uniswap TWAP（时间加权平均价）

TWAP 用一段时间内的累积价（价格×时间）求平均，抗「瞬时插针」操纵，但响应慢。适合「不太需要实时、但要抗操纵」的场景。

6.3 操纵攻击案例

典型攻击：某借贷协议用「单一 Uniswap V2 现货价」做抵押品估值。攻击者先用闪电贷拉高该池价格（瞬间现货价虚高），以此虚高抵押品借走真实资产，再让价格回落——净赚差价。防御：用 Chainlink/TWAP、设心跳（heartbeat）过期、价格偏差上限。

7. 闪电贷、流动性质押与再质押、DEX 聚合、MEV

7.1 闪电贷原理与典型攻击

闪电贷（Aave/Uniswap/balancer 均支持）规则：同一笔交易内借出、使用、归还，否则整笔回滚。因原子性，你无需抵押即可借巨额资金做套利/清算/操纵测试。

// Aave V3 闪电贷回调（示意）
function executeOperation(address asset, uint256 amount, uint256 fee, address, bytes calldata) external returns (bool) {
    // 1) 用借来的 amount 做某事：套利 / 操纵后套利 / 自救清算
    // 2) 必须归还 amount + fee
    IERC20(asset).approve(pool, amount + fee);
    return true; // 否则交易 revert，借款当没发生
}
攻击≠非法：闪电贷本身是中性工具。被用于「先借巨资操纵预言机/拉盘再砸盘」才是攻击。防御方应加固喂价、限额。对学习者，闪电贷最适合做无本金的套利/清算演练。

7.2 Lido / stETH 与 EigenLayer 再质押

概念说明
流动性质押 Lido质押 ETH 得 stETH，stETH 随质押奖励缓慢 rebasing 增值，可继续在 DeFi 里用（如抵押借出）
再质押 EigenLayer把已质押的 ETH（或 LST）再「复用」去保护其他中间件/AVS，赚取额外收益，但叠加被罚没风险

7.3 DEX 聚合器 1inch 与 MEV

1inch 等聚合器把一笔大额兑换拆到多个池/多步路径，寻找最优成交价，减少滑点。

MEV（最大可提取价值）：验证者/搜索者通过排序交易获利：

类型机制用户影响
抢跑 Front-running看到你的大单先插队同方向你成交价变差
三明治 Sandwich你之前买入推高、你之后卖出，夹击吃价差严重滑点损失
套利 Arbitrage跨池价格差搬平中性，甚至有益
保护：用 swapExactTokensForTokens 务必设 amountOutMin（最小接收）防三明治；Flashbots / 私有内存池可把交易直接交给验证者，避开公开 mempool 被夹。理解 MEV 是设计安全 DeFi 交互的前提。

8. 实战①：读取 V2 Pair 储备与兑换输出

// 本地复刻 getAmountOut（含 0.3% 费）
function getAmountOut(amountIn, reserveIn, reserveOut) {
  const inAfter = amountIn * 997n;
  return reserveOut * inAfter / (reserveIn * 1000n + inAfter);
}
// 假设用 1e18 个 token0 换 token1
const out = getAmountOut(ethers.parseUnits("1", 18), r0, r1);
console.log("1 token0 约换得 token1:", ethers.formatUnits(out, 18));
提示：Sepolia 没有真实的 WETH/USDC 深度，练习时可在 anvil fork 主网（见 12 节）使用真实地址，或用上篇部署的 MiniAMM 类比。本文示例地址以主网为例，fork 时直接可用。

9. 实战②：approve + Router 兑换全流程

// 09-swap.js
// 完整流程：授权 Router 花费代币 → 调 swapExactTokensForTokens
import { ethers } from "ethers";
import "dotenv/config";

const provider = new ethers.JsonRpcProvider(process.env.SEPOLIA_RPC);
const wallet = new ethers.Wallet(process.env.MNEMONIC, provider);

// 主网地址示例（fork 时直接用）
const ROUTER = "0x7a250d5630B4cF539739dF2C5dAcb4c659F2488D"; // Uniswap V2 Router
const TOKEN_IN = "0x...";   // 输入代币（如 DAI）
const TOKEN_OUT = "0x...";  // 输出代币（如 WETH）

const erc20 = new ethers.Contract(TOKEN_IN, [
  "function approve(address spender, uint256 amount) external returns (bool)",
  "function allowance(address owner, address spender) external view returns (uint256)",
], wallet);

const router = new ethers.Contract(ROUTER, [
  "function swapExactTokensForTokens(uint amountIn, uint amountOutMin, address[] calldata path, address to, uint deadline) external returns (uint[] memory)",
], wallet);

const amountIn = ethers.parseUnits("100", 18); // 100 DAI
const deadline = Math.floor(Date.now() / 1000) + 60 * 20; // 20 分钟有效期

// 1) 授权 Router 花费（必要时）
const allowed = await erc20.allowance(wallet.address, ROUTER);
if (allowed < amountIn) {
  const tx = await erc20.approve(ROUTER, amountIn);
  await tx.wait();
  console.log("已授权 Router 花费", amountIn.toString());
}

// 2) 先估算最小输出（用上节 getAmountOut 逻辑，预留 0.5% 滑点缓冲）
const minOut = amountIn * 995n / 1000n; // 简化：实际应读储备计算

// 3) 兑换：DAI -> WETH
const path = [TOKEN_IN, TOKEN_OUT];
const swapTx = await router.swapExactTokensForTokens(
  amountIn,
  minOut,
  path,
  wallet.address,
  deadline,
  { maxFeePerGas: ethers.parseUnits("3", "gwei") }
);
const receipt = await swapTx.wait();
console.log("兑换完成，区块:", receipt.blockNumber, "gasUsed:", receipt.gasUsed.toString());
滑点保护：amountOutMin 是反三明治/反失败的关键。设得过低会被夹；设得过高在大波动时交易会 revert。生产应实时读储备算理论输出再打折（如 0.3%~1%），而非写死。

  "function withdraw(address asset, uint256 amount, address to) external returns (uint256)",

// 11b-multicall.js
// 用 Multicall3 合约一次 RPC 批量读多个 ERC20 余额
import { ethers } from "ethers";
import "dotenv/config";

const provider = new ethers.JsonRpcProvider(process.env.SEPOLIA_RPC);
const MULTICALL3 = "0xcA11bde05977b3631167028862bE2a173976CA11"; // 通用部署地址
const owner = "0x5aAeb6b2b3e1d8e8a1b3f3c0c0e3a7d2e0d3c9e0";

const tokens = [
  "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48", // USDC
  "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2", // WETH
  "0x6B175474E89094C44Da98b954EedeAC495271d0F", // DAI
];
const erc20Fragment = ["function balanceOf(address) external view returns (uint256)"];

const multicall = new ethers.Contract(MULTICALL3, [
  "function aggregate(tuple(address target, bytes callData)[] calls) external view returns (uint256 blockNumber, bytes[] returnData)",
], provider);

const calls = tokens.map(t => ({
  target: t,
  callData: new ethers.Interface(erc20Fragment).encodeFunctionData("balanceOf", [owner]),
}));
const [, returnData] = await multicall.aggregate(calls);
const iface = new ethers.Interface(erc20Fragment);
returnData.forEach((d, i) => {
  const bal = iface.decodeFunctionResult("balanceOf", d)[0];
  console.log(tokens[i], "余额:", bal.toString());
});
为什么用 Multicall：逐一代币 balanceOf 要 N 次 RPC 往返；Multicall 把多次只读调用打包成一笔聚合调用，省延迟与配额，是前端展示多资产余额的标准做法。

14. 综合案例：循环贷与闪电贷原子套利

本节把前面零散的协议「拼」起来，体会可组合性的威力。两个案例都在一笔交易/一次操作中完成，体现 DeFi 的原子性优势。

14.1 循环贷（Leveraged Staking / Looping）

目标：用 1 份 ETH 撬出「多份 stETH 敞口」。流程：抵押 ETH 借出稳定币 → 用稳定币买更多 ETH → 再抵押 → 再借……反复若干轮，放大本金的质押收益。风险是每次借贷都压低健康因子，行情下跌易连环清算。

// 14a-looping.js
// 循环贷示意：抵押 WETH → 借 USDC → 换成 WETH → 再抵押（重复 N 轮）
import { ethers } from "ethers";
import "dotenv/config";

const provider = new ethers.JsonRpcProvider("http://127.0.0.1:8545"); // fork 环境
const wallet = new ethers.Wallet(process.env.MNEMONIC, provider);

const AAVE_POOL = "0x87870Bca3F3fD6335C3F4ce8392D69350B4fA4E2";
const UNISWAP_ROUTER = "0x7a250d5630B4cF539739dF2C5dAcb4c659F2488D";
const WETH = "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2";
const USDC = "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48";

const pool = new ethers.Contract(AAVE_POOL, [
  "function supply(address,uint256,address,uint16) external",
  "function borrow(address,uint256,uint256,uint16,address) external",
  "function getUserAccountData(address) view returns (uint256,uint256,uint256,uint256,uint256,uint256)",
], wallet);
const router = new ethers.Contract(UNISWAP_ROUTER, [
  "function swapExactTokensForTokens(uint,uint,address[],address,uint) external returns (uint[])",
], wallet);

const LOOPS = 3; // 循环 3 轮
let amountWeth = ethers.parseUnits("1", 18); // 起始 1 WETH

for (let i = 0; i < LOOPS; i++) {
  // 1) 抵押当前 WETH
  const weth = new ethers.Contract(WETH, ["function approve(address,uint256) external returns (bool)"], wallet);
  await (await weth.approve(AAVE_POOL, amountWeth)).wait();
  await (await pool.supply(WETH, amountWeth, wallet.address, 0)).wait();

  // 2) 借出 60% 价值的 USDC（留缓冲，避免清算）
  const data = await pool.getUserAccountData(wallet.address);
  const borrowBase = (data.availableBorrowsBase * 60n) / 100n; // 以 USD 计
  const usdcAmt = borrowBase * 10n ** 6n / 10n ** 8n;            // 转 6 位小数
  await (await pool.borrow(USDC, usdcAmt, 2, 0, wallet.address)).wait();

  // 3) 把 USDC 换成 WETH，进入下一轮
  const usdc = new ethers.Contract(USDC, ["function approve(address,uint256) external returns (bool)"], wallet);
  await (await usdc.approve(UNISWAP_ROUTER, usdcAmt)).wait();
  const out = await router.swapExactTokensForTokens(
    usdcAmt, 0, [USDC, WETH], wallet.address, Math.floor(Date.now()/1000)+1200, { maxFeePerGas: ethers.parseUnits("3","gwei") }
  );
  const rec = await out.wait();
  // 下一轮本金 = 刚换回的 WETH（从事件/receipt 解析，此处简化为继续循环）
  amountWeth = ethers.parseUnits("0.5", 18); // 演示用定值
  console.log(`第 ${i+1} 轮完成，HF=`, ethers.formatUnits((await pool.getUserAccountData(wallet.address)).healthFactor, 18));
}
注意：循环轮数越多，杠杆越高，清算阈值越近。熊市里价格下跌会让多层抵押同时触发清算，损失被杠杆放大。务必用 fork 反复压力测试不同跌幅下的 HF。

14.2 闪电贷原子套利（无本金套利）

利用闪电贷「零抵押借巨资」，在两个池间搬平价格差，赚差价后还本付息，全程一笔交易内完成。若算错/滑点吃光利润，整笔回滚，借款当没发生。

// 14b-flash-arb.js
// 闪电贷套利骨架：借 USDC → 池 A 买便宜 WETH → 池 B 卖贵 WETH → 还 USDC
import { ethers } from "ethers";
import "dotenv/config";

const provider = new ethers.JsonRpcProvider("http://127.0.0.1:8545");
const wallet = new ethers.Wallet(process.env.MNEMONIC, provider);

const AAVE_POOL = "0x87870Bca3F3fD6335C3F4ce8392D69350B4fA4E2";
const ROUTER = "0x7a250d5630B4cF539739dF2C5dAcb4c659F2488D";
const USDC = "0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48";
const WETH = "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2";

const pool = new ethers.Contract(AAVE_POOL, [
  "function flashLoanSimple(address receiver, address asset, uint256 amount, bytes calldata params, uint16 referralCode) external",
], wallet);
const router = new ethers.Contract(ROUTER, [
  "function swapExactTokensForTokens(uint,uint,address[],address,uint) external returns (uint[])",
], wallet);

// 第一步：发起闪电贷
const borrow = ethers.parseUnits("100000", 6); // 借 10 万 USDC
await (await pool.flashLoanSimple(wallet.address, USDC, borrow, "0x", 0)).wait();
console.log("闪电贷套利已发起（实际套利逻辑在回调合约中执行）");

// 真实场景需部署一个 Receiver 合约，实现 executeOperation：
//   - 用借来的 USDC 在池 A swap 成 WETH（amountOutMin 设好防夹）
//   - 用 WETH 在池 B swap 回 USDC
//   - 计算 finalUSDC，要求 finalUSDC > borrow + fee（约 0.05%）
//   - approve Pool 花 borrow+fee，return true；否则 revert
// 详见 Aave 文档的 IFlashLoanSimpleReceiver 接口。
为什么必须合约：闪电贷的还款逻辑在回调里——Aave 把币转给你后调用你的 executeOperation，你必须在函数返回前把本金+费 approve 回 Pool。这段「借→用→还」必须在一个合约调用内完成，单纯 JS 钱包无法做到，因此要部署 Receiver 合约（可在 Remix/Foundry 写，逻辑同上）。

15. DeFi 风险总结与安全自检表

DeFi 把传统金融数月的流程压缩进「无需许可、不可篡改」的代码，收益与风险同源。下表汇总高频风险与缓解。

智能合约漏洞重入、整数溢出、权限缺失、逻辑错误审计 + 形式化验证 + bug bounty + CEI 模式

15.1 交互侧安全自检（用户/开发者）

  • 授权前：只给知名合约授权；额度用「精确值」而非 type(uint256).max；用 revoke.cash 定期清理。
  • 兑换前：总是填 amountOutMin，且基于实时储备计算（留 0.3%~1% 滑点）；通过私有 RPC 发送避免被夹。
  • 借贷前：确认 HF 远高于 1，预留至少 20%~30% 下跌空间；理解利率模式与清算阈值。
  • 存款前：确认合约已验证源码、有审计报告、TVL 健康、无异常管理权限（owner 能否抽走资金）。
  • 升级前：代理合约的 admin 是否多签/时间锁？避免「项目方一夜改逻辑卷款」。

15.2 协议侧安全自检（开发者）

  • 所有外部转账走Checks-Effects-Interactions 或加 nonReentrant。
  • 权限用 Ownable/AccessControl，关键操作加时间锁（Timelock）。
  • 价格一律走抗操纵预言机，禁止「合约内价」或单一现货池。
  • 用 require/自定义 error 显式校验，整数运算优先 Solidity 0.8+ 自带溢出检查。
  • 上线前跑 slither + Foundry invariant/fuzz + 第三方审计 + bug bounty。
  • 重要资金走多签（如 Safe）与渐进式额度上限（先小后大）。
