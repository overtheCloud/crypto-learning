TRON 篇 II：TVM 合约开发与部署

用 TronBox 编译部署 Solidity 合约，从 HelloTron 到完整 TRC-20 与图书馆 DApp，搞懂 TRON 上合约与钱包交互的全部细节。主要参考：官方 Build a Web3 App、TronBox/TronWeb 文档、tron-workshop 示例仓库。

本章目标：
  1. 搭建 TronBox 工具链，配置 tronbox-config.js 与测试网；
  2. 列出并理解 Solidity on TRON 与以太坊的关键差异；
  3. 完成 HelloTron 存储合约的 编写→编译→migrate→TronWeb 交互；
  4. 给出一个完整、可部署的 TRC-20 代币合约代码；
  5. 基于官方教程重构一个去中心化图书馆 DApp（合约 + 前端），并讲清 .call()/.send()、feeLimit、Energy 错误处理与迁移 Checklist。

1. 工具链：TronBox 总览

TronBox 是 TRON 版的 Truffle：同一套命令心智模型，编译 Solidity、部署合约、跑测试、开控制台。它是 TRON 合约开发的事实标准。

# 全局安装
npm i -g tronbox

# 初始化一个空工程（生成 contracts/ migrations/ test/ tronbox-config.js）
tronbox init

# 编译
tronbox compile

# 部署到配置的网络
tronbox migrate --network nile

# 跑测试
tronbox test

# 交互式控制台（连上节点后可直接 new 合约、调用）
tronbox console --network nile

tronbox-config.js 是核心配置，包含网络、编译器版本、优化器：

// tronbox-config.js
module.exports = {
  networks: {
    // 本地私链（tronbox 自带或 docker 私网）
    development: {
      privateKey: "你的私钥HEX",
      consume_user_resource_percent: 30, // 合约部署者承担的资源比例
      feeLimit: 100000000,               // 部署交易 feeLimit（SUN）
      fullHost: "http://127.0.0.1:9090",
      network_id: "*",
    },
    nile: {
      privateKey: process.env.NILE_PRIVATE_KEY,
      consume_user_resource_percent: 30,
      feeLimit: 100000000,
      fullHost: "https://nile.trongrid.io",
      network_id: "*",
    },
    mainnet: {
      privateKey: process.env.MAIN_PRIVATE_KEY,
      consume_user_resource_percent: 30,
      feeLimit: 200000000,
      fullHost: "https://api.trongrid.io",
      network_id: "*",
    },
  },
  compilers: {
    solc: {
      version: "0.8.16",                 // TVM 支持的稳定版本（避免过新）
      settings: {
        optimizer: { enabled: true, runs: 200 },
      },
    },
  },
  // 合约源码目录
  contracts_directory: "./contracts",
  contracts_build_directory: "./build",
};
版本注意：TVM 的 solc 支持版本滞后于以太坊官方。不要直接贴 0.8.24+ 的最新特性（如某些新 opcode、transient storage），先查 TRON 文档确认。本篇示例统一用 0.8.16（稳妥区间）。

2. 测试网 Nile 与 Shasta

TRON 有两个常用公共测试网，用途不同：

测试网RPC / fullHost特点适用
Nilehttps://nile.trongrid.io官方主推测试网，资源/生态最完整，配套 faucet 发 TRX 与测试 USDT合约开发、DApp 集成首选
Shastahttps://api.shasta.trongrid.io老牌测试网，网络较稳定但生态文档少快速验证、与老教程对齐
  • 水龙头：nileex.io 领取 Nile 测试 TRX/USDT；Shasta 在 shasta.tronscan.org 相关页面领水。
  • 浏览器：nile.tronscan.org（Nile）、shasta.tronscan.org（Shasta）。
选择建议：本篇所有示例默认 Nile。两个网络的地址体系、代码完全一致，只是网络参数与代币不同，切换只需改 fullHost 与私钥。

3. 私钥管理与 .env 规范

切勿把私钥写进代码或提交到 git。标准做法是用 .env + dotenv：

// .env（务必加入 .gitignore）
NILE_PRIVATE_KEY=你的Nile私钥HEX（纯 hex，无 0x）
MAIN_PRIVATE_KEY=你的主网私钥HEX
TRONGRID_API_KEY=你的TronGrid_API_Key（事件 API 需要）

// tronbox-config.js 顶部
require("dotenv").config();
// 之后用 process.env.NILE_PRIVATE_KEY

# .gitignore 至少包含
.env
node_modules/
build/
安全底线：测试网私钥也别和主网混用同一套；主网私钥只在本地部署机临时存在，绝不进代码仓库、不进前端 bundle、不进日志。

4. Tronscan 合约验证

部署后让外部可读源码，需在 Tronscan 做“合约验证（Verify）”。流程：

  1. 在 Tronscan 搜索你的合约地址 → 进入合约页 → “Contract” → “Verify”；
  2. 选择编译器版本（须与部署时一致）、开启/关闭优化器（须与部署时一致）；
  3. 粘贴完整源码（含 import 的文件需内联或按目录上传）；
  4. 提交后 Tronscan 重新编译并与链上 bytecode 比对，一致即验证通过，用户可在线 Read/Write。
提示：验证失败最常见原因是“优化器 runs 数不一致”或“源码未包含全部 import”。TronBox 编译产物在 build/contracts/*.json 里有 source 与 bytecode，可对照排查。

5. Solidity on TRON 差异对照表

维度以太坊TRON / TVM
编译器版本紧跟 solc 最新版本滞后，需用受支持版本（如 0.8.x 特定区间）
计费方式Gas（ETH 支付）Energy（质押或燃烧 TRX），写操作须带 feeLimit
block.timestamp 语义出块时间戳同为秒级时间戳，但受 27 个 SR 影响，不要用于强安全随机数
地址字面量0x 前缀 20 字节合约内地址仍是 20 字节，但外部表示带 0x41 前缀的 21 字节；address(0x41...) 字面量需小心
TRC-20 / ERC-20 接口ERC-20 标准接口完全一致（name/symbol/decimals/balanceOf/transfer/approve/transferFrom/Transfer/Approval），可移植
合约创建CREATE / CREATE2支持 CREATE；CREATE2 在较新 TVM 版本支持，需注意版本
预编译合约一系列 precompile部分预编译不同，跨链移植前查 TRON 预编译列表
移植结论：多数标准 ERC-20/ERC-721 合约“改个编译器版本 + 加 feeLimit”即可上 TRON；但时间敏感的随机逻辑、价格预言机、地址字面量拼接要重点回归测试。

6. 实战一：HelloTron 存储合约

最小可运行合约：存一个字符串，可读可写。对应官方 Getting Started。

① 编写合约 contracts/HelloTron.sol：

// contracts/HelloTron.sol
pragma solidity ^0.8.16;

contract HelloTron {
    string public greeting;

    event GreetingChanged(string oldGreeting, string newGreeting);

    constructor(string memory _greeting) {
        greeting = _greeting;
    }

    function setGreeting(string memory _greeting) public {
        string memory old = greeting;
        greeting = _greeting;
        emit GreetingChanged(old, _greeting);
    }

    function getGreeting() public view returns (string memory) {
        return greeting;
    }
}

② 迁移脚本 migrations/2_deploy_hello.js：

// migrations/2_deploy_hello.js
const HelloTron = artifacts.require("HelloTron");

module.exports = function (deployer) {
  deployer.deploy(HelloTron, "Hello TRON!");
};

③ 编译并部署到 Nile：

tronbox compile
tronbox migrate --network nile
# 部署成功会打印合约地址（base58）

④ 用 TronWeb 交互（前端或脚本里）：

// interact-hello.js —— .call() 只读，.send() 写链
const TronWeb = require("tronweb");
const tronWeb = new TronWeb({
  fullHost: "https://nile.trongrid.io",
  privateKey: process.env.NILE_PRIVATE_KEY,
});

async function hello() {
  const instance = await tronWeb.contract().at("T你的HelloTron地址");

  // 只读：免 Energy，用 .call()
  const g1 = await instance.greeting().call();
  console.log("当前问候:", g1);

  // 写链：用 .send()，带 feeLimit
  const tx = await instance.setGreeting("你好 TRON").send({
    feeLimit: tronWeb.toSun(30),
  });
  console.log("setGreeting txID:", tx);

  // 写后再次读取
  const g2 = await instance.greeting().call();
  console.log("更新后问候:", g2);
}
hello().catch(console.error);

7. 实战二：完整 TRC-20 代币合约

下面是可直接在 TronBox 编译部署的 TRC-20 实现（精简自 OpenZeppelin 思路，保留标准接口）。注意点：

  • 接口与 ERC-20 一致，便于钱包与交易所识别；
  • USDT 是 6 位小数，但本示例用 18 位以贴合多数 ERC-20 习惯；上线前按需改 decimals；
  • 避免 SafeMath 冗余（solc 0.8+ 自带溢出检查）。
// contracts/MyToken.sol
pragma solidity ^0.8.16;

interface ITRC20 {
    function totalSupply() external view returns (uint256);
    function balanceOf(address who) external view returns (uint256);
    function allowance(address owner, address spender) external view returns (uint256);
    function transfer(address to, uint256 value) external returns (bool);
    function approve(address spender, uint256 value) external returns (bool);
    function transferFrom(address from, address to, uint256 value) external returns (bool);
    event Transfer(address indexed from, address indexed to, uint256 value);
    event Approval(address indexed owner, address indexed spender, uint256 value);
}

contract MyToken is ITRC20 {
    string public name = "My TRON Token";
    string public symbol = "MTT";
    uint8 public decimals = 18;
    uint256 public override totalSupply;

    mapping(address => uint256) public override balanceOf;
    mapping(address => mapping(address => uint256)) public override allowance;

    address public owner;

    constructor(uint256 initialSupply) {
        owner = msg.sender;
        totalSupply = initialSupply;
        balanceOf[msg.sender] = initialSupply;
        emit Transfer(address(0), msg.sender, initialSupply);
    }

    function transfer(address to, uint256 value) public override returns (bool) {
        require(balanceOf[msg.sender] >= value, "余额不足");
        require(to != address(0), "零地址");
        balanceOf[msg.sender] -= value;
        balanceOf[to] += value;
        emit Transfer(msg.sender, to, value);
        return true;
    }

    function approve(address spender, uint256 value) public override returns (bool) {
        allowance[msg.sender][spender] = value;
        emit Approval(msg.sender, spender, value);
        return true;
    }

    function transferFrom(address from, address to, uint256 value) public override returns (bool) {
        require(balanceOf[from] >= value, "余额不足");
        require(allowance[from][msg.sender] >= value, "授权不足");
        require(to != address(0), "零地址");
        balanceOf[from] -= value;
        balanceOf[to] += value;
        allowance[from][msg.sender] -= value;
        emit Transfer(from, to, value);
        return true;
    }
}
OpenZeppelin 移植注意点：直接 import "@openzeppelin/contracts/token/ERC20/ERC20.sol" 在 TRON 上多数能编译，但要确认 OpenZeppelin 版本不依赖 TRON 不支持的特性（如特定预编译、block.chainid 等）。建议先用一个最小实现跑通，再逐步引入库。

8. 实战三：去中心化图书馆 DApp

官方 “Build a Web3 App” 教程浓缩重构：一个去中心化图书馆，任何人可上架书（缴租金），读者可租借（付 TRX），合约管理书的状态。我们给出完整合约 + 无框架前端。

8.1 Solidity 合约

// contracts/Library.sol
pragma solidity ^0.8.16;

contract Library {
    struct Book {
        uint256 id;
        string title;
        address owner;
        uint256 price;        // 租一天的价格（SUN）
        bool available;
    }

    uint256 public bookCount;
    mapping(uint256 => Book) public books;
    mapping(address => uint256[]) public borrowedBooks;

    event BookAdded(uint256 id, string title, address owner, uint256 price);
    event BookRented(uint256 id, address renter, uint256 days_);

    // 上架一本书，price 单位为 SUN/天
    function addBook(string memory _title, uint256 _price) public {
        require(bytes(_title).length > 0, "书名不能为空");
        bookCount++;
        books[bookCount] = Book(bookCount, _title, msg.sender, _price, true);
        emit BookAdded(bookCount, _title, msg.sender, _price);
    }

    // 租书：days_ 租期天数，调用时附带 TRX（callValue）
    function rentBook(uint256 _id, uint256 days_) public payable {
        Book storage b = books[_id];
        require(b.id != 0, "书不存在");
        require(b.available, "已借出");
        uint256 cost = b.price * days_;
        require(msg.value >= cost, "TRX 不足");
        b.available = false;
        borrowedBooks[msg.sender].push(_id);
        // 租金转给书主
        payable(b.owner).transfer(cost);
        emit BookRented(_id, msg.sender, days_);
    }

    function getBook(uint256 _id) public view returns (
        uint256, string memory, address, uint256, bool
    ) {
        Book memory b = books[_id];
        return (b.id, b.title, b.owner, b.price, b.available);
    }
}

8.3 前端 app.js（TronLink + TronWeb）

// app.js —— 图书馆 DApp 逻辑（浏览器内，依赖 TronLink 注入的 tronWeb）
const CONTRACT = "T你的Library合约地址";

async function connect() {
  if (!window.tronLink && !window.tron) {
    alert("请安装 TronLink"); return;
  }
  const tl = window.tronLink || window.tron;
  await tl.request({ method: "tron_requestAccounts" });
  const tw = tl.tronWeb;
  document.getElementById("status").innerText = "已连接: " + tw.defaultAddress.base58;
  return tw;
}

async function loadBooks(tw) {
  const inst = await tw.contract().at(CONTRACT);
  const count = Number(await inst.bookCount().call());
  const ul = document.getElementById("list");
  ul.innerHTML = "";
  for (let i = 1; i <= count; i++) {
    const [id, title, owner, price, avail] = await inst.getBook(i).call();
    const li = document.createElement("li");
    li.innerText = `#${id} ${title} | 日租 ${tw.fromSun(price)} TRX | ${avail ? "可租" : "已借出"} | 主:${owner}`;
    ul.appendChild(li);
  }
}

document.getElementById("connect").onclick = async () => {
  const tw = await connect();
  if (tw) loadBooks(tw);
};

document.getElementById("add").onclick = async () => {
  const tw = await connect();
  const inst = await tw.contract().at(CONTRACT);
  const title = document.getElementById("title").value;
  const priceSun = tw.toSun(Number(document.getElementById("price").value));
  const tx = await inst.addBook(title, priceSun).send({ feeLimit: tw.toSun(50) });
  alert("上架成功 txID: " + tx);
  loadBooks(tw);
};

document.getElementById("rent").onclick = async () => {
  const tw = await connect();
  const inst = await tw.contract().at(CONTRACT);
  const bid = Number(document.getElementById("bid").value);
  const days = Number(document.getElementById("days").value);
  // 先查价再算 callValue（附带 TRX）
  const [, , , price, ] = await inst.getBook(bid).call();
  const callValue = Number(price) * days;
  const tx = await inst.rentBook(bid, days).send({
    feeLimit: tw.toSun(50),
    callValue: callValue,   // 随交易附带的 TRX（SUN）
  });
  alert("租书成功 txID: " + tx);
  // 交易确认后刷新
  setTimeout(() => loadBooks(tw), 8000);
};
两个关键写法：① feeLimit 是给 Energy 燃烧的上限；② callValue 是随这笔交易附带支付的原生 TRX（单位 SUN），对应合约里的 msg.value，用于“租书付钱”。这两者在以太坊里靠 API 参数区分，在 TronWeb 里就是 send 的两个字段。

9. 合约交互进阶

9.1 .call() vs .send()

方法是否上链消耗用途
.call()否（只读，本地执行）免 Energyview/pure 查询（balanceOf、getBook 等）
.send()是（广播交易）消耗/燃烧 Energy，需 feeLimit状态变更（transfer、addBook 等）
// 只读——永远用 .call()，且不要在 .send() 里意外调用只读方法导致烧钱
const bal = await token.balanceOf(addr).call();

// 写——必须 .send() 且带 feeLimit
const tx = await token.transfer(to, amt).send({ feeLimit: tronWeb.toSun(20) });

9.2 feeLimit 估算（estimateEnergy）

上线前先估算 Energy，避免 feeLimit 设得离谱。TronWeb 可用节点 API 估算：

// 估算某次合约调用的 Energy 消耗
async function estimateEnergy(contractAddr, functionSelector, params, ownerAddr) {
  const res = await tronWeb.fullNode.request(
    "/wallet/estimateenergy",
    {
      owner_address: tronWeb.address.toHex(ownerAddr),
      contract_address: tronWeb.address.toHex(contractAddr),
      function_selector: functionSelector,   // 如 "transfer(address,uint256)"
      parameter: params,                     // 已 ABI 编码的参数 hex
    },
    "post"
  );
  // res.energy_required / energy_used 即所需 Energy
  return res;
}

9.3 Energy 不足时的错误处理与重试

async function safeSend(txPromise, feeLimitSun) {
  try {
    const tx = await txPromise.send({ feeLimit: feeLimitSun });
    const info = await waitConfirm(tx);
    if (info.receipt && info.receipt.result !== "SUCCESS") {
      throw new Error("合约执行失败: " + JSON.stringify(info.contractResult));
    }
    return tx;
  } catch (e) {
    // 常见：OUT_OF_ENERGY —— 说明 feeLimit 不足以燃烧，需提高或先质押/租 Energy
    if (/OUT_OF_ENERGY|feeLimit/.test(e.message)) {
      console.error("Energy 不足，请提高 feeLimit 或质押 Energy 后重试");
    }
    throw e;
  }
}

9.5 合约升级模式（代理）

TRON 上做可升级合约（代理模式）与以太坊思路一致：逻辑合约 + 代理合约 + 存储分离，通过 delegatecall 转发。但注意：

  • TRON 的 delegatecall 在 TVM 中可用，但协议层对代理的 storage 布局校验要回归测试；
  • 部分 OpenZeppelin 升级库依赖的特性要确认 TVM 支持；
  • 更简单的“半中心化”方案：用 owner 可替换逻辑合约地址的注册表模式（适合内部系统）。
// 极简可替换逻辑（注册表式伪代码）
contract Registry {
    address public logic;
    address public admin;
    function upgrade(address newLogic) public {
        require(msg.sender == admin, "only admin");
        logic = newLogic;
    }
    fallback() external payable {
        address l = logic;
        assembly { calldatacopy(0,0,calldatasize()) }
        // delegatecall 到 logic，存储留在代理
    }
}
TRON 代理注意点：delegatecall 后 storage 留在代理，但 TVM 对存储槽行为需实测；上线前务必在 Nile 完整回归 upgrade + 调用，确认状态不丢。

10. 部署成本实测与 Energy 优化

部署合约本身消耗 Energy。下表是典型量级（以 Nile/主网常见参数，实际以链上为准）：

操作自有 Energy 充足无 Energy 燃烧 TRX
部署简单合约（~几 KB）近乎免费约 40~80 TRX
部署复杂合约（含库）近乎免费约 100~300 TRX
普通 TRC-20 交互免费约 3.6~3.9 TRX/笔

10.1 Energy 租赁降本

当短时高并发（如发币空投、批量转账）时，可临时租赁 Energy（第三方市场/JustLend Energy Rental），比永久燃烧便宜得多：

  • 自质押：锁 TRX 换 Energy，适合长期高频；
  • 租赁：按小时/天租 Energy，适合短时爆发，单价显著低于燃烧；
  • 燃烧：最简单但最贵，仅适合偶发。
// 成本对比思想（伪代码量级）
// 场景：1 万笔 USDT 转账，每笔约需 13800 Energy
const perTxBurn = 13800 * 0.00028;          // 燃烧：约 3.86 TRX/笔
const totalBurn = perTxBurn * 10000;        // ≈ 38600 TRX（燃烧方案）

// 租赁：约 0.0001~0.0003 TRX/Energy（市场价波动）
const perTxRent = 13800 * 0.0002;           // ≈ 2.76 TRX/笔，但可批量议价更低
const totalRent = perTxRent * 10000;        // ≈ 27600 TRX（租赁方案，通常更低）

// 自质押：10000 TRX 质押换 Energy，支撑数万笔近乎免费
console.log("燃烧:", totalBurn, "租赁:", totalRent);
结论：长期运营用质押最省；短时峰值用租赁填补；只做一两笔用燃烧图省事。商户收款系统（第 12 篇）会据此设计 Energy 策略。

12. 实战四：脚本化部署（脱离 TronBox）

生产后端常需要在 Node 服务里动态部署合约（如为用户创建子合约）。此时可以不依赖 TronBox CLI，直接用 TronWeb + 编译产物部署。流程：先用 tronbox compile 得到 build/contracts/MyToken.json，其中 bytecode 与 abi 是关键。

// deploy-script.js —— 用 TronWeb 直接部署已编译合约
const fs = require("fs");
const TronWeb = require("tronweb");
require("dotenv").config();

const tronWeb = new TronWeb({
  fullHost: "https://nile.trongrid.io",
  privateKey: process.env.NILE_PRIVATE_KEY,
});

async function deploy() {
  // 读取 tronbox 编译产物
  const artifact = JSON.parse(fs.readFileSync("./build/contracts/MyToken.json", "utf8"));
  const bytecode = artifact.bytecode;             // 含 constructor 占位
  const abi = artifact.abi;

  // 构造部署交易（构造函数参数要 ABI 编码后拼到 bytecode 后）
  const deployTx = await tronWeb.transactionBuilder.createSmartContract({
    abi: abi,
    bytecode: bytecode,
    feeLimit: tronWeb.toSun(100),
    callValue: 0,
    userFeePercentage: 30,
    originEnergyLimit: 10000000,
    parameters: [tronWeb.toSun(1000000)], // 构造函数 initialSupply 参数
    name: "MyToken",
  }, tronWeb.defaultAddress.hex);

  const signed = await tronWeb.trx.sign(deployTx);
  const ret = await tronWeb.trx.broadcast(signed);
  if (!ret.result) throw new Error("部署广播失败: " + JSON.stringify(ret));
  console.log("部署 txID:", ret.transaction ? ret.transaction.txID : ret.txid);

  // 等待合约地址（部署成功后，合约地址可从回执或按规则推导）
  await new Promise((r) => setTimeout(r, 8000));
  const txInfo = await tronWeb.trx.getTransactionInfo(
    ret.transaction ? ret.transaction.txID : ret.txid
  );
  const contractAddr = txInfo.contract_address;
  console.log("合约地址(base58):", tronWeb.address.fromHex(contractAddr));
}
deploy().catch(console.error);
构造函数参数编码：当合约构造函数有参数时，必须先把参数按 ABI 编码后拼接到 bytecode 末尾，或用 TronWeb 的 parameters 字段让 SDK 代为编码（如上例）。手拼错误会导致部署出的合约构造函数参数错乱。

13. 编写 TronBox 测试

TronBox 内置 Mocha + Chai，测试文件放在 test/ 目录，用 tronbox test 运行。与 Truffle 几乎一致：

// test/library.test.js
const Library = artifacts.require("Library");

contract("Library", (accounts) => {
  let lib;
  const [alice, bob] = accounts; // TronBox 注入的测试账户（base58）

  before(async () => {
    lib = await Library.deployed();
  });

  it("上架一本书并可查询", async () => {
    await lib.addBook("三体", web3.utils.toWei("1", "szabo")); // 仅示例单位
    const count = await lib.bookCount();
    assert(count.toNumber() >= 1, "应有至少一本书");
  });

  it("租书需附带 TRX", async () => {
    const id = (await lib.bookCount()).toNumber();
    const before = await web3.eth.getBalance(bob);
    await lib.rentBook(id, 3, { from: bob, value: web3.utils.toWei("3", "szabo") });
    const [,, owner,, avail] = await lib.getBook(id);
    assert.equal(avail, false, "书应被标记为已借出");
  });
});

// 在 tronbox-config.js 的 networks 里加测试账户
// test: {
//   privateKey: "测试私钥",
//   fullHost: "http://127.0.0.1:9090",  // 本地 private net
//   network_id: "*"
// }
// 运行：tronbox test --network test
测试要点：TronBox 注入的 accounts 是 TRON 地址；web3 同样可用（TronBox 自带）。断言逻辑与以太坊一致，只是金额单位/费用用 TRON 的 SUN 体系。CI 里建议连接本地 private net 跑测试，避免消耗测试网资源。

14. 调试与常见合约错误

为了不浪费测试网资源、又能快速迭代，强烈建议本地起一条 TRON 私链（private net）：官方提供 java-tron 的 private net 镜像，或用 docker 一键启动，fullHost 指向 http://127.0.0.1:9090。本地私链上 TRX 随意生成、零成本，适合跑 TronBox 测试与调试 revert。

# 本地私链常用命令（示例，以官方 docker 镜像为准）
# docker run -d -p 9090:9090 -p 8090:8090 tronprotocol/java-tron private
# 启动后用 tronbox 的 development 网络（fullHost: http://127.0.0.1:9090）即可

本地私链起好后，把 tronbox-config.js 的 development 网络指向它，tronbox migrate --network development 即可零成本反复部署调试。等逻辑稳定，再切到 Nile 做联调，最后才上主网。

调试心法：90% 的“部署/调用失败”都集中在三处——feeLimit 不够、构造函数参数编码错、地址格式/网络不匹配。遇到问题时按这张表与第 14 节错误码逐项排除，比盲目改代码高效得多。

// 解码合约事件日志（用 tronweb 的 abi 解码）
async function decodeLogs(txID, abi) {
  const info = await tronWeb.trx.getTransactionInfo(txID);
  const logs = info.log || [];
  for (const lg of logs) {
    // lg.topics / lg.data 可配合 ethers/utils 的默认 abiCoder 解码
    console.log("raw log:", lg);
  }
}
