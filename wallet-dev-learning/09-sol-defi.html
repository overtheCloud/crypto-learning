SOL 篇 III：DeFi 与生态实战

站在 Jupiter、Orca、Kamino、Jito、Metaplex、Pyth、Helius 等协议肩膀上，用现成 SDK 把"聚合交易 / 借贷 / 流动性质押 / NFT / 预言机 / 数据增强"全部跑通。主要参考：Jupiter 文档 dev.jup.ag、各协议官方文档。

本章目标：
  1. 建立 Solana DeFi 生态地图，并对照以太坊 DeFi 找到对应物；
  2. 用 Jupiter Quote/Swap API 完成一次完整聚合兑换（含优先费与滑点）；
  3. 读取 Orca Whirlpool 池数据，了解 Kamino/Marginfi 借贷交互思路；
  4. 理解 Jito 流动性质押与 MEV 小费机制；
  5. 用 Metaplex 创建 NFT、用 DAS API 读压缩 NFT；
  6. 用 Helius webhook 监听活动，并掌握交易落地可靠性策略与 Pyth 喂价读取。

1. 生态地图与 ETH DeFi 对照

Solana DeFi 的"可组合性"建立在统一的 SPL Token 标准与高吞吐之上。下面这张地图帮你在脑子里建立坐标：

Jupiter

聚合器入口。把全网 AMM/路由的最优路径聚合，是大多数钱包/前端做"兑换"的默认后端。

Raydium / Orca / Meteora

AMM 三强：Raydium 经典 AMM+订单簿混合；Orca 主推 Whirlpool（CLMM 集中流动性）；Meteora 主推 DLMM 动态流动性。

Kamino / Marginfi

借贷协议。Kamino 还做流动性 vault 与 LST；Marginfi 是多抵押借贷，生态老牌。

Jito / Marinade

流动性质押（LST）。Jito 额外把 MEV 收益分配给质押者，并主导 MEV 小费市场。

Metaplex

NFT 标准与工具链（Token Metadata、Candy Machine、Bubblegum 压缩 NFT）。

Pyth

预言机。Solana 生态主流喂价来源，采用"按需 pull"上链的轻量模型。

2. Jupiter 实战：聚合兑换（核心）

Jupiter 提供两套 API：Quote API（计算最优路径与报价）和 Swap API（据此生成可直接签名的交易）。前端/后端拿到交易后反序列化、签名、广播即可。

2.1 完整兑换代码（Node.js）

import { Connection, Keypair, VersionedTransaction, PublicKey } from "@solana/web3.js";

const RPC = "https://api.mainnet-beta.solana.com"; // 生产请换 Helius/QuickNode
const connection = new Connection(RPC);

// 实际项目里钱包应由用户持有；这里仅演示流程
const wallet = Keypair.generate();

const inputMint = "So11111111111111111111111111111111111111112";  // SOL
const outputMint = "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v"; // USDC
const amount = 1_000_000_000; // 1 SOL = 1e9 lamports

// 1) 请求报价（注意 URL 中的 & 是查询参数分隔符）
const quoteUrl =
  "https://quote-api.jup.ag/v6/quote?inputMint=" + inputMint +
  "&outputMint=" + outputMint +
  "&amount=" + amount +
  "&slippageBps=50"; // 50 = 0.5% 滑点容忍
const quote = await (await fetch(quoteUrl)).json();
console.log("预计得到 USDC 最小量:", quote.outAmount, "路由步数:", quote.routePlan.length);

// 2) 用报价请求 swap 交易（返回 base64 序列化的 VersionedTransaction）
const swapUrl = "https://quote-api.jup.ag/v6/swap";
const swapBody = {
  quoteResponse: quote,            // 直接塞入上一步的报价
  userPublicKey: wallet.publicKey.toBase58(),
  wrapAndUnwrapSol: true,          // 自动处理 SOL<->wSOL 包装
  dynamicComputeUnitLimit: true,   // 让 Jupiter 估算计算单元
  prioritizationFeeLamports: "auto", // 优先费自动估算（拥堵时很有用）
};
const swapRes = await (await fetch(swapUrl, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(swapBody),
})).json();

// 3) 反序列化并签名
const swapTx = VersionedTransaction.deserialize(
  Buffer.from(swapRes.swapTransaction, "base64")
);
swapTx.sign([wallet]); // 前端用 adapter.signTransaction(swapTx)

// 4) 发送并确认
const sig = await connection.sendRawTransaction(swapTx.serialize());
const result = await connection.confirmTransaction(sig, "confirmed");
console.log("成交签名:", sig, "错误:", result.value.err);
滑点与优先费：slippageBps 设置过低在波动行情会频繁失败；过高则可能被套利。优先费用 prioritizationFeeLamports 在网络拥堵时建议设 "auto" 或显式给值（如 100000），否则交易可能长时间不被打包。

2.2 前端钱包适配器版本

在 React 里，私钥由用户钱包持有，你只需拿到 VersionedTransaction 让用户签名：

import { useWallet, useConnection } from "@solana/wallet-adapter-react";

function SwapButton({ quote }) {
  const { connection } = useConnection();
  const { publicKey, signTransaction, sendTransaction } = useWallet();

  async function doSwap() {
    const res = await fetch("https://quote-api.jup.ag/v6/swap", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        quoteResponse: quote,
        userPublicKey: publicKey.toBase58(),
        wrapAndUnwrapSol: true,
      }),
    }).then((r) => r.json());

    const tx = VersionedTransaction.deserialize(Buffer.from(res.swapTransaction, "base64"));
    // 用户钱包弹窗签名（私钥不出设备）
    const signed = await signTransaction(tx);
    const sig = await connection.sendRawTransaction(signed.serialize());
    await connection.confirmTransaction(sig, "confirmed");
    alert("兑换成功: " + sig);
  }
  return <button onClick={doSwap}>用 Jupiter 兑换</button>;
}

2.3 Limit Order 与 DCA 简介

Jupiter 还提供两类进阶产品（均通过专属 API/程序）：

  • Limit Order（限价单）：设定"到达某价格才成交"的挂单，由 Jupiter 的限价程序托管，撮合后自动执行。适合不想盯盘的用户。
  • DCA（定投）：把"每 N 分钟买 X 数量"拆成多笔，程序按计划自动执行，平摊成本。通过 https://api.jup.ag/swap/v1/.../dca 系列接口或 SDK 创建。
// 创建 DCA 订单（示意请求体）
const dcaBody = {
  user: wallet.publicKey.toBase58(),
  inputMint, outputMint,
  inAmountPerCycle: 1_000_000,   // 每周期投入（lamports/SOL）
  numberOfCycles: 10,            // 共 10 次
  cycleSecondsApart: 3600,       // 每小时一次
};
// POST https://api.jup.ag/swap/v1/dca/createOrder 并签名返回的 tx

3. Orca Whirlpool 数据读取

Orca 的 Whirlpool 是集中流动性 AMM（类似 Uniswap V3）。用 @orca-so/whirlpools-sdk 可只读地读取池子状态。

import { Connection, PublicKey } from "@solana/web3.js";
import { AnchorProvider } from "@coral-xyz/anchor";
import {
  WhirlpoolContext, buildWhirlpoolClient,
  ORCA_WHIRLPOOLS_CONFIG,
} from "@orca-so/whirlpools-sdk";

const connection = new Connection("https://api.mainnet-beta.solana.com");
// 读取场景不需要真实签名者，用只读 provider 占位
const dummyWallet = { publicKey: PublicKey.default, signTransaction: async (t) => t, signAllTransactions: async (t) => t };
const ctx = WhirlpoolContext.from(connection, new AnchorProvider(connection, dummyWallet, {}), ORCA_WHIRLPOOLS_CONFIG);
const client = buildWhirlpoolClient(ctx);

// 已知某 Whirlpool 地址（如 SOL/USDC），读取实时数据
const whirlpoolAddr = new PublicKey("<WHIRLPOOL_ADDRESS>");
const whirlpool = await client.getPool(whirlpoolAddr);
const data = whirlpool.getData();
console.log({
  tokenA: data.tokenMintA.toBase58(),
  tokenB: data.tokenMintB.toBase58(),
  price: data.price,              // 当前价格（Decimal）
  tickSpacing: data.tickSpacing,  // 价格刻度间隔
  liquidity: data.liquidity.toString(),
  feeRate: data.feeRate,          // 手续费率（百万分比）
});

// 还可以列出某代币相关的所有池子
const candidates = await client.getPoolsByTokenPair(
  new PublicKey(inputMint), new PublicKey(outputMint)
);
console.log("候选池数量:", candidates.length);
CLMM 要点：集中流动性让 LP 在指定价格区间提供流动性，资本效率更高但面临"区间外无收益/需再平衡"。读取 price / tickSpacing / liquidity 是做行情面板与套利分析的基础。

4. Kamino / Marginfi 借贷

借贷协议的交互范式类似：存入抵押品 → 借出资产 → 监控健康因子 → 还款取回。两大协议都提供 TS SDK（@kamino-finance/kamino-lending、@marginfi/mrgn-client-v2）。

import { MarginfiClient, getConfig } from "@marginfi/mrgn-client-v2";

const config = getConfig("production");

5. Jito 质押与 MEV 小费

JitoSOL 是流动性质押代币：你把 SOL 质押进 Jito 的 stake pool，获得 JitoSOL，它随质押奖励（含 MEV 收益）持续增值，同时可自由转移、提供流动性。

// 简化示意：真实质押请用 @jito-labs/jitosol SDK 或 stake pool 程序
// 质押后你会收到与存入量 1:1（随奖励增长）的 JitoSOL 代币
async function stakeToJito(connection, wallet, solAmount) {
  // 实际流程：向 Jito stake pool 程序转账 SOL，程序 mint JitoSOL 到你的 ATA
  console.log("质押", solAmount, "SOL 换 JitoSOL");
}

// Jito 的 MEV 小费（tip）：把少量 SOL 转给 Jito tip 账户，提升被 leader 优先打包概率
const JITO_TIP_ACCOUNTS = [
  "96gYZGLnJYVFmbjzopPSU6QiEV5fGqZNyN9nmNhvrZU",
  "HFqU969nJ8i9CJWgPNfCse5PqaD1w8dQngzd6rmeuaga",
  "Cw8CFyM9FkoBi8NL9wiRAwzskCA8XBiDqYJioGAg3TmF",
];

function buildTipTx(wallet, tipLamports) {
  return new Transaction().add(
    SystemProgram.transfer({
      fromPubkey: wallet.publicKey,
      toPubkey: new PublicKey(JITO_TIP_ACCOUNTS[0]),
      lamports: tipLamports,
    })
  );
}

// 用法：把 tip 交易与你的主交易合并（或作为独立优先级提示），一起签名发送
const tipTx = buildTipTx(wallet, 10_000); // 0.00001 SOL 小费
console.log("已构建 Jito 小费交易");
优先费 vs MEV 小费：ComputeBudgetProgram.setComputeUnitPrice 是"协议内优先费"，给验证者；Jito tip 是"给 Jito 的 MEV 小费"，由 Jito 的 leader 优先打包。高价值/抢跑敏感交易（如套利、清算）常两者叠加。

6. Metaplex：创建 NFT

Metaplex 的 Token Metadata 标准是 Solana NFT 的事实标准。下面用 Umi（Metaplex 新一代工具链）创建一个 NFT：

import { createUmi } from "@metaplex-foundation/umi-bundle-defaults";
import {
  generateSigner, keypairIdentity, percentAmount,
} from "@metaplex-foundation/umi";
import { createNft } from "@metaplex-foundation/mpl-token-metadata";

// 1) 初始化 Umi（连 devnet）+ 设置身份（creator 钱包）
const umi = createUmi("https://api.devnet.solana.com");
const creator = generateSigner(umi);
umi.use(keypairIdentity(creator));

// 2) 创建 NFT（1 个，不可拆分；若要 SFT 用 createFungible）
const mint = generateSigner(umi);
await createNft(umi, {
  mint,
  name: "我的第一个 NFT",
  symbol: "DEMO",
  uri: "https://example.com/metadata.json", // 指向 JSON 元数据（图片/IPFS 等）
  sellerFeeBasisPoints: percentAmount(5),     // 二级市场交易 5% 版税
  creators: [{ address: creator.publicKey, verified: true, share: 100 }],
}).sendAndConfirm(umi);

console.log("NFT mint 地址:", mint.publicKey);
元数据 JSON：uri 指向的 JSON 至少含 name、description、image（图片链接）、attributes 等字段。生产通常存到 Arweave / IPFS，并用去中心化链接（如 ar://... 或 ipfs://...）。

7. 压缩 NFT 与 DAS API

普通 NFT 每个都占一个链上 ATA，铸造量大时成本极高。压缩 NFT（cNFT，基于 Bubblegum + State Tree）把数据存进 Merkle 树，单次铸造成本极低，适合的大规模铸造（门票、游戏物品）。

import { createUmi } from "@metaplex-foundation/umi-bundle-defaults";
import { generateSigner, keypairIdentity } from "@metaplex-foundation/umi";
import {
  createTree, mintToCollectionV1,
} from "@metaplex-foundation/mpl-bubblegum";

const umi = createUmi("https://api.devnet.solana.com").use(keypairIdentity(generateSigner(umi)));

// 1) 先创建一棵状态树（Merkle tree），容量与深度决定可铸数量
const tree = generateSigner(umi);
await createTree(umi, {
  merkleTree: tree,
  maxDepth: 14,   // 深度
  maxBufferSize: 64,
}).sendAndConfirm(umi);

// 2) 在树上铸造压缩 NFT（成本极低）
await mintToCollectionV1(umi, {
  merkleTree: tree.publicKey,
  metadata: {
    name: "压缩 NFT #1",
    uri: "https://example.com/cnft.json",
    sellerFeeBasisPoints: 0,
  },
}).sendAndConfirm(umi);
console.log("已在状态树上铸造压缩 NFT");

7.1 用 DAS API 读取压缩 NFT

读取压缩 NFT 不能像普通 NFT 那样直接读 ATA，要走 DAS（Digital Asset Standard）API。Helius / Metaplex DAS 都提供。

// 通过 Helius 的 DAS 端点查询某地址拥有的全部资产（含压缩 NFT）
const dasUrl = "https://mainnet.helius-rpc.com/?api-key=YOUR_API_KEY";
const res = await fetch(dasUrl, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    jsonrpc: "2.0", id: "1", method: "getAssetsByOwner",
    params: { ownerAddress: "<WALLET_BASE58>", page: 1, limit: 100 },
  }),
});
const data = await res.json();
for (const item of data.result.items) {
  console.log(item.id, item.content.metadata.name, "是否压缩:", item.compression.compressed);
}
DAS 关键字段：返回项含 compression.compressed（是否压缩）、content.metadata（名称/属性）、ownership（拥有者）。做 NFT 市场的"我的资产"页，DAS API 是唯一高效路径。

8. 基础设施：Helius / 可靠性 / Pyth

8.1 Helius 增强 API 与 webhook 监听

Helius 的增强 API把原始交易解析成易读的"账户变动、代币转移、NFT 转移"等结构化字段；webhook 可在地址发生活动时主动推送给你。

// 1) 创建 webhook（需服务端调用 Helius 接口，下面仅示例请求体）
const webhookBody = {
  webhookURL: "https://your-server.com/notify",
  transactionTypes: ["SWAP", "TRANSFER", "NFT_SALE"],
  accountAddresses: ["<WALLET_A>", "<WALLET_B>"],
  webhookType: "enhanced",
};
// POST https://api.helius.xyz/v0/webhooks?api-key=YOUR_KEY

// 2) 服务端接收回调（Node/Express 示例）
import express from "express";
const app = express();
app.use(express.json());
app.post("/notify", (req, res) => {
  const events = req.body;
  for (const ev of events) {
    console.log("类型:", ev.type, "签名:", ev.signature);
    // ev 里含增强字段：账户余额变动、转移的代币、涉及地址等
    // 据此触发通知 / 更新数据库 / 执行策略
  }
  res.sendStatus(200); // 必须尽快返回 200，否则 Helius 会重试
});
app.listen(3000);
webhook 可靠性：收到后应尽快 ack（返回 200），把重活（写库、复杂计算）放进队列异步处理，避免超时导致 Helius 重复推送。

8.2 交易落地可靠性策略

Solana 高吞吐下，交易失败的常见原因：blockhash 过期、算力超限、被抢跑、优先费不足。稳健发送策略如下：

import { Connection, TransactionExpiredBlockhashError, VersionedTransaction } from "@solana/web3.js";

async function sendReliably(connection, tx: VersionedTransaction, maxRetry = 3) {
  for (let i = 0; i < maxRetry; i++) {
    try {
      const sig = await connection.sendRawTransaction(tx.serialize(), {
        skipPreflight: false,
        maxRetries: 2,
      });
      const result = await connection.confirmTransaction(
        { signature: sig, ...(await connection.getLatestBlockhash()) },
        "confirmed"
      );
      if (result.value.err) throw new Error(JSON.stringify(result.value.err));
      return sig;
    } catch (e) {
      // blockhash 过期：刷新并重签后再试
      if (e instanceof TransactionExpiredBlockhashError) {
        console.warn("blockhash 过期，重签重试", i + 1);
        // 真实场景需重新构造交易并签名
        continue;
      }
      // 优先费不足：阶梯式提高 microLamports 再试（略）
      console.error("发送失败:", e);
      if (i === maxRetry - 1) throw e;
    }
  }
}
  • 优先费阶梯：首次用 "auto"，失败则按 1x→2x→5x 递增 setComputeUnitPrice；
  • blockhash 管理：长流程定期 getLatestBlockhash()，过期则重签；
  • 幂等：对"已发送未确认"的交易用 getSignatureStatus 查状态，避免重复提交造成双倍操作。

8.3 Pyth 喂价读取

Pyth 在 Solana 上采用按需 pull 预言机：价格更新数据先由 Hermes 网关分发，调用方付费把更新"拉"到链上，合约再读取。两种方式：

// 方式 A：链下直接拉取最新价格（做展示/策略计算）
import { HermesClient } from "@pythnetwork/hermes-client";
const hermes = new HermesClient("https://hermes.pyth.network");

// priceId 是 Pyth 为每个交易对分配的固定 ID（如 SOL/USD）
const SOL_USD_ID = "0xef0d8b6fda2ceba41da15d4095d1da392a0d2f8ed0c6c7bc0f4cfac8c280b56d";
const feeds = await hermes.getLatestPriceFeeds([SOL_USD_ID]);
const price = feeds[0].price;
console.log("SOL 价格:", price.price * Math.pow(10, price.expo), "置信区间:", price.conf);

// 方式 B：链上 pull —— 先把更新数据上链，再在合约里用 pyth-sdk 读取
const updateData = await hermes.getLatestUpdateData([SOL_USD_ID]);
// 调用 Pyth 的 pull oracle 程序写入 updateData，得到链上 PriceAccount
// 你的 Anchor 合约通过 pyth_sdk_solana 的 load_price_feed_from_account_info 读取
// 关键点：Solana 上 Pyth 不是"常驻链上喂价"，而是"谁用谁付费上链"，所以调用前要确保价格已更新
价格新鲜度：链上读到的 Pyth 价格可能"陈旧"。合约里应检查 publish_time / 最大延迟，价格过旧直接 revert，防止用过期价格结算造成损失。

9. 端到端实战：监控 → 报价 → 执行的迷你机器人

把前面能力串起来：用 Helius 监听某钱包的买入行为，当监听到"大额买入某代币"时，自动用 Jupiter 查报价、构造并发送跟单交易。这是 DeFi 策略/套利机器人的基本骨架。

import { Connection, Keypair, VersionedTransaction, PublicKey } from "@solana/web3.js";

const connection = new Connection("https://mainnet.helius-rpc.com/?api-key=YOUR_KEY");
const wallet = Keypair.generate(); // 实际由用户/策略钱包持有

// 步骤1：从 Helius webhook / 或直接轮询某地址最近交易，拿到"目标代币 mint"
async function watchAndFollow(targetWallet: string) {
  // 真实环境用 webhook 推送；这里用轮询最近签名示意
  const sigs = await connection.getSignaturesForAddress(new PublicKey(targetWallet), { limit: 5 });
  for (const { signature } of sigs) {
    const tx = await connection.getParsedTransaction(signature, { maxSupportedTransactionVersion: 0 });
    if (!tx || tx.meta.err) continue;
    const boughtMint = extractBoughtMint(tx); // 解析出买入的代币 mint
    if (boughtMint) await followBuy(boughtMint, 0.1 /* 用 0.1 SOL 跟单 */);
  }
}

function extractBoughtMint(tx: any): string | null {
  // 简化：从 postTokenBalances 中找到余额增加且非已知稳定币的 mint
  const balances = tx.meta.postTokenBalances ?? [];
  for (const b of balances) {
    if ((b.uiTokenAmount.uiAmount ?? 0) > 0) return b.mint;
  }
  return null;
}

// 步骤2：用 Jupiter 跟单买入
async function followBuy(outputMint: string, solAmount: number) {
  const inputMint = "So11111111111111111111111111111111111111112"; // SOL
  const quoteUrl =
    "https://quote-api.jup.ag/v6/quote?inputMint=" + inputMint +
    "&outputMint=" + outputMint +
    "&amount=" + Math.floor(solAmount * 1e9) +
    "&slippageBps=100";
  const quote = await (await fetch(quoteUrl)).json();

  const swapRes = await (await fetch("https://quote-api.jup.ag/v6/swap", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ quoteResponse: quote, userPublicKey: wallet.publicKey.toBase58(), wrapAndUnwrapSol: true, prioritizationFeeLamports: "auto" }),
  })).json();

  const tx = VersionedTransaction.deserialize(Buffer.from(swapRes.swapTransaction, "base64"));
  tx.sign([wallet]);
  const sig = await connection.sendRawTransaction(tx.serialize());
  await connection.confirmTransaction(sig, "confirmed");
  console.log("跟单买入成交:", sig, "代币:", outputMint);
}

// watchAndFollow("<被跟单的大户地址>");
合规与风险：跟单/抢跑类策略可能触碰"三明治攻击"与合规红线。本例仅作技术演示，请遵守所在司法辖区法规，且仅用自己授权的资金在小范围内测试。

10. 读懂一笔交易：getParsedTransaction

调试与对账时，getParsedTransaction 是最常用接口。它返回已解析的指令、账户、SOL 余额变动与代币余额变动。

import { Connection, PublicKey } from "@solana/web3.js";

const connection = new Connection("https://api.mainnet-beta.solana.com");
const sig = "<交易签名>";

const tx = await connection.getParsedTransaction(sig, { maxSupportedTransactionVersion: 0 });
if (!tx) throw new Error("交易不存在或未被确认");

console.log("是否成功:", !tx.meta.err);
console.log("手续费( SOL ):", (tx.meta.fee ?? 0) / 1e9);

// 1) SOL 余额变动（pre/post 数组按 accountKeys 顺序对应）
const keys = tx.transaction.message.accountKeys;
for (let i = 0; i < keys.length; i++) {
  const pre = (tx.meta.preBalances[i] ?? 0) / 1e9;
  const post = (tx.meta.postBalances[i] ?? 0) / 1e9;
  if (pre !== post) {
    console.log("SOL 变动:", keys[i].pubkey.toBase58(), pre, "->", post);
  }
}

// 2) 代币余额变动
const preMap = new Map((tx.meta.preTokenBalances ?? []).map((b) => [b.accountIndex, b]));
for (const post of (tx.meta.postTokenBalances ?? [])) {
  const pre = preMap.get(post.accountIndex);
  const preAmt = pre?.uiTokenAmount.uiAmount ?? 0;
  const postAmt = post.uiTokenAmount.uiAmount ?? 0;
  if (preAmt !== postAmt) {
    console.log("代币变动:", post.mint, "账户#" + post.accountIndex, preAmt, "->", postAmt);
  }
}
对账技巧：把 preTokenBalances 与 postTokenBalances 按 accountIndex 配对，就能精确算出"谁向谁转移了多少代币"，是做税务/流水导出的基础。

11. 钱包 UX 最佳实践

好的 Solana 钱包前端应把"余额、代币、价格、滑点"整合。下面是组合多个 API 的最小面板逻辑。

import { Connection, PublicKey, LAMPORTS_PER_SOL } from "@solana/web3.js";

const connection = new Connection("https://mainnet.helius-rpc.com/?api-key=YOUR_KEY");

// 拉取某代币美元价（Jupiter Price API）
async function getUsdPrice(mint: string): Promise<number> {
  const url = "https://price.jup.ag/v6/price?ids=" + mint;
  const r = await (await fetch(url)).json();
  return r.data[mint]?.price ?? 0;
}

// 组合：SOL 余额 + SPL 列表 + 各自美元估值
async function buildPortfolio(owner: PublicKey) {
  const sol = (await connection.getBalance(owner)) / LAMPORTS_PER_SOL;
  const solPrice = await getUsdPrice("So11111111111111111111111111111111111111112");

  const tokens = await connection.getParsedTokenAccountsByOwner(owner, {
    programId: new PublicKey("TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA"),
  });

  const rows = [];
  for (const { account } of tokens.value) {
    const info = account.data.parsed.info;
    const amount = info.tokenAmount.uiAmount;
    if (!amount) continue;
    const price = await getUsdPrice(info.mint);
    rows.push({ mint: info.mint, amount, usd: amount * price });
  }
  return {
    sol, solUsd: sol * solPrice,
    tokens: rows,
    totalUsd: sol * solPrice + rows.reduce((s, r) => s + r.usd, 0),
  };
}
  • 滑点设置：给用户可选的 0.1% / 0.5% / 1% 滑点档位，默认 0.5%，并提示"高波动代币建议提高"；
  • 交易预览：发送前显示"预计得到 X、价格影响 Y%、最少收到 Z（含滑点）"；
  • 状态反馈：用 confirmed / finalized 两阶段提示"处理中 / 已确认"。

import { getMint } from "@solana/spl-token";

13. 性能与成本优化

当交易涉及的账户很多（聚合器常达 20+ 账户），体积与算力都会吃紧。两个关键优化：

13.1 Address Lookup Table（ALT）

import {
  AddressLookupTableProgram, Connection, Keypair, PublicKey, TransactionMessage,
  VersionedTransaction,
} from "@solana/web3.js";

async function buildLookupTable(connection: Connection, payer: Keypair, addresses: PublicKey[]) {
  // 1) 创建表（需付费，且要等约一个 epoch 才能写入地址）
  const [createIx, lookupTableAddress] = AddressLookupTableProgram.createLookupTable({
    authority: payer.publicKey,
    payer: payer.publicKey,
    recentSlot: await connection.getSlot(),
  });
  let tx = new VersionedTransaction(
    new TransactionMessage({ payerKey: payer.publicKey, recentBlockhash: (await connection.getLatestBlockhash()).blockhash, instructions: [createIx] }).compileToV0Message()
  );
  tx.sign([payer]);
  await connection.sendRawTransaction(tx.serialize());

  // 2) 扩展表，把常用地址登记进去
  const extendIx = AddressLookupTableProgram.extendLookupTable({
    authority: payer.publicKey,
    lookupTable: lookupTableAddress,
    payer: payer.publicKey,
    addresses,
  });
  tx = new VersionedTransaction(
    new TransactionMessage({ payerKey: payer.publicKey, recentBlockhash: (await connection.getLatestBlockhash()).blockhash, instructions: [extendIx] }).compileToV0Message()
  );
  tx.sign([payer]);
  console.log("查找表地址:", lookupTableAddress.toBase58());
}

13.2 计算单元与批量

  • 精确设置 CU：先用 simulateTransaction 看实际消耗，再 setComputeUnitLimit 给略高的余量，避免浪费或被拒；
  • 优先费阶梯：拥堵时按 1x→2x→5x 提升 setComputeUnitPrice；
  • 合并交易：把多步操作（approve + swap）放进同一笔 VersionedTransaction，减少往返与失败点。
经验值：普通转账约 5000 CU，Jupiter 兑换常需 20万~100万+ CU；主网单笔上限约 140万 CU/区块可调。设置 setComputeUnitLimit 时宁可多给 20% 余量，避免"算力不足"失败。
